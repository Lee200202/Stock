    維護工具
    
        
    平常不需要碰。三個工具差在動不動資料：「只刷新畫面」只重算網站上看到的東西；
          「全面重整」會讓過去的資料套用新規則；「指定日期」只改一天的郵件或分類。
    

        
    
          
    只刷新畫面不動資料GitHub Actions
    
          
    用試算表現有的正式操作內容，依序重算九步：清除產業列、三段品質關卡、
             代號、基本面、日K、持股追蹤與績效。操作紀錄與會員持股不會因刷新被重建；
             快取與衍生結果會更新。日K檔數多時可能需要十幾分鐘。
    
          
    某一步失敗時不必整條鏈重來，選擇該步驟接續即可。後面的相依步驟會依序完成；
             例如補齊日K失敗時，系統會保留日K游標，並暫停持股追蹤與績效，避免用不完整行情計算。

    會員簡訊
    
        
    會員簡訊平常每 5–10 分鐘自動抓取與解析，不用按。這裡處理例外：漏抓的補抓、提示詞改過要重新解析、把簡訊併進過去的紀錄。
          依操作順序由上往下排；重的工作在 GitHub Actions 執行，關掉頁面也會繼續。
    
        
    
          
    抓取與解析工作流自動補抓與稽核GitHub Actions
    
          
    系統會先探索來源帳號全部文章、辨識張震，再還原發文時間與套用範圍。無法驗證日期的文章保留重試資格並單獨列入稽核，不會歸到今天。
    
          
    
            探索文章→辨識張震→日期篩選→逐日稽核→收錄個股（13 格）
          
    
          
    收錄個股整段排在逐日稽核之後，共十三格：
            分類已解析與空白、建立收錄佇列、載入代號對照表、讀取歷史買價、AI 收錄個股、
            規則稽核與代號比對、條件式買賣去重、寫入操作紀錄、寫入會員持股、原子取代舊列、
            回寫解析狀態。每一格都會在進度條上單獨亮起，卡住時看得出卡在哪一段。
    

          
    
            一、補抓最近
            
    「最近七天」會自動算今天起往前六天；「全部文章」會沿來源網站游標逐頁找到底。
               兩者都不需要輸入日期或文章編號，且先掃過來源帳號文章、判斷是否為張震，再套日期範圍。
    
            
    
              
              
            
    
          
    

          
    
            二、依編號補抓
            
    任意久以前的都補得到，前提是手上有那份清單。一行一個，
               貼文章網址或純數字都可以，一次最多 100 篇；同樣會先驗證張震與真實日期。
    
            
            
    
              
            
    
          
    

          
    
            三、重新解析
            
    提示詞改過或有新簡訊未解析時使用。GitHub 逐則呼叫模型、查證並寫回；
               重跑會以文章 ID 取代該篇舊衍生紀錄，不會累積重複列。
    
            
    
              
              
            
    
            
    
              
    使用與前台相同的日曆選取起始日；從該日起到今天都會重跑。
