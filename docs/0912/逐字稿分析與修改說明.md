## 三、Prompt 與文章品質

完整執行用 Prompt 見同目錄 `PROMPT_CONTEXT_JSON.md`。`pipeline/pipeline.py` 是唯一 Python 執行來源；`scripts/sync_quality.py` 同步根目錄副本及 GAS 擷取／稽核／複審／撰稿規則。GAS 使用逐字引句、Python 使用 S 段落編號，兩者僅證據傳輸格式不同。

每筆摘要在原文足夠時寫 70～160 字、2～4 句，交代狀態、條件、講者的理由與後續觀察。盤勢目標 6～10 點、每點 70～140 字；教學目標 5～8 點、每點 70～140 字。原文少就少寫，不能替只有名單的牧德補出長篇基本面。舊的 650 字硬上限已擴大至 2400 字的防護上限，保留完整列點而不切半句。

「洞見」表達採：**觀察到的現象 → 講者的解讀／落差 → 適用對象與行動条件 → 後續確認事項**。原文沒有的環節就省略。例：宜鼎營收好但價格下跌，可以寫出基本面与技術條件不同步，以及先等技術確認的做法；不能自行加上未定價利多、內幕、停損價或保證反彈。

同一天重跑，第三、第五章都由本輪有效摘要重建；不再讓舊第五章蓋掉新教學。會員持股表持續保留。原文與判斷紀錄留在稽核資料，公開文章不解釋 Prompt、引用格式或內部改列流程。

## 四、流程安排與呼叫用量

1. 讀取原文與雜湊，潤飾稿僅供閱讀。
2. 保留已有潤飾稿；未有者沿用目前分段潤飾。
3. 按整個請求的輸入預算分批，以 JSON 一次完成擷取、分類、日期、候選盤點、盤勢與教學。
4. **增加一次語意覆核**：即使本機引句校驗零問題，也重讀來源檢查漏股、持股與觀望對象。原本的證據修復併入這輪，每批最多一次，不再另加第三輪修復。
5. 查官方代號、套用確認過的語音名稱，再進逐筆品質關卡；真正無法識別才隔離，引用定位缺漏可修復後收錄。
6. 未解名稱視需要一次批次釐清；合併時保留不同對象／日期／事件。
7. 校對價格用途與日期，保存稽核及最終結構化資料。
8. 直接以最終資料建立文章，不再另叫模型撰稿。
9. 寫表後按檢查點同步郵件內容、代號、追蹤、績效歷史及快照。缺日K先停在相依步驟。

以你提供的兩天為例，原稿各可容納在一批。已有修飾稿且名稱已確認時，核心判讀預期 **2 次**；需要名稱釐清再加 1 次。沒有修飾稿時，9/10 另有 4 次、9/11 另有 3 次潤飾。另計開頭三把金鑰的健檢，以及重試／備援模型請求；日誌的「本輪 6 次」並不是整個 Actions 的所有生成請求總數。

`GEMINI_SEMANTIC_AUDIT=true` 是新預設；設 `false` 可比較單輪模式，此時只有本機发现問題才呼叫修復。不建議只以呼叫少做為品質指標。

JSON 本身不會增加模型記憶，也不保證省 token。這版省下的是反覆抄引句與獨立撰稿；跨請求不假設模型記得之前內容。現有預算採 UTF-8 位元組長度的保守代理，不是實測 token 數；模型上限雖為 1,048,576 輸入／65,536 輸出，仍保留较低的任務預算與輸出空間。長稿不硬塞、不無聲截掉中間內容。[模型規格](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)

## 五、thinkingLevel 與免費方案

Python、GAS 維持 `gemini-3.5-flash-lite`，本專案目前預設 `medium`（模型官方預設為 minimal，兩者不同）。兩端均以 `GEMINI_THINKING_LEVEL` 調整 `low`／`medium`／`high`。Google 官方文件列有這個模型及其思考能力；提高層級不需要在程式切換付費模型，但可能增加生成時間及思考 token，不代表自動更正所有分類。[思考設定](https://ai.google.dev/gemini-api/docs/thinking)

免費層的可用額度仍以該專案 AI Studio 顯示為準，不承諾固定每日次數。輸出計量包含 thinking token；同專案多把金鑰不等於各自獨立額度。建議以 `medium + 語意覆核` 作為比較基準，另跑 `high` 評估漏列、錯分類與耗時，而不是直接把全站改 high。[價格與免費層](https://ai.google.dev/gemini-api/docs/pricing)、[速率限制](https://ai.google.dev/gemini-api/docs/rate-limits)

健檢真的呼叫 generateContent，會用生成配額。ReadTimeout／暫時網路錯誤改為「尚未驗證，保留正式重試」；401／403 等確定授權失敗仍不可用。`思考=0` 是 API 回報的實際 usage 值，不能單憑這個數字推定 thinkingLevel 沒送出。

| Aiservice.gs | 既有 Gemini 外部 API／金鑰／重試服務 |

GAS 全部檔案共用全域命名空間，不新增 ES module imports。原有公開函式名稱保留，拆檔不是把服務複製一份。部署時必須同時新增拆出的檔案；只貼新的 Code.gs 會缺函式。

**修改前**，更新訂閱逐格寫，查列與寫入不在同一個鎖範圍：

```javascript
var hit = findSubscription_(email);
hit.sheet.getRange(hit.rowNum, iItems + 1).setValue(items.join('、'));
hit.sheet.getRange(hit.rowNum, iCodes + 1).setValue(codes.join(','));
hit.sheet.getRange(hit.rowNum, iState + 1).setValue('生效中');
```

**修改後**，在鎖內重新查到當下列，再依相鄰欄位一次 `setValues`：

```javascript
return withLock_(function () {
  var hit = findSubscription_(email);
  writeSubscriptionFields_(hit, {
    '訂閱項目': items.join('、'),
    '關注股票代號': codes.join(','),
    '狀態': '生效中'
  });
});
```

三欄相鄰時只寫一次；中間隔著其他欄位時分組寫，不用整列覆蓋公式。查詢原本已是一次 `getValues`，維持 O(n) 掃描；優化的是 RPC 次數與讀改寫的一致性，不宣稱把線性查詢變成常數時間。GAS ScriptLock **無法鎖住外部 Python 的 Sheets API**，外部寫入仍需現有來源識別、檢查點與工作排隊配合。[GAS 批次操作建議](https://developers.google.com/apps-script/guides/support/best-practices)

## 七、流程審查與界線

| 項目 | 已調整／既有防護 | 仍需線上確認 |
| --- | --- | --- |
| 名稱與代號 | Python/GAS 同步確認別名，貨幣與產業優先排除；同音多候選交上下文 | 官方清單當日來源、人工名稱快取是否另有覆寫 |
| 稽核漏股 | 引句校驗加語意覆核，覆核消失的候選留稽核；異常不靜默換空資料 | 真實模型的逐檔 precision／recall 與分類差異 |
| GAS 6 分鐘限制 | `all` 每請求只做一批／一步，既有日K游標与日編輯分步保留 | 單一步內部大資料重算仍須量測，拆入口不能保證任意資料量永不逾時 |
| 缺日K | 績效歷史回待補資料；不標記完成、不接著公布成功快照 | 先補日K後從檢查點接續；不因重跑重新生成文章 |
| API 逾時 | 金鑰健檢暫時錯誤保留；正式請求既有節流／重試／配額判別 | 多把金鑰所屬專案及當下配額 |
| 同時更新 | 訂閱讀改寫上鎖；相鄰欄位批寫不碰其他公式；同日期 all 入口有短鎖＋到期租約防重入 | 不同外部流程仍非跨服務交易；避免同日多人同時重跑 |
| 進度顯示 | 非完成不達 100%；真實子進度取代固定半格；待補資料停止旋轉；獨立步驟有正確名稱 | 線上 job 狀態、觸發器能否接續 |
| 日期切換 | 郵件查詢忽略較舊請求晚到的回應 | 真實部署讀取延遲與錯誤頁 |
| 寄信 | 保留同日防重寄與既有寄送狀態 | 本次未寄信；已寄出的信不會被遠端改寫 |

GAS 一般執行限制為每次 6 分鐘；單一網路请求耗時仍可能吃掉整次预算。這版只對找到的高風險重複入口做有界處理，不宣稱所有雲端操作已有端到端保證。[GAS 限制](https://developers.google.com/apps-script/guides/services/quotas)

## 九、上線與比較步驟

1. 使用本次 source ZIP 作為同一批版本更新；Apps Script 新增 Config、API、DB、Logic、Refreshrunner，再更新其他變動檔案。不要同時保留舊 Code.gs 的函式副本。
