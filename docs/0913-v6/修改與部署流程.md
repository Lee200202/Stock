## 3. 文章品質及呼叫次數

來源充足時：③盤勢6–10點、⑤教學5–8點，每點約70–140字；個股說明2–4句、約70–160字。結構是現象、講者明講的原因、條件及觀察訊號，不能自行發明「未定價利多」。

新流程把篇幅與漏收疑點加入既有 `context-review`，不是每個股票另問一次。長稿仍按完整JSON輸入／輸出與模型上下文預算分批，沒有把大量文字悄悄截掉。已有一次覆核後仍有缺口、且時間足夠，最多再覆核一次；所以較舊日誌可能多一次呼叫，換取可檢查的品質修復。仍不合格會留稽核疑點，不能宣稱零缺漏。文章以最終JSON本機產生，刷新時不另問Gemini。

`gemini-3.5-flash-lite` 支援 low／medium／high；目前兩端維持 medium，可用 `GEMINI_THINKING_LEVEL=high` 調高。high 不是免費額度增加，也不保證永不漏股。Google 的支援說明見 [Gemini thinking](https://ai.google.dev/gemini-api/docs/thinking)。本機未使用真實金鑰重跑兩份逐字稿，模型一致性須在部署後實測。

## 4. 價位及盤中 K 的邊界

- 公開價位只顯示 `2135`、`900以下`、`1000以上` 或 `未說明`。用途與多次價位寫在說明中。
- 多次成交原始價位在試算表保留，不用最高展示價取代平均成本。非交易觀察列可以存正規化摘要價。
- 沒有日 K 時仍擋格式、均線天數及無法確認黏連；無行情基準無法證明任何正常格式數字必定合理。不得宣稱完整驗價已完成。
- 有快取時依影片日期區間核對，沒有當日時只用截至影片日的歷史資料；不拿未來行情回頭驗證。超出區間清空價位，不猜乘十、乘百，也不強迫改持股方向。
- `即時快取` 新增開、高、低及行情日期。取自既有報價回應，不增加前端外部請求；Fugle 欄位依 [官方 Intraday Quote](https://developer.fugle.tw/docs/data/http-api/intraday/quote/)。
- 日 K 圖僅在同日快取有完整正值OHLC、且正式當日日 K 還沒入庫時加一根預覽。標示快取更新時間；跨日、資料缺漏、不合理高低不補。正式 K 已存在以正式為準；週／月 K 與績效只用正式資料。
- 舊即時快取尚無新增欄位時，等下一次盤中報價更新後才有預覽。沒有報價權限或行情商資料時，不用昨收假裝當日 K。

## 7. 預期日誌與進度

```text
寫入：操作紀錄、會員持股、每日整理
刷新：同步郵件內容 → 代號比對 → 持股追蹤
文章已更新；背景日K／績效將在 Gemini 用量摘要之後執行
本輪呼叫 Gemini ... 次 ...
背景：績效歷史；缺日K時自動補齊 → 再算持股 → 績效歷史 → 績效快照
```

這是同一個 GitHub 執行的後半段，並非啟動無法追蹤的背景程序。使用者可先閱讀網站與郵件查詢；已寄信件不重寄。後台額外分列「內容已更新100%」與「日K／績效尚未完成」，整體進度不會提早變100%。每批沿用檢查點，預算不足為等待日K；既有5分鐘觸發器冷卻10分鐘後自動接續，最多6輪，持續失敗則待處理。
