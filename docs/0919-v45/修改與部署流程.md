# 9/19 取稿交棒與介面修正（v45）

## 這次實際確認的問題

1. 舊影片清單已經有排版欄，但沒有「逐字稿來源」。原本用總欄數判斷是否補齊，會漏加來源欄；後台又按固定位置驗表頭，導致自動與手動入口互相不相容。現在保留 A–G 基本欄位，其他欄位按名稱追加，不搬既有排版資料。
2. pipeline 先讀 YouTube 清單才看原稿。原稿已在試算表時，清單錯誤仍會擋住交棒。現在先選試算表當日原稿，超過 200 字直接交棒。
3. 自動聽打期間可能有人貼稿。三端選列改為手動／手動保留優先；空來源但有原稿也受保護。自動聽打完成再次核對，並以追加列保存自動結果，避免跨服務同時寫同一列造成覆蓋。可能留下同日等待列，但選讀規則一致；需要整併時，既有後台工具可先乾跑、核對再備份套用。
4. 潤飾原本會連舊原稿一起回寫。現在只寫修飾欄，寫前檢查原稿沒有變；原稿變了就等下一輪讀新稿。
5. 完成的聽打片段原本只存在程序記憶體。現在保存至檔案，Actions cache 在棒次間接續；整輪時間將用盡就先停，不再開新片段。快取只存公開逐字稿，不存金鑰。平台強制砍掉或快取服務失敗仍可能重抓，因此不是持久資料庫保證。
6. sync_quality.py 還會重建根目錄 pipeline.py，復活模組名衝突。現在只保留 pipeline/pipeline.py，仍同步 GAS 提示詞與公開文字處理。
7. Holidays.gs 漏列在部署檔案檢查表，已補上。新來源欄的舊表升級也已納入。
8. 技術說明有過期 FAQ（例如沒有小時線），改為六段短圖解，保留作者資訊與既有切段導覽。後台區分「資料已寫入」與「網站／郵件已更新」，前者不顯示 100%。

## 對附件紀錄的核對

你提供的最新附件已記錄 13 個端對端斷言通過，包含實際取稿及手動優先兩幕；與前一份完成紀錄寫的「第 5、6 幕尚未做」不同，以新日誌為準。該次 9/18 聽打是約 30,213 字。這能證明當次取稿成功，不能推論未來排程一定準點或每次模型均成功。

本輪未呼叫真實 Gemini、未寫正式試算表、未寄信。分類、會員持股、原文證據、價格與文章品質規則延續現有 v44，不以舊版提示詞覆蓋。

## Apps Script 部署

這個資料夾目前共 **20 個 .gs、8 個 .html**，全部都是同一個專案的部署檔。

1. 在原本 Apps Script 專案保留現有設定與屬性，先備份。
2. 同名檔案整份更新；缺檔用「新增指令碼／HTML」建立。不要把多份內容併貼到 Code.gs。
3. 新增 Holidays.gs。若已有檔案，更新內容即可。
4. 更新所有下列檔案，避免只貼入口而漏掉相依函式。

`API.gs`、`Adminpipeline.gs`、`Adminservice.gs`、`Aiservice.gs`、`Articlequality.gs`、`Cachebuilder.gs`、`Cmoney.gs`、`Code.gs`、`Config.gs`、`DB.gs`、`Evidencequality.gs`、`Holidays.gs`、`Logic.gs`、`MailService.gs`、`Presentationquality.gs`、`Quoteservice.gs`、`Refreshrunner.gs`、`Setup.gs`、`SheetService.gs`、`Transcriptstore.gs`

`Admin.html`、`Changelog.html`、`Index.html`、`JavaScript.html`、`Settings.html`、`Stylesheet.html`、`Tech.html`、`Unsubscribed.html`

5. 存檔後執行 `checkProjectFiles()`，確認沒有缺檔或版本錯配。預期 build：`2026-09-19-quality-v45`。
6. 既有表頭會由程式補缺欄；不必刪資料或搬欄。如果 A–G 已被改名／改序，先人工核對，程式會拒絕把資料寫到錯欄。
7. 「部署」→「管理部署作業」→ 選原本網頁應用程式 → 編輯 → 版本選「新版本」→ 部署。使用原部署即可保留 /exec 網址。
8. 用原 /exec 網址加 `?action=ping` 確認 build；重整網站與後台。
9. **不要執行 installTriggers()**。既有 everyFiveMinJob、16:45 日 K 等觸發器保留。
10. 手動投稿仍使用原後台；若只想先預留一天自己貼稿，可用 transcript workflow 的 hold，貼稿後由後台送出工單。解除保留使用 release。

## GitHub 部署與驗收

1. 更新 `transcript.py`、`pipeline/pipeline.py`、`.github/workflows/transcript.yml`、`scripts/sync_quality.py` 及本輪測試。根目錄不能放回 pipeline.py。
2. 保留既有 requirements、market_holidays.py 與 daily.yml。兩個 workflow 以影片清單交棒，不互相呼叫。
3. Variables 的 GEMINI_MODEL 維持實際驗證可用型號；備援模型需先用 workflow mode=check 列出的型號驗證，不填猜測名稱。
4. Secrets 保留 GEMINI_API_KEY（與備援金鑰）、YOUTUBE_API_KEY、SPREADSHEET_ID、GOOGLE_SHEETS_SERVICE_ACCOUNT。服務帳號仍須有試算表編輯權限。
5. 下一交易日觀察：11:05 起取稿輪詢；完成片段出現快取檔；原稿落地後 daily 流程應印「試算表原稿已就緒，直接交棒」。原稿就緒仍不保證 12:00 前寄出，取決於平台排程、回放就緒與模型時間。
6. 手動稿／手動保留應先停自動取稿，不查影片、不重抓。手動較短的新稿仍優先，不能被較長自動稿選走。
7. 前台確認每日總覽、會員持股、郵件、逐字稿、個股與技術說明；後台看待複核、等待日 K、資料已寫入三種狀態。已寄出的信不重寄。
