- 保留inline核心樣式與背景／文字顏色，不必全數推倒。Gmail支持部分style和media query，刪掉「Gmail一律丟style」的錯誤說明；仍需多收件匣實測。
- Gmail寄件者旁退訂按鈕與正文取消連結不同；MailApp現路徑沒有RFC8058標頭，不能捏造設定。需要時評估支援的寄送方法、資格與投遞規則。

### C. 自動寄送可靠性：先解決逐收件者漏寄

目前dailyPushJob第一封成功就把整日標已寄；後面失敗者不會續送。cmNotifyNew_額度不足只取前N人，錯誤記log、最後文章標已通知N人；核對callers是否另有補救，不可假設有。

改成每位收件者的delivery ledger：

```text
messageId = 種類 + 日期/文章ID + 固定內容版本
recipientKey = 受控的收件人識別
state = pending / sending / accepted / retryable / unknown / cancelled
attempt, leaseUntil, lastErrorCode, nextRetryAt, acceptedAt
```

只續送明確未成功的收件者，不把整批從頭寄。已接受的收件者不能因同日原文更新再收一次。固定批次內容版本，網站可發布較新版本但兩者可追溯。

寄信成功但寫帳本前程序中斷的狀況，若發送端沒有idempotency證據，不可宣稱完全exactly-once；標結果不明，設受限恢復規則。MailApp成功僅為服務接受，不代表Gmail已送達或已讀。
