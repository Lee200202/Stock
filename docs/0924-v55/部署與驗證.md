# v55 手機排版與自動化監控：部署與驗證

版本：`2026-09-24-quality-v55`。本版以 v54 的 33 個 Apps Script 檔案為基礎，沒有改動 GitHub Actions 的 Python 正本 `pipeline/pipeline.py`，也沒有改動既有試算表欄位。GitHub 的 `apps-script/` 是完整可部署來源；推送 GitHub **不會自動更新** Google Apps Script 的 `/exec` 網站。

## 這次改了什麼

- 市場卡片在手機與「版面設定＝手機」時固定單欄，數字不拆行；大字級會隨卡片寬度收斂。
- 現有持股的「新成本／備註」改成足寬、至少 46px 高的欄位；1280px 以下改疊列。
- 會員簡訊稽核圖例明確採橫向膠囊，避免全站 `.empty` 空資料樣式把文字擠成直排。
- 後台新增「自動化監控」：每分鐘在分頁可見時讀取狀態，檢查五分鐘總排程心跳、必要觸發器、逐字稿、會員簡訊、郵件寄送帳本、日 K、績效與今日失敗紀錄。綠色僅表示目前沒有偵測到異常；郵件的「服務接受」不代表已投遞到收件匣。
- 可設定**當日**整理信最早寄送時間（12:00–21:55，每五分鐘一格）。預設 12:00；文章與品質關卡就緒後才寄，已開始寄送不可更改。設定只對當天生效，隔天恢復預設。
- 修正今日狀態的日 K 變數被郵件摘要覆蓋，導致日 K 卡片誤顯示進行中的問題。

## 部署檔案

請以儲存庫 `apps-script/` 中 **全部 33 個檔案**（21 個 `.gs`、12 個 `.html`）更新原 Apps Script 專案。這次實際有變更的檔案是 `Admin.html`、`Adminservice.gs`、`Config.gs`、`MailService.gs`、`Market.html`、`Setup.gs`；整套部署可以避免舊檔混用。沒有新增 Apps Script 檔，`Setup.gs` 的專案檔案清單仍是 33 個。不要把測試、Python 或文件貼入 Apps Script，也不要重建根目錄 `pipeline.py`。

## 部署前

1. 開正式 `/exec?page=admin`，到「今日與投稿」確認沒有正在寫入的工單。若有，等它完成或記下工單狀態後再操作。
2. 到 Apps Script「部署 → 管理部署作業」記下目前正式部署的版本號，以便回退。維持同一個部署 ID；這樣郵件內的網站與退訂連結不用換網址。
3. 在 Apps Script「專案設定 → 指令碼屬性」確認原有 `ADMIN_KEY`、`WEBAPP_URL`、API 金鑰仍在。新版本不要求新增密鑰，也不要把密鑰貼進 GitHub。
4. 建議避開盤中直播判讀與寄信中的時段更新。若今日整理信還沒寄，先記下寄送狀態與收件者帳本，以利部署後比對。

## 更新 Apps Script

1. 從 [GitHub 儲存庫](https://github.com/Lee200202/Stock/tree/main/apps-script) 取得 `apps-script/`。在原 Apps Script 專案逐檔替換 21 個 `.gs` 與 12 個 `.html`；HTML 檔在編輯器內用原檔名（不帶 `.html`）。先儲存全部檔案。
2. 在編輯器執行 `checkProjectFiles()`，確認沒有缺檔、標記缺失或版本不合；`Config.gs` 的 `GAS_BUILD` 和 `Setup.gs` 的 `PROJECT_BUILD_` 都應為 `2026-09-24-quality-v55`。
3. 檢查原有排程是否還在。正常情況**不必**執行 `installTriggers()`：本版沒有增加觸發器。若監控頁顯示缺少觸發器，先確認是否有一次性工單正在跑，再在 Apps Script 執行紀錄核對；只有確定需要重建時才執行 `installTriggers()`，因為它會刪掉現有觸發器後重裝常設排程。
4. 用「部署 → 管理部署作業 → 編輯」選擇**新版本**並更新原正式網頁應用程式。不要只儲存程式碼或只打開 `/dev`：那不會更新所有人使用的 `/exec`。維持原本的執行身分與存取設定。
5. 開原正式網址 `/exec?action=ping`，檢查 build 是 `2026-09-24-quality-v55`，features 含 `ops-monitor-v55`、`mobile-spacing-v55`。若 ping 仍是 v54，先確認部署作業選的是新版本，而非重建另一個網址。

## 逐頁驗收

1. 手機打開 `/exec`，點「持股追蹤／市場總覽／績效走勢／個股查詢／訂閱／會員通知／逐字稿／郵件查詢／技術說明」。每頁都要能切換、返回、捲到底，且整頁沒有水平捲動。市場總覽的加權指數與台指期應各占整行，價位數字不拆開；在設定中選大字級再檢查一次。
2. 開 `/exec?page=admin`，依次點「今日與投稿／逐日編輯／現有持股／維護工具／會員簡訊／自動化監控／版本沿革」。檢查每頁內容寬度、按鈕、進度、錯誤訊息與日曆；尤其現有持股的成本與備註欄應能完整點按輸入，會員簡訊稽核圖例應橫排且不蓋住月曆。
3. 在監控頁按「立即檢查」。應顯示更新時間、各項狀態及今日預定時間線；一分鐘後仍停在此頁會自動更新。切去其他頁時不再持續輪詢。五分鐘排程心跳顯示的是**啟動時間**，請對照最近執行紀錄判斷是否完成。
4. 先不要改正式寄送時間也不要寄測試信。若確實要調整今日最早寄送時間，選 12:00–21:55 的五分鐘格並按「儲存今日時間」；畫面應回報今日日期與所選時間。已寄送、寄送中或部分寄送時會拒絕變更。
5. 郵件狀態要對照「每日推播內容」與「寄送帳本」：服務接受、待續送、失敗、結果不明分開看。逐字稿要對照今日影片與工單；日 K、持股與績效依背景排程完成，不因文章先發布就立即宣稱全部成功。

## 排查與回退

- 監控頁顯示「五分鐘排程超過 20 分鐘沒有啟動紀錄」：交易日 09:00–22:00 時先看 Apps Script「觸發器」是否有 `everyFiveMinJob`，再看「執行紀錄」最近一次錯誤。部署後第一棒執行前可能短暫顯示尚無紀錄。
- 監控頁顯示郵件結果不明：帳本可能在 MailApp 接受請求和寫入確認之間中斷；系統不自動重寄，先人工查帳本與實際收件情況。
- 寄信晚於設定時間：設定的是**最早**時間，請看文章、品質關卡、額度、正式 `/exec` 網址及寄送帳本，不要直接把「尚未寄」當成排程停止。
- 新版異常時，在「部署 → 管理部署作業」把同一部署改回部署前記下的舊版本。試算表、寄送帳本、當日時間設定不會因程式碼回退而自動還原；不要為了測試重複寄信。
