# v56 預告停播：部署與驗證

版本：`2026-09-24-no-show-v56`。本版修正 2026/09/24 已預告請假，11:09 啟動的取稿仍在 11:34 寫出「敲了 9 次仍未取得」的問題。

## 判定與流程

1. 交易日 11:05 起，`transcript.py` 先讀前一個交易日的**原始**逐字稿，只接受「明天我放假／請假／休息」、「明天不播」或「明天怎麼沒有上……請假」等明確語句。修飾稿、一般市場休假討論和假設問句不作依據。讀稿失敗時維持正常輪詢。
2. 每一棒仍查一次當日 YouTube 頻道。有影片就照常聽打；沒有影片且有明確預告，就寫「預告停播」，立即結束本棒。接下來的 GitHub 排程各查一次；Apps Script 五分鐘備援在 12:30 前不重複派密集取稿。無預告的普通交易日仍用既有輪詢，不因 11:05 尚未看到影片就誤判停播；過去有影片約 11:04–11:24 才進頻道。
3. 12:30 後再次查頻道仍無當日影片，寫「今日無直播」，後續取稿、每日判讀與備援停止。每日判讀在 15:00 後可將尚未確認的預告狀態補成正式無直播。若當日有人工原稿或當日影片，仍優先處理原稿／影片。
4. 後台「今日與投稿」「自動化監控」「開始取稿」進度和管理員狀態信分別顯示「預告停播」與「今日無直播」，不把舊的「逐字稿等待中」當作最新結論。會員簡訊及行情原本的排程照常運作。

## 部署步驟

1. 在 [GitHub `main`](https://github.com/Lee200202/Stock) 確認包含本版提交。GitHub Actions 下次執行會自動使用新的 `transcript.py` 和 `pipeline/pipeline.py`，不需要改 Secret、cron 或試算表欄位。已經啟動的舊版 run 不會在中途換程式碼；看**新啟動** run 的日誌。
2. 將 GitHub 的 `apps-script/` **全部 33 個檔案**（21 個 `.gs`、12 個 `.html`）覆蓋到現有 Apps Script 專案，保留同名檔案。這版實際修改 `Admin.html`、`Adminservice.gs`、`Config.gs`、`MailService.gs`、`Setup.gs`；整套更新可避免 v55 舊檔混用。不要貼 Python、測試或文件，也不要新增根目錄 `pipeline.py`。
3. 在 Apps Script 編輯器執行 `checkProjectFiles()`；`Config.gs` 的 `GAS_BUILD` 與 `Setup.gs` 的 `PROJECT_BUILD_` 都要顯示 `2026-09-24-no-show-v56`。本版沒有新增觸發器，正常不用重跑 `installTriggers()`。
4. 「部署 → 管理部署作業 → 原網頁應用程式的鉛筆編輯 → 版本選**新版本** → 部署」。保留原部署 ID、執行身分與存取設定。只儲存程式碼或開 `/dev` 不會更新正式 `/exec`。GitHub 推送亦不會自動部署 Apps Script。
5. 開原正式 `/exec?action=ping`，確認 `build=2026-09-24-no-show-v56`，features 含 `no-show-v56`；再開 `/exec?page=admin` 的今日狀態與自動化監控。若 ping 還是 v55，回到原部署的編輯畫面選「新版本」，不要另建部署。

## 當日驗收與限制

- 11:05–12:29，有明確前日預告且當日頻道無影片：新 run 只查一次，系統狀態有一筆「預告停播」，後台顯示同名狀態，不再出現新的「敲了 9 次仍未取得」。GitHub cron 可能延遲，11:05 是**程式允許開始的時間**，不是保證實際啟動時間；看 run 的台北時間。
- 12:30 之後下一棒：若當日頻道仍無影片，狀態改「今日無直播」；後續 run 直接略過，每日總覽不會憑空產生或寄給訂閱者。若有當日會員簡訊，盤中通知照常處理。
- 如預告後臨時開播，當日影片會優先於預告，正常寫原稿並交給 `pipeline.py`。若自動識別失敗，管理者仍可在後台手動貼原稿；正式停播標記不會覆蓋人工稿。
- 舊的 11:34「逐字稿等待中」是已寫入的歷史系統狀態列，本版不刪紀錄；新版後台以較新的預告／正式停播結論顯示。版本部署前已寄出的管理員狀態信也不會追溯修改。

本機驗證：`python -m unittest discover -s tests -p test_planned_no_show.py -v`、`node tests/test_no_show_dispatch.js`、既有 Apps Script 回歸。這些測試以假試算表與假時間執行，不曾在此環境實際聽打或寄信；Apps Script `/exec` 仍須按上述步驟部署並核對新 build。
