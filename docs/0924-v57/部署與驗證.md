# v57 力旺出場價與自動化監控：詳細部署與驗證

版本 `2026-09-24-ops-exit-v57`。本版沒有改 Python、GitHub Actions 或試算表欄位；需要更新 Apps Script 的 33 個來源檔（21 個 `.gs`、12 個 `.html`）。本輪實際變更 `Admin.html`、`Adminservice.gs`、`Changelog.html`、`Config.gs`、`MailService.gs`、`Marketservice.gs`、`Setup.gs`、`SheetService.gs`。GitHub 推送只更新程式庫，不會替正式 `/exec` 建立 Apps Script 新版本，也不會直接改動力旺的試算表出場價。

## 為什麼力旺顯示空白

正式站的力旺（3529）第 1 回合在 2026/09/23「轉觀望不碰，視為出場」，成本 2,650 元，出場價卻是 `—`。這是持股追蹤已寫入的空值；個股面板顯示的 9/24 即時價 3,230 元不可回填 9/23 的已實現損益。原程式在轉觀望時呼叫 `priceOnDate_`，若日 K 快取只有 9/23 以前的棒，找不到「當日或更後」的棒就回空。本版對立場轉變獨立取 9/23 收盤；當日棒暫缺時只取**之前**最近交易日收盤並在來源明示該日期。單檔修復會要求 9/23 的有效日 K，補入後重算持股與 9/23 起的績效，並檢查新出場價等於補入的正式收盤；查不到就停下且保留原資料，不用 9/24 價格猜測。

## 部署前先記錄現況

1. 開 [正式網站後台](https://script.google.com/macros/s/AKfycbyLQjAd-CnQ6D6_JP3OY1WwXDkafCJthzeP3G4FDkT4t26PY9Gx1rhrXJjiHVZExQhoaw/exec?page=admin)，在「今日與投稿」及「自動化監控」確認沒有正在寫入的工單。先記下力旺原列、當日寄信帳本、最近一輪日 K 完成時間。若工單正在寫入，等它完成再更新。
2. 在 Apps Script「部署 → 管理部署作業」記下目前正式版本，以備回退；保留原部署 ID 與 `/exec` 網址。指令碼屬性及金鑰原樣保留，不要貼進 GitHub。
3. 查看現有觸發器清單及 `checkAutomationReadiness()` 輸出。舊版的 `marketSnapshots:false` 只表示沒有**獨立** `marketSnapshotJob` 觸發器；五分鐘總排程已呼叫它，不能據此判定行情停止。`hourlyHistory:false` 則表示 19:15 的獨立歷史 60 分 K 觸發器確實缺少。`marketRows:7` 是快取列數，不等於今天已成功取得七筆即時行情。

## 更新原 Apps Script 專案

1. 從 [GitHub 的 apps-script 目錄](https://github.com/Lee200202/Stock/tree/main/apps-script) 取得本版**全部 33 個檔案**，在原 Apps Script 專案逐一覆蓋同名檔。`.html` 在編輯器使用不帶副檔名的 HTML 檔名。不要新增根目錄 `pipeline.py`，不要重建試算表，也不要只貼 `Admin.html` 而保留舊 `Adminservice.gs`。
2. 全部儲存後，在 Apps Script 編輯器執行 `checkProjectFiles()`。須回 `ok:true`，`Config.gs` 的 `GAS_BUILD` 與 `Setup.gs` 的 `PROJECT_BUILD_` 都是 `2026-09-24-ops-exit-v57`。有缺檔或標記不符時先修正，不要發佈混版。
3. 執行 `checkAutomationReadiness()`。預期 `everyFiveMin:true`、`dailyK:true`、`marketSnapshots:true`、`marketSnapshotMode:"五分鐘總排程"`；`marketSnapshotLast` 會另外指出最近一次採樣時間及結果。若 `hourlyHistory:false`，在編輯器執行一次 `installMarketDataJobs()`，它只補 19:15 歷史分 K 觸發器，不重建原有觸發器。再執行 `checkAutomationReadiness()`，確認 `hourlyHistory:true`。**不要為市場快照另跑一支五分鐘觸發器，也不要因兩個 false 直接重跑 `installTriggers()`。** 本版 `installMarketSnapshotJob()` 在總排程存在時會直接略過，避免重複採樣。
4. 在編輯器執行 `repairLiwangExitPriceNow()`。它先讀力旺目前出場日；若 9/23 有正式日 K 直接重算，否則只向既有 Fugle／FinMind 來源補該日棒，補成才重算。執行紀錄要看到 `exitDate:"2026/09/23"`、`close` 與 `trackerExit` 為相同且大於零的數值。若來源沒有有效 9/23 棒，函式會報錯並保留資料；先用 `auditDailyKCoverage(['3529'])` 查缺口，必要時執行 `backfillDailyKJob()`，待其整輪完成後重試。不能把 9/24 盤中價手填成 9/23 出場價。
5. 若要核對歷史 60 分 K，可先執行 `auditHourlyCoverage('3529')`。安裝 19:15 觸發器只保證未來會跑，**不代表歷史已補滿**；需要立刻補第一輪可執行 `backfillHourlyHistoryNow()`，它會保存游標並自動續跑。用 `auditHourlyCoverage` 追進度，不要因首次尚在跑就重複啟動多輪。
6. 使用「部署 → 管理部署作業 → 編輯 → 新版本 → 部署」更新**原**網頁應用程式。保留原來執行身分、存取設定與部署 ID。只有儲存檔案或開 `/dev` 不會更新訪客的 `/exec`。

## 發佈後逐項核對

1. 開 [正式 ping](https://script.google.com/macros/s/AKfycbyLQjAd-CnQ6D6_JP3OY1WwXDkafCJthzeP3G4FDkT4t26PY9Gx1rhrXJjiHVZExQhoaw/exec?action=ping)，確認 `build` 為 `2026-09-24-ops-exit-v57` 且 `features` 含 `ops-exit-v57`。仍顯示 v56 就回到原部署編輯畫面建立新版本。
2. 前台「持股追蹤 → 已出場 → 力旺」須有 9/23 對應的出場價與已實現報酬；點進個股面板核對「出場價來源」。不要拿 9/24 即時行情或 9/24 的 K 棒代替 9/23。若來源只寫「之前最近交易日」，代表正式 9/23 K 尚未補上，繼續按上節補 K。
3. 後台「自動化監控」檢查每日總覽信、盤中即時信**分開**的寄送帳本：各自的服務接受人數、首次／最近時間、待續送、失敗、結果不明應與寄送帳本對上。「服務接受」表示 MailApp 接受請求，不保證進收件匣。沒有直播的日子每日整理信顯示不需寄送；會員簡訊通知仍可單獨發出。選 15:00 快捷時間應只改輸入欄，按「儲存今日時間」才寫入；已開始寄送不得改，隔天恢復 12:00。
4. 同頁看主排程心跳、取稿狀態、會員簡訊來源、日 K 的**完成日期**、缺出場價檔數、市場快照的最近結果、歷史分 K 排程與進度、績效最後日期。黃色表示待補或尚未到時段，不要只看 `ready:true` 就宣稱整條工作流完成。
5. 在手機或「版面設定 → 手機預覽」依序點每日總覽、持股追蹤、市場總覽、績效走勢、訂閱通知、郵件查詢、會員通知、逐字稿、技術說明，再檢查後台今日與投稿、逐日編輯、現有持股、維護工具、會員簡訊、自動化監控、版本沿革。監控卡片桌面最多三欄、手機單欄，寄送時間控制與時間線不得水平溢出。按「立即檢查」應更新檢查時間；不要用「儲存」或重算按鈕當純版面測試。

## 本輪驗證與限制

離線執行 `node tests/test_gas.js`、`node tests/test_ops_monitor_v55.js`、`node tests/test_ops_exit_v57.js`、`node tests/test_no_show_dispatch.js`、`node tests/test_roomy_layout_v54.js`，以及 Python 的 5 項停播回歸。正式站九個公開分頁已逐頁實際點選，桌面及網站「手機預覽」各留截圖於 `screenshots/`。正式後台在本次瀏覽工作階段顯示管理密鑰登入頁，沒有登入驗收正式後台；本機完整 `Admin.html` 模板已逐頁點選七個後台分頁，**只有自動化監控頁**接上模擬回應並測試「立即檢查」及時間快捷鍵，其餘頁面只驗證靜態排版，不宣稱真實資料或功能已驗收。這些預覽資料不代表正式站已寄信或力旺已修復。尚未在 Google Apps Script 建新版本，也未在正式試算表執行修復函式。
