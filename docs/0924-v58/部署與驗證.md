## 一、這次改了什麼

### 取價規則（後端，`SheetService.gs`）

| | 以前 | v58 |
|---|---|---|
| 進場價 | 有明講價且當天成交區間內就用明講價；沒講價用當日最低；持有聲明用收盤 | **一律取成交日「當日最低」**（持有聲明取聲明當日或之前） |
| 出場價 | 明講賣出用明講價或當日最高；轉觀望、逾期用收盤 | **一律取出場日「當日最高」**（轉觀望、逾期只取當日或之前的交易日） |
| 張震明講的價位 | 當成交價 | **灰字附註**：「明講 73.5 以下買進」「明講 255 以上賣出」「明講成本 2250」；沒成交加「期間未成交」「查無成交紀錄」 |

- 條件價（「跌到 241 以下買」）、回述成本（「會員在 2135 買的」）的判斷不變，仍然決定**哪一天**成交；價格改成那一天的最低／最高。
- 被判定「不是這一檔價位」的數字（例如 8）不會變成附註。
- 後台「現有持股」手動修正的成本仍然優先。
- 持股追蹤分頁新增兩欄：「進場明講」「出場明講」；回合JSON 多存當日高低與明講價（給區間圖用）。重算時自動寫入，**不用手動加欄**。
- 取價立場的效果：買最低、賣最高是跟著喊單能拿到的最好結果，報酬會比實際成交好看。網站計算說明（問號）已寫明。

### 網站

- **持股追蹤表**：十欄改三欄——股票｜交易軸｜最新說明（已出場時是出場原因）。狀態、持有天數、提及拿掉；進場價、目前價、報酬收進交易軸：左端進場日與進場價，右端目前（或出場日）與價格，報酬寫在線上，上漲紅、下跌綠，明講價是灰字。最新說明在桌面約佔一半寬度；手機一檔一張卡。
- **個股面板**：新增「取價區間」圖——進場日、出場日各一條當日最低～最高，實心點＝採用的價，空心圈＝張震明講，第二條線畫出從進場價到目前價的一段並寫報酬。圖上已有的價格、日期、報酬不再用卡片重複（上方只留首次提到日期、回合、累積報酬、參考價位、出場原因）。舊資料還沒重算、畫不出圖時，退回原本的卡片。
- 信件沒有持股追蹤表（只有當天的買賣與持股明細），所以狀態／持有天數／提及原本就不在信裡，不用改。

## 三、部署步驟

1. **避開盤中與寄信時段**：建議 17:00 以後或 08:30 以前。Apps Script 的排程會立刻使用「已儲存」的程式碼，一邊貼檔一邊跑會新舊混用。
2. 開正式 `/exec?page=admin` →「今日與投稿」與「自動化監控」確認沒有工作正在寫入；到「部署 → 管理部署作業」記下目前正式版本號（回退用）。
3. 從**本機** `apps-script\` 資料夾（GitHub 不放 Apps Script 原始碼）在原 Apps Script 專案逐檔整份替換 33 檔（HTML 用不帶副檔名的檔名），全部儲存。
4. 編輯器執行 `checkProjectFiles()`：必須 `ok:true`、build `2026-09-24-quality-v59`。有「缺檔」或「marker 不符」就把那一個檔重貼。
5. 「部署 → 管理部署作業 → 編輯 → 版本：新版本 → 部署」。沿用同一個部署（網址不變）。開 `正式網址?action=ping` 確認 build 與 features。
6. **重算持股追蹤與歷史績效（新取價要套用到全部歷史）**，二選一：
   - 推薦：GitHub → Actions → **`day-edit-sync`** → Run workflow → `mode = performance`。它會依序重算持股 → 重建 7/08 起的歷史績效 → 記錄目前績效，不重抓逐字稿、不跑 Gemini、不寄信。在後台「今日與投稿」看進度到完成。
   - 或在 Apps Script 編輯器依序執行 `rebuildHoldingsTrackerJob()`，再執行 `rebuildPerformanceHistoryJob('2026/07/08')`。
7. 不要執行 `installTriggers`、`dailyPushJob`、`repairDailyKCache`。
