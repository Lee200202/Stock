# v63：持股追蹤交易軸對齊

持股追蹤每列的進場日期、價格和口頭價長度不同。舊樣式讓交易軸左右兩欄依內容自動伸縮，因此同一張表的線段與端點不對齊。v63 將左右兩欄設為等寬、中央報酬欄固定相同比例；口頭價限制在自己的欄位內。這是純版面修改，不更動買賣、持股、日 K 或績效資料。

## 驗證

本機以實際 `Index.html`、`Stylesheet.html`、`JavaScript.html` 和模擬資料在 Chromium 檢查 1440、1280、900、768、390、360 像素寬度。每種寬度的四筆持股交易軸，左右端點位置逐筆相同；桌面與手機皆無橫向溢出。`test_tracker_layout_v58_gas.js`、`test_project_check_v37_gas.js` 通過。這是離線版面驗證，不代表正式網站已部署。

## 部署到原 Apps Script 網頁應用程式

部署包：`release/zhangzhen-tracker-axis-v63.zip`，含 `Cachebuilder.gs`、`SheetService.gs`、`JavaScript.html`、`Stylesheet.html`、`Config.gs`、`Setup.gs`。前五個中的 `Cachebuilder.gs`、`SheetService.gs`、`JavaScript.html` 保留 v61／v62 的近期日 K、價格與快取修正。若原專案已是 v62，實際新增的修改只有 `Stylesheet.html`、`Config.gs`、`Setup.gs`；如不確定目前版本，使用包內六檔可避免混版。不要把整個舊專案重建，也不要覆蓋包外的其他檔案。

1. 進入目前正在供正式網站使用的 **同一個** Apps Script 專案。在編輯器將包內六個同名檔案的內容逐一貼上並儲存；既有 Script Properties、試算表與觸發器保持原樣。
2. 在編輯器執行 `checkProjectFiles()`。應顯示沒有缺檔或版本不一致，`Config.gs` 的 `GAS_BUILD` 和 `Setup.gs` 的 `PROJECT_BUILD_` 均為 `2026-09-24-tracker-axis-v63`。若有缺檔，先補正，暫不要部署。
3. 依序按「部署」→「管理部署」→目前正式網頁應用程式旁的編輯鉛筆→「版本」選「新增版本」→部署。**更新原部署**，沿用原本 `/exec` 網址。只在編輯器儲存，正式網站不會自動換版。
4. 打開原網址後面加 `?action=ping`，確認回傳 `build` 為 `2026-09-24-tracker-axis-v63`。若仍是舊版，回管理部署檢查是否編輯了正確的部署、是否選了新增版本；必要時重新整理並再確認一次。
5. 在正式網站強制重新整理後，進入「持股追蹤」→「目前持有」及「已出場」，檢查同一區塊每列線條的兩端圓點是否垂直對齊；手機也檢查一次。此次不必執行 `snapshotPerformanceJob()`、補日 K 或全站重算。

GitHub 更新只提供部署包與說明，不會自動部署 Apps Script 正式網站。
