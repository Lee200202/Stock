# v66 隔年休市與 Gemini 月度模型盤點

本版將台股交易日判斷放在排程最前面。已知休市日跳過影片抓取、逐字稿稽核、日 K 與市場行情工作；會員簡訊仍由每分鐘觸發器接收，五分鐘排程仍替簡訊補抓、解析派工及續寄。手動補資料的 GitHub `workflow_dispatch` 不受交易日預檢限制。

## 休市日來源與年度更新

| 地點 | 更新方式 | 查不到隔年正式資料時 |
|---|---|---|
| GitHub／Python | `calendar-yearly.yml` 從十月到隔年一月每週查證交所；首次取得完整資料後只提交一次 `pipeline/market_holidays.py` | 不寫入假日期；下週重試。跨年仍缺資料時，台股自動排程暫停並在 Actions 日誌告警 |
| Apps Script | `Holidays.gs` 從十月起每七天最多查一次，核實後存在指令碼屬性；跨年尚缺時每七天重試 | 暫停台股自動工作，日誌標明「年度休市日尚未核實」；會員簡訊續行 |

目前證交所查詢 **2027 年得到 0 筆**（2026/09/25 實測），因此沒有填入任何猜測日期。證交所資料包含「春節前最後交易日／春節後開始交易日」，這兩種會從休市清單排除。隔年資料首次公布後，GitHub 自動提交 Python 清單；GAS 自行查證，毋須每年重新部署。可在編輯器執行 `checkNextYearHolidays()` 查看結果；尚未公布時 `verified:false` 是正常狀態。

## Gemini 模型

官方 [models.list](https://ai.google.dev/api/models) 提供分頁模型清單及 `supportedGenerationMethods`。網站 AI 對話用**該使用者自己的金鑰**，每個月讀完全部頁面、只挑文字 Flash／`generateContent`，再用短回覆實測，選單只顯示通過者。新型號會自動加入、已不可用型號會從該月選單移除；429、503 與連線失敗屬暫時狀態，不在 GitHub 報告中當作過期。重開頁面沿用當月快取，不重複花測試額度；官方暫時壅塞時沿用上次成功清單，六小時後重試，並明示資料較舊。介面下方「本月模型與 API 使用次數」伸展窗格會列出查表／短回覆實際呼叫數，並註明無法讀取免費額度剩餘量。

`gemini-models-monthly.yml` 每月 1–7 日找到首個台股交易日後，用 GitHub 現有三把金鑰查驗，將不含金鑰的結果提交到 `data/gemini-models.json` 並上傳同名 artifact；同月已有報告就跳過。報告只寫金鑰序號及模型狀態，不寫金鑰。若 GitHub `main` 禁止 Actions 直接推送，需開放該工作流寫入權限，否則 Actions 會明確失敗並於下個交易日重試。當 GitHub Variable `GEMINI_MODEL` 不在可用清單時，Actions 會警告；**Python 聽打與稽核的模型變數仍由管理者決定**，月度盤點不會擅自改動正式流程的模型，以免模型能力差異讓輸出品質變動。

## 部署順序

1. GitHub：本次 Python 程式及五條既有／新增 workflow 已推至 `main`。在 Actions 檢查 `台股隔年休市日盤點`、`Gemini 模型月度盤點` 出現；可手動執行一次。前者在 2027 未公布時顯示「下週再查」，不會改資料；後者需既有 `GEMINI_API_KEY` Secrets，會花短回覆測試額度。
2. Apps Script：正式站 `/exec?action=ping` 於 2026/09/25 回報 **v63**。請在**原專案**用 `zhangzhen-full-v66.zip` 的 **21 個 `.gs` 與 12 個 `.html`，共 33 檔**依同名完整替換／新增並儲存，避免 v63 與 v66 程式混用；不要新建另一個 GAS 專案。若你的編輯器已經部署完整 v65，才可改用七檔差異包 `zhangzhen-calendar-model-v66.zip`。不要建立根目錄 `pipeline.py`，也不要執行 `installTriggers()`。
3. 編輯器依序執行 `checkProjectFiles()`（應無缺檔／版本不符）、`ensureMonthlyModelTrigger()`（只需一次，重跑不重複；若觸發器已滿 20 個，或每月 1 日休市時，改用原有五分鐘排程於下一交易日 08:00 盤點）及 `checkNextYearHolidays()`。2027 尚未公布時，最後一項回 `verified:false`。若要盤點系統金鑰，請在交易日執行 `monthlyGeminiModelsJob()`；這會真正消耗模型查驗呼叫。休市日執行會顯示延後，交由下一交易日 08:00 的五分鐘排程完成。
4. 在 Apps Script「部署 → 管理部署作業 → 編輯現有網頁應用程式 → 新版本 → 部署」，沿用既有正式 `/exec` URL。開 `/exec?action=ping`，確認 build 為 `2026-09-25-calendar-model-v66` 且 features 包含 `calendar-model-monthly-v66`。
5. 在 Apps Script「觸發條件」確認原有 `everyFiveMinJob`、`cmoneyPollJob` 各仍只有一個，另有 `monthlyGeminiModelsJob` 一個；若已達 20 個上限，執行紀錄應顯示改走五分鐘總排程。不要重設其餘現有觸發器。打開正式站 AI 對話，展開模型使用次數說明；同一金鑰當月重開不再產生測試呼叫。
6. 休市驗收：2026/09/25、09/28 的 GitHub 定時 `transcript-gemini`、`daily-transcript-pipeline`、`market-data-cache` 在交易日預檢後跳過；GAS 五分鐘日誌印休市原因，會員簡訊每分鐘輪詢仍運作。若手動工單在假日補歷史資料，`workflow_dispatch` 可照常執行。

正式站 v63 用完整部署包：`release/zhangzhen-full-v66.zip`；v65 專案可用七檔差異包：`release/zhangzhen-calendar-model-v66.zip`。本次沒有直接部署 GAS 或用真實金鑰呼叫 Gemini；月度模型可用名單須在部署後實際執行才有結論。
