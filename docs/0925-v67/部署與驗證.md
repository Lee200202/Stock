## 三、部署步驟

1. **時間**：17:00 以後或 08:30 以前（排程會立刻使用「已儲存」的程式碼，邊貼邊跑會新舊混用）。
2. 開正式 `/exec?page=admin` →「今日與投稿」確認沒有工作正在寫入；「部署 → 管理部署作業」記下目前版本號（回退用）。
3. 在**原** Apps Script 專案逐檔整份替換上面 15 檔（HTML 用不帶副檔名的檔名），全部儲存。
4. 編輯器執行 `checkProjectFiles()`：必須 `ok:true`、build `2026-09-25-ops-kpanel-v67`。有「marker 不符」就把那一檔重貼。
5. 「部署 → 管理部署作業 → 編輯 → 版本：新版本 → 部署」，沿用同一個部署（網址不變）。開 `正式網址?action=ping` 確認 build 與 features。
6. **產業保底排程**（R5）：後台「自動化監控」的「產業成交比重」若寫「獨立保底排程未安裝」，按該格的「安裝保底排程」；或在編輯器執行 `installSectorCatchupJob()`。
7. 不要執行 `installTriggers`、`dailyPushJob`、`repairDailyKCache`。

## 四、部署後核對

1. **自動化監控**：多了「今天預計需要」與「觸發器今日累計」兩格（部署後第一棒觸發器結束才有數字）；「執行紀錄」右上角有日期選單，選前一交易日看得到當天每日總覽與盤中通知的接受人數；時間線第二行是「11:05 起 影片與逐字稿」。
2. **休市日（9/28 教師節）**：監控各格灰色「今天休市，不執行」；Apps Script「執行項目」裡 14:05～15:05 的五支排程只跑一秒多並記「排程略過」；「每日績效」**不會新增 9/28**。9/25 已經誤寫的那一列可以在試算表手動刪除（前台本來就濾掉，不刪也不影響圖）。
3. **今日與投稿**：前三格同一列；時間軸空狀態是一整行；投稿日曆 9/25、9/28 灰底斜線。
4. **會員簡訊**：載入收錄清單，9/24 那則的「即時通知」欄顯示寄送結果；手機寬度是卡片；流程只顯示一行「目前第 N 格」。
5. **個股面板**（點嘉澤 3533）：持有期間是「進場以來走勢」小圖，標題列寫「8/12 第一次提到 → 8/19 成交 → 持有 N 個交易日」；持股追蹤卡片左端是「8/19 進場（當日最低）」、灰字「8/12 提到，明講 1580 以下買進」——**三處日期要一致**。K 線工具列只有一行（週期膠囊＋右邊文字區間），均線是圖例、點了會開關；日 K 上有提到／進場三角形與兩條水平線；游標停在 K 線上滾輪會往下捲頁，按住 Ctrl 才縮放；十字線日期是 2026/09/23。
6. **逐日編輯同步失敗時**：Actions 的 Annotations 會出現「逐日編輯同步：＿＿」中文原因，後台今日狀態同一段原因變紅。
7. **GitHub Actions**：10/19 前手動跑一次 `day-edit-sync`（mode=queue）與 `market-data-cache`，確認 ubuntu-24.04／checkout@v5／setup-python@v6 正常。
