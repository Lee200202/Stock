# v70 技術說明部署與驗證

本版只修改網站「技術說明」及其版本標記，未更動取稿、判讀、簡訊、寄信、行情或持股計算程式。網站與郵件的會員持股專區保留。本文以 2026/09/26 本機檔案為準；**目前尚未替你部署 Apps Script，也沒有呼叫真實 Gemini 模型**。

## 變更

原本的六段步進器一次只顯示一段，重複四格卡與對話讓說明像制式手冊；三處持股出場價仍寫「收盤」，取稿時間也把 GitHub 備援誤寫成主流程。v70 改成一篇可連續閱讀的作者文章，前段放七個資料領域、三十多張分頁及六段工作流程。點分頁會標亮相關分頁並顯示誰寫、誰讀；點流程則標亮涉及的分頁。窄螢幕轉為直向，圖下另有文字版。分類、價格歸屬、持股日期的互動同步顯示選中狀態。

公開規則已校正：進場取當日最低、出場取出場日當日最高；逾十個交易日未提及在確認後回溯最後提及日，不向未來取價。11:05 起由 Apps Script 主排程派取稿，GitHub cron 備援；休市或隔年日曆未核實時暫停台股自動工作，會員簡訊仍照常處理。績效是理想上下限的示意，並非真實成交。

## Apps Script：替換六個檔案

從本機 `apps-script` 資料夾，將下列檔案的**完整內容**貼入同名 Apps Script 檔案：

1. `Tech.html`
2. `Stylesheet.html`
3. `JavaScript.html`
4. `Changelog.html`
5. `Config.gs`
6. `Setup.gs`

`release/zhangzhen-full-v70.zip` 包含當前完整 Apps Script 專案，可用來核對檔案。這次實際變更僅上述六個；不要把 ZIP 裡的檔案當成另一個新專案部署，否則指令碼屬性與試算表連結不會跟著移過去。貼上前請先匯出目前正式 Apps Script 專案備份，避免蓋掉你在編輯器裡尚未同步回本機的修改。

在原有專案貼上後：

1. 全部儲存，在編輯器執行 `checkProjectFiles()`。應看到 `2026-09-26-tech-story-v70`，且六個更新檔的 marker 都通過。
2. 到「部署 → 管理部署作業」，編輯目前正式的「網頁應用程式」部署，選「新增版本」，發布。沿用原有部署與網址，不用重新安裝觸發器，也不用執行 `setupSpreadsheet()`。
3. 開正式網址加 `?action=ping`，確認 `build` 是 `2026-09-26-tech-story-v70`，`features` 含 `tech-story-v70`。若仍顯示舊版，確認部署時有選「新增版本」，並重新整理。
4. 進「技術說明」：七個資料領域都可看見；點「會員簡訊」時「操作紀錄」「會員持股」「寄送帳本」亮起；點「補行情與績效」時「日K快取」「持股追蹤」「每日績效」亮起。
5. 分類按「現在還不能買」，按鈕與上方第三格同時選中；點 168、900、600，各自說明張數／條件價／漲跌額；拖日期到 8/25，第五個時間點亮起，文字顯示 8/10 當日最高。
6. 在 1440、768、390、360px 與深色模式看技術說明。手機不應左右滑整頁；流程直向，分頁字至少 12px，點選區至少 44px。按右側子目錄可跳各章，常見問題和作者一直在主文底部。
7. 核對目前網站其他分頁、會員持股區、郵件查詢仍正常。這版沒有改寄信函式，無須寄測試信。
