# GitHub 公開閱讀站：部署與驗收

Google Apps Script 的多帳號登入可能在網站程式啟動前顯示 Google 自己的「找不到檔案」頁。這個錯誤無法由站內 JavaScript 攔截。公開閱讀站改由 GitHub Pages 提供，訪客不需要登入 Google；資料仍由既有工作流寫入原試算表，再由 Actions 匯出**已公開**欄位。

## 會顯示什麼

每日總覽、當日操作與觀望、會員持股聲明、個股搜尋、持股追蹤、市場總覽快取、績效走勢、會員通知原文、已完成影片的逐字稿。沒有完成的影片不生成每日整理；會員通知仍可獨立出現。行情卡顯示來源及最後更新時間，GitHub 排程有延遲時保留最後成功快照並顯示過期提示。

不匯出訂閱清單、Email、LINE user ID、寄送帳本、管理工單、密鑰、判讀稽核。GitHub Pages 的內容是**公開**的，不能把後台或訂閱寫入放進靜態 JSON。原 GAS 後台、Email/LINE 訂閱寫入、AI 問答、五分鐘即時行情仍在原服務，不宣稱已完成遷移。

## 第一次啟用

1. GitHub 打開 `Lee200202/Stock` → **Settings** → 左側 **Pages** → **Build and deployment** 的 **Source** 選 **GitHub Actions**。
2. 確認儲存庫 Actions secrets 已有 `SPREADSHEET_ID` 與 `GOOGLE_SHEETS_SERVICE_ACCOUNT`。這兩項既有 `daily.yml` 與 `market-data.yml` 已在用，不要把內容貼進程式、Issues 或 Pages。
3. 打開 **Actions** → **public-site-pages** → **Run workflow** → 選 `main` → **Run workflow**。首次匯出讀不到必要表頭、或公開紀錄為空時會失敗並保留舊頁，防止空白站取代正常頁。
4. 等 `publish` 成功，回到 Settings → Pages 查看正式網址。一般會是 `https://lee200202.github.io/Stock/`，但以 Pages 畫面為準。用無痕視窗開它，應不需登入 Google。
5. 驗收日期選單、每日文章、會員通知、逐字稿、個股搜尋、持股追蹤、市場卡片。頁首「快照」時間必須更新；超過一小時會顯示舊資料提示。手機寬度須可閱讀且整頁沒有橫向捲動。

## 後續更新與故障

- 平日台北 09:00–17:45 每 15 分鐘排一次，其他時間早晚各一次；也能手動 Run workflow。GitHub 的 cron 可能延遲，因此這不是五分鐘即時行情。
- 每輪最多讀九張**指定的公開分頁**。若匯出失敗，Pages 保留上次成功的內容，網站顯示快照時間；先看該次 Actions 日誌，不要清空試算表重跑。
- 逐字稿、自動稽核、簡訊、行情與寄信仍由現有 GAS/GitHub 工作流執行；本 workflow 只讀取結果，**不寄信、不改表、不呼叫 Gemini**。
- 要停用公開鏡像，到 Settings → Pages 改回其他 Source 或停用 `public-site-pages`。已經公開的快照可能暫留在瀏覽器/CDN 快取；公開前需確認逐字稿與會員通知原文可公開。

## 改寄出的公開內容連結

先完成上述驗收，再考慮將郵件與 LINE 的「看整理」連結改到 GitHub Pages。**取消訂閱、管理訂閱、後台**仍須指向原 GAS `/exec`，不能把帶 token 的退訂連結寫進 GitHub 靜態頁。此版尚未改既有信件連結，避免 Pages 尚未啟用時寄出壞連結。
