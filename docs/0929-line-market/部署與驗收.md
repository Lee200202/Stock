## A. 先部署 Apps Script 原檔

1. 在 GitHub 打開 [`release/zhangzhen-full-v79.zip`](../../release/zhangzhen-full-v79.zip)，按 **Download raw file**；解壓。ZIP 是全部原 GAS 檔案，不要把 ZIP 當單一檔貼入。
2. 開**原本服務正式站的同一個** Apps Script 專案。先確認編輯器中的私有修改；再用 ZIP 中同名檔案完整取代這七個：`Line.gs`、`Marketservice.gs`、`Adminservice.gs`、`Config.gs`、`Setup.gs`、`Stylesheet.html`、`Admin.html`。其他檔案此次未改。副檔名 `.html` 要貼進同名 HTML 檔。
3. 按上方 **儲存**。從函式選單執行 `checkProjectFiles()`；執行紀錄應無缺檔，版本是 `2026-09-29-automation-health-v79`。再執行 `checkAutomationReadiness()`，確認五分鐘總排程及簡訊排程在清單中。這兩支是檢查，不會爬影片或寄信。
4. 執行 `lineSetupCheck()`，核對 access token／channel secret 已設定、bot ID、正式 `/exec`、轉送服務網址，以及五分鐘總排程 `everyFiveMinJob`。不要把 token 貼在聊天或 GitHub。若缺五分鐘總排程，才執行 `ensureAutomationTick()`；**不要**執行 `installTriggers()` 製造重複排程。
5. 點 **部署 → 管理部署作業**，選原正式網頁應用程式旁的 **編輯（鉛筆）→ 版本：新增版本 → 部署**。保持「執行身分：我」與原存取設定，保留原 `/exec` 網址。開 `正式 /exec?action=ping`，確認 build 為 `2026-09-29-automation-health-v79`；若仍是舊版，代表只存檔、尚未發布。
6. **要讓 LINE 在 GAS／Queue 開始處理前就顯示等待動畫**：進 `line-webhook/`，執行 `npx wrangler secret put LINE_CHANNEL_ACCESS_TOKEN`，在互動提示中貼 Messaging API **同一個 Channel 的 long-lived access token**，不要把權杖寫進檔案或命令參數。接著執行 `npx wrangler deploy` 更新現有 Worker。`/healthz` 應回 `loadingConfigured:true`。原 `LINE_CHANNEL_SECRET`、`GAS_WEBAPP_URL`、Queue 與 Webhook URL 均不必重建；若尚未架設，先照[Cloudflare 免費版逐步部署](../0927-line/免費方案-Cloudflare部署.md)。這是選填的提早動畫功能；不設定時 GAS 接手後仍會顯示動畫。

GitHub 推送會觸發 `public-site-pages` Actions，用原版檔案重新組裝 Pages。Actions 成功後用一般瀏覽器與無痕視窗各開 <https://lee200202.github.io/Stock/>；若頁面可見但資料讀不到，去看 Pages 的 `SITE_API_URL`、`site-api` Worker 與 GAS `/exec` 的存取，不要把 Pages 200 當成後端通過。

## A-2. 在後台確認真正的四段流程

1. 打開 GitHub Pages 網站 → 後台登入 → **今日與投稿**。頂端四張整色卡分別表示 GAS 五分鐘排程、取稿原文、Pipeline 發布、每日郵件。灰色是休市或尚未到時，黃色是等待或待核，紅色需要查原因。**排程心跳只證明觸發器起來，不證明工作完成。**
2. 今天若有影片：11:05 後看「自動取稿」是否變成原文已落地；點 **取稿即時日誌** 查看 `transcript-gemini`；再點 **Pipeline 即時日誌** 查看 `daily-transcript-pipeline`。Pipeline 卡片要等影片處理狀態完成且有當日推播列才變綠。
3. 中午出稿後看「每日郵件」與下方「郵件投遞」帳本，確認至少一位收件者被郵件服務接受；這只證明 MailApp 已接受，不等於收件者已讀。若今日沒有影片，卡片應寫不寄每日總覽。
4. 同頁「今日會員簡訊寫入」是後台專用表格，只列來源為 `CMONEY-` 且確實寫入「操作紀錄／會員持股」的列；待解析原文不會裝成買賣。來源已有文章、表格仍空時，到 **會員簡訊** 分頁查解析工單與派送。
5. **自動化監控**分頁的全色狀態卡提供觸發器、採樣、額度與錯誤詳情；紅色錯誤要看時間軸及 Apps Script **執行項目**。同一包 `apiAdminTodayStatus` 供頂端流程與今日表格，沒有額外整張讀表。

## B. 關掉 LINE 官方帳號的重複回應

1. 開 [LINE Developers Console](https://developers.line.biz/console/) → 選同一個 **Messaging API Channel** → **Messaging API** 分頁。
2. 找 **Auto-reply messages** 旁的 **Edit**，會開 LINE Official Account Manager；在回應設定把自動回應設為 **Disabled／關閉**。同頁若 **Chat** 開啟且設定了自動回應，亦須檢查它是否在送出那句「無法個別回覆」。
3. 回 Developers，點 **Greeting messages → Edit**，把內建歡迎訊息設為 **Disabled／關閉**。`Line.gs` 的 follow 事件會送自己的歡迎卡。保留 **Use webhook** 開啟及原本的 `/callback` URL。
4. 用第二個 LINE 帳號傳「你好」「華成代號歷年有否提過買賣」「1+1」。每句只應看到一則 Bot 的回覆；處理中可能出現官方等待動畫，正式答覆來後消失。等待動畫不是一則「努力加載中」文字訊息；若內建自動回覆不關，改字會讓它和 Bot 答案一起出現。[LINE 官方回應設定](https://developers.line.biz/en/docs/messaging-api/building-bot/)、[等待動畫](https://developers.line.biz/en/docs/messaging-api/use-loading-indicator/)

## C. 安全驗收推送，不要直接群發

1. 在網站後台 **LINE → 設定**，先把推送模式改成 **只送測試帳號**並儲存。現有 channel token 與 secret 不須重貼。
2. 在後台按 **產生綁定碼**，用自己的 LINE 對官方帳號輸入「綁定 六位數」。確認測試帳號出現在後台；驗證碼十分鐘有效。
3. 在該 LINE 帳號輸入「訂閱每日總覽」，再輸入「我要啟用盤中通知」；後台須看到兩者分別開啟。輸入「管理訂閱」看狀態。公開加入好友卡與圖文選單仍只放每日總覽。
4. 後台先按 **驗證卡片格式**（不寄訊息），再按 **送一則每日總覽測試**及 **送一則盤中通知測試**（兩者會計入 LINE 月額度）。手機實收後看 **LINE 待送訊息／寄送帳本**；不要只看「已接受」就推定用戶已讀。
5. 輸入「關閉盤中通知」後再看管理訂閱：盤中應關，每日仍開。舊訂閱清單中只有 `盤中通知=開啟`、沒有新的 `:sms-keyword` 同意版本者**不會被自動寄送**；本人重新輸入啟用指令即可。
6. 測試通過後，才把後台推送模式設為 **正式推送**。如果尚未決定是否對外開放 LINE，網站「顯示加入好友」可繼續關閉。秘密指令不等於法規豁免；如要對外提供投資訊息，另請確認內容與發送方式符合適用規範。

## D. 當日行情與權限驗收

* 交易日 09:00–13:40，在 Apps Script 編輯器執行 `marketSnapshotJob()` 一次，再執行 `marketSnapshotStatus()`（只讀狀態）。`index.quoteAt` 必須是**當天**；若空白，表示 Yahoo 尚無當日時間戳，網站應顯示「未取得」而非數日前的即時價。已有 `everyFiveMinJob` 時，後續由它每五分鐘取樣；不要再建第二個五分鐘 trigger。非交易日或盤後手動執行不會補造當日線。
* 網站市場總覽按 **更新資料**，看加權指數、台指期各自的**資料時間**；舊日期只能以歷史／未取得呈現。LINE「市場總覽」是讀網站最近快取，不能比來源更即時。
* 一般瀏覽器若直接打 GAS `/exec` 出現 Google Drive「找不到檔案」，先用公開的 [GitHub Pages 入口](https://lee200202.github.io/Stock/)；這不需要清掉瀏覽器全部 Cookie。若 Pages 也顯示資料錯誤，核對原 GAS 部署的「誰可以存取」、`?action=ping`、`site-api` 健康狀態。無痕可開只能證明瀏覽器身分狀態可能有差，不能單憑它認定 GAS 原因。
