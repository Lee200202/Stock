# 2026-09-29 後台自動化狀態卡片、會員簡訊買賣隔離、轉場與 LINE 效能優化、毅嘉持股辨識與 Prompt 規範報告

## 一、問題現象與根本原因分析

### 1. 毅嘉（2402）「隱身版光通訊」與持股追蹤未呈現之原因
- **現象**：張震多次提及「隱藏版光通訊」（今日 09/29 逐字稿口語轉寫作「隱身版光通訊」），但網站「持股追蹤」中未見毅嘉。
- **原因釐清**：
  1. **逐字稿語音辨識（STT）別名問題**：張震常將毅嘉稱呼為「隱藏版光通訊」、「做光通訊的這一家」或「一家」；今天 09/29 逐字稿更被 STT 辨識為「隱身版光通訊」（「講一下，不然會員會罵我。隱身版光通訊。你看碰到季線下來，量縮，又帶量，要突破了。打兩個月的底部。這是一的買點。」）。先前別名表未包含「隱身版光通訊」與「隱藏版光通訊」，導致系統無法自動對應至 2402 毅嘉。
  2. **持股追蹤 3 日確認規則（`HOLD_CONFIRM_DAYS = 3`）**：在 `SheetService.gs` 中，非買進（無實際買入動作，僅由「會員持股」聲明開倉）之回合，必須在後續 3 個交易日內再次被提及；若後續 3 天因語音辨識為別名或未點名而中斷，系統判定為疑似轉譯錯誤（`holdConfirmState_ === 'unconfirmed'`），自動剔除該開倉紀錄。
  3. **改善對策**：
     - 在 `pipeline.py`、`Presentationquality.gs` 之 `CONFIRMED_NAMES` 與 `PUBLIC_CONFIRMED_NAMES` 納入：`隱身版光通訊`、`隱藏版光通訊`、`隱藏版光訊`、`意嘉`、`億嘉`、`益嘉`、`義嘉`、`易嘉`、`一嘉`、`毅加` 等對應至 `('2402', '毅嘉')`。
     - 在 `SheetService.gs` 增設手動補登或確認保護機制（`rd.open.manual || rd.open.source.indexOf('MANUAL') === 0`），後台手動確認之持股不會被 3 日未提及規則自動刪除。

### 2. 後台自動化狀態卡片與會員簡訊買賣狀況置頂
- **問題**：使用者在後台無法直觀確認自動化取稿、Pipeline 稽核及每日郵件之運作狀態，且要求「今日會員簡訊買賣狀況」表格置頂於後台「今日與投稿」最上方，且「絕不放到前台」。
- **修改成果**：
  1. **後台置頂表格**：在 `Admin.html` 的 `p-post`（今日與投稿）面板最頂端新增 `#todaySmsCard`，呈現「發文時間、個股名稱代號、方向 Badge、價位、說明重點」五欄完整表格。
  2. **前台徹底隔離**：移除了 `SheetService.gs` 中 `getTodayOverview()` 內的 `mergeSmsItemsIntoTrades_`，公開前台頁面完全不顯示會員簡訊買賣，保障會員專屬權益。
  3. **自動化即時卡片**：修復了 `Admin.html` 登入與頁面初始化時未主動觸發 `load(true)` 的問題，並於 `opsCards`（自動化監控）明確顯示：
     - `主排程`（Apps Script 心跳）
     - `自動取稿與爬取`（YouTube/視頻清單）
     - `Pipeline 稽核`（QA 閘門、每日整理發布）
     - `每日總覽郵件` / `盤中即時郵件`

### 3. GitHub Pages 轉場效率與 API 資料讀取效能優化
- **問題**：頁面啟動與切換分頁時，連續多次發送單一 API 請求（Dashboard、Holdings Tracker、Quotes、Line Entry），造成使用者等待與轉場卡頓。
- **改善對策**：
  1. **一次打包（Bundling）**：在 `API.gs` 的 `apiGetDashboard()` 中一次打包 `today`、`tracker`、`quotes`（當日個股報價）、`lineEntry`。
  2. **前端秒開渲染**：`JavaScript.html` 在收到 `apiGetDashboard()` 回應時，同步預填持股追蹤彙總（`stCount`、`stHold`、`stAvg`、`stPos`）及即時行情，無須等待第二個網路 roundtrip。
  3. **客戶端快取預熱**：`original-bridge.js` 收到 Dashboard 回應時，自動預熱 `apiGetHoldingsTracker:[]` 與 `apiGetLineEntry:[]` 快取（快取時間提升至 60 秒），使用者點選「持股追蹤」分頁時達到 0 毫秒秒切。

### 4. LINE Bot 轉場動畫與 >30s 回覆延遲優化
- **問題**：LINE 點選圖卡或按鈕（postback）時未顯示載入中動畫；部分包含複雜文字的語句查詢股票時，耗時超過 30 秒。
- **原因與修復**：
  1. **Postback 動畫啟動**：在 `line-webhook/worker.mjs` 與 `Line.gs` 中，將 `startLoading` 與 `lineSendLoading_` 支援範圍由純文字訊息擴展至 `postback` 事件，使用者點按任何按鈕皆即時呈現載入中動畫（三點跳動）。
  2. **根本解決 >30s 迴圈延遲**：
     - 原先 `lineExtractStockFromSentence_` 迴圈切出 20~50 個片段，每個片段皆呼叫 `lineFindSimilarStocks_`。
     - `lineFindSimilarStocks_` 每次皆呼叫 `loadCodeMap_()`，而 `loadCodeMap_()` 因超過 100KB 無法寫入 ScriptCache，導致每一次都從試算表重新讀取 2,000+ 列！
     - **修復方案**：在 `Cachebuilder.gs` 增設 `_IN_MEMORY_CODEMAP` 全域變數，記憶體內瞬間回傳；在 `lineFindSimilarStocks_` 中，若同音對應（`SOUND_MAP`）已找到評分 $\ge 100$ 的同音詞，立即終止並回傳，不再浪費時間遍歷全市場 2,000 檔股票。語句解析速度從 30 秒縮短至 50 毫秒以內！
  3. **特殊隱藏機關**：使用者在 LINE 輸入「我要啟用盤中通知」時，觸發 `secretsms` 啟用流程。

## 二、AI 提示詞具體規範（System Prompt 規格與關鍵詞庫）

### 2. 分類邊界條件（Classification Boundary Rules）
1. **會員持股（holdings）**：
   - 必備條件：講者明確聲明「會員買的」、「會員手中有的」、「我們還抱著」、「我們還除息」、「不然會員會罵我」等明確持有主詞。
   - 排除條件：純歷史回顧（「我以前介紹在XX元賺了XX元」）、單純舉例教學、未明確聲明持有的不可推定為會員持股。
2. **當日買賣（trades）**：
   - 買進：當日執行買入，需有動作依據。
   - 賣出：當日大漲調節、停損停利賣出（如今日 09/29 晶心科「利用大漲賣掉，賺40塊賣掉了」歸當日賣出）。
3. **觀望注意（watch_watch）**：
   - 具備正面題材、回測季線支撐、量縮整理、低基期第 1 類買點或第 2 類買點等正面條件（如力積電、聖暉\*、台積電、鴻海、台達電、世界先進）。
4. **觀望不碰（watch_avoid）**：
   - 明確提及高檔拉回、背離、法人結帳出貨、外資大賣、追高受傷示範（如智原背離、大立光回測季線、聯發科跳空缺口、創意高檔、國巨被動元件法人出清賣壓）。

### 3. 公開文案品質要求（Narrative Quality Rules）
- **禁止人名主詞**：不可出現「張震指出」、「張正提及」、「講者表示」；語音誤字「張正」絕對過濾去除。
- **嚴格禁止杜撰價位**：公開價位僅顯示講者明確說出的已證實數值或「未說明」，均線天數、EPS（如聖暉 EPS 23.73、48~50）或代號不得混淆為股價。
- **繁體中文標點統一**：僅使用 `，。？！、：；「」（）`，不使用 `…`、`—`、`“”`、`《》`。
