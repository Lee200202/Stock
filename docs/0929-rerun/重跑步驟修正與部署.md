# 後台「從此步驟重跑」修正與部署（2026/09/29）

## 這次的根因

正式 `/exec?action=ping` 回的是有效 JSON，長約 4,416 字。舊版 GitHub 程式先取前 4,000 字才解析，所以把截斷的 JSON 誤判為「HTTP 200 網頁」，重試三次也一樣。`script.googleusercontent.com/macros/echo` 是 Apps Script 正常的回應轉址；這次不需更換 `APPS_SCRIPT_URL` 或 `ADMIN_KEY`。

同一條鏈的「全面重整」每棒也只解析前 800 字。修正後，ping、一般刷新、全面重整及進度查詢都解析完整回應，只有錯誤日誌仍截短顯示。全面重整若下游回報失敗，不再印成「全面重整完成」；讀不到回應會先查保存的進度，多次沒有進展才讓 GitHub Action 明確顯示失敗。

## 兩個重跑入口的檢查結果

| 後台位置 | 執行路徑 | 已確認／修正 |
|---|---|---|
| 維護工具 → 只刷新畫面 → 從此步驟重跑 | `apiAdminStartRefreshFrom` → GitHub `refresh_from` → Python `maybe_refresh_site` → GAS `refresh` | 選單按 GAS 的 `REFRESH_ORDER_` 排列；`tracker` 是第 8 項。無效索引現在拒絕派工，無效步驟代號也停止，不再默默從第一步重算；已在執行的刷新須先查看或取消，不能同時派另一輪。每個 GAS 回應完整解析。|
| 維護工具 → 全面重整 → 從此步驟重跑 | `apiAdminRetryFullFixStep` → GitHub `full_fix` → Python `drive_full_fix` → GAS `fullfix` | 前台十項與後端 `FULLFIX_STEPS` 一致；第 8 項是「重算追蹤」。後端拒絕無效索引與執行中的重複重跑；修正 ping 4,000 字及單棒 800 字截斷，失敗不再假報完成。|

全面重整的「從此步驟重跑」會把**該步游標歸零**，再依序執行後續步驟。「從中斷處續跑」則保留該步游標；僅因本次 ping 誤判停住時，應選後者。一般刷新與全面重整使用不同進度；兩者都由 GitHub 派工，Apps Script 仍保存實際步驟及游標。

## 部署順序

1. GitHub `main` 已包含 `pipeline/pipeline.py` 修正。確認新派的 `daily.yml` 執行頁 **head SHA 是最新 commit**；舊執行不會在中途換成新程式。
2. 若使用 GitHub Pages 後台，等 `public-site-pages` 於最新 commit 部署成功，重新整理後台。原 GAS 後台仍須下一步更新。Pages 與 GAS 後台都從同一份 `Admin.html` 原檔生成。
3. 在既有 Apps Script 專案內，將 GitHub `public-site/gas-source/` 下列四檔**整檔替換**後儲存：`Adminservice.gs`、`Admin.html`、`Config.gs`、`Setup.gs`。本機原檔 `C:\Users\user\Downloads\zhangzhen-stock-site-updated\apps-script\` 已同步相同內容。其他 GAS 檔不必因這次修正重貼。
4. 在 Apps Script 編輯器執行 `checkProjectFiles()`，確認沒有缺檔或版本不一致；本版 build 為 `2026-09-29-rerun-guards-v80`。不要執行 `installTriggers()`，也不要重設日 K 游標。
5. 右上角 **部署 → 管理部署作業 → 找現有網頁應用程式 → 鉛筆編輯 → 版本選「新版本」→ 部署**。沿用現有部署 ID、執行身分與存取設定，不另建新網址。
6. 用正式 `/exec?action=ping` 驗收：HTTP 200、`ok:true`、`build` 為 v80，且 `features` 有 `full-fix`、`refresh-step`。這個端點只讀，不重算、不寄信。
7. 在後台 **維護工具 → 全面重整 → 查看進度** 先看現況。若是「已取消／失敗／暫停」，按 **從中斷處續跑**；若仍顯示「處理中」但對應 GitHub Action 已結束且不再前進，先按 **取消執行**，再按 **從中斷處續跑**。本次不必再選「第 8 步從此步驟重跑」，否則會重新計算該步。
8. 新執行的 Actions 日誌應一次取得 `build=2026-09-29-rerun-guards-v80`，不再出現「ping 收到 HTTP 200 網頁」。後台進度要從「重算追蹤」推進到「重寫郵件」與「完成」。若下游真正出錯，Action 會顯示失敗及原因，已完成的游標仍保留。

本次沒有部署 Apps Script；第 3–7 步需在正式專案完成。沒有跑真實模型，也沒有以寫入正式表格來測試重跑。
