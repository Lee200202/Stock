## 三、其他回報的問題與改法

1. **管理者收到「輪詢漏抓」信**：補抓（`cmAutoReconcileToday_`）照舊自動補存、派解析、60 分鐘內補寄即時通知（Email 與 LINE），但不再寄信給管理者，紀錄只留在系統狀態。輪詢本身改成存檔成功才記看過，失敗下一分鐘自動重試。
2. **信尾「本站前台與退訂頁面已移至 GitHub Pages…」**：整段拿掉。
3. **退訂頁「連線失敗（method-not-allowed）」**：線上網站 API（Cloudflare Worker `zhangzhen-site-api`）是 9/28 的舊版，白名單沒有 `apiUnsubscribeConfirm`（倉庫版本本來就有）。重新部署 Worker 後即可退訂。退訂頁的錯誤也改成讀者看得懂的句子，技術代碼放在括號裡。
4. **網站「網站資料暫時無法載入」**：實測後端偶爾回 404（18 秒）或非 JSON（48 秒），多數請求正常。改法：
   - Worker：可重送的方法最多試三次；HTML 錯誤頁也算暫時錯誤；唯讀資料留一份最近結果（新鮮期內直接回、後端失敗時回最多 6 小時內的舊資料，回應標 `X-Cache: stale`）。寄信類方法不重送 404，避免重複寄。
   - 瀏覽器端（`original-bridge.js`）：唯讀請求失敗再試兩次，最後用這台瀏覽器 12 小時內上次成功的資料，畫面上「更新於」照資料本身的時間顯示。
   - 首頁總覽：失敗先安靜重試兩次（5、15 秒後），都失敗才顯示提示；Pages 版提示改為「伺服器暫時沒有回應，已自動重試三次…不需要登入任何帳號」，Google 帳號的排除指引只在 Apps Script 網址顯示。
5. **LINE 沒收到盤中通知與每日整理**：
   - 盤中通知只推給用文字指令「開啟盤中通知」確認過的好友（v78 規則），但管理卡片只看開關，舊的按鈕設定顯示「已開啟」卻從來不會收到。v87 卡片如實顯示「未生效」並附「確認開啟盤中通知」按鈕，也寫出推送暫停、只送測試帳號、帳號屬於其他頻道等原因。在 LINE 輸入「通知狀態」或「為什麼沒收到」就看得到。
   - 盤中通知沒有收件人時留一筆 `skipped` 推送紀錄；每日／盤中收件人為零時，推送紀錄與系統狀態寫明各類人數（不列 ID）。
   - 後台 LINE 分頁新增「為什麼沒收到」按鈕（`apiAdminLineDiagnose`）；編輯器可執行 `diagnoseLineDelivery()`。
   - 今天的 LINE 每日總覽與 Email 一樣被品質關卡擋下；部署後隨自動放行一起送出。

## 四、部署步驟（依序）

### 1. GitHub（已推送 main）

推送後 `public-site-pages` 工作流程會自動：比對 API 白名單 → 實測網站 API → 以 `public-site/gas-source` 組裝 → 發布 GitHub Pages。前台新版與舊後端相容（新方法只有後台的「為什麼沒收到」，在 Apps Script 更新前按了會回「方法不存在」）。

### 2. Cloudflare 網站 API（修好退訂的關鍵）

```bash
cd site-api
npx wrangler deploy
```

部署後檢查 `https://zhangzhen-site-api.rainforecast2026-6fb.workers.dev/healthz` 回 `"build":"site-api-v87"`。`SITE_BRIDGE_TOKEN` 是既有 Secret，不必重設。

### 3. Apps Script（需要你在編輯器操作）

先匯出目前專案備份，再把 `public-site/gas-source/` 下列 14 個檔的完整內容貼到同名檔：

`Admin.html`、`Adminservice.gs`、`Changelog.html`、`Cmoney.gs`、`Config.gs`、`Index.html`、`JavaScript.html`、`Line.gs`、`MailService.gs`、`Quoteservice.gs`、`Setup.gs`、`SiteBridge.gs`、`Stylesheet.html`、`Unsubscribed.html`

1. 全部儲存後執行 `checkProjectFiles()`：應顯示 `2026-09-30-delivery-fix-v87`，沒有問題項目。
2. 「部署 → 管理部署作業 → 編輯 → 版本：新版本 → 部署」，沿用原網址。
3. 開 `…/exec?action=ping`，`build` 應為 `2026-09-30-delivery-fix-v87`，`features` 第一項 `delivery-fix-v87`。
4. 不用重裝觸發器。另外執行一次 `installMarketDataJobs()`（補 19:15 歷史分 K 排程，既有提醒）。

### 4. 部署後驗證

1. 後台「今日與投稿」→ 今日狀態「每日推播」：沒寄時會寫出原因與品質關卡狀態；今天應在下一次五分鐘排程後變成已寄送，系統狀態多一列「推播放行」。
2. 後台 LINE 分頁按「為什麼沒收到」：看每日與盤中各有幾位會收到、收不到的原因。
3. 在 LINE 輸入「通知狀態」：確認自己的每日總覽「已開啟」；盤中通知若顯示「未生效」，按「確認開啟盤中通知」。
4. 從任一封信按「取消訂閱」→ 確認頁按鈕不再出現 method-not-allowed（可先用測試信箱）。
5. 監控頁「觸發器今日累計」：明天盤中的 `refreshQuoteCacheJob` 應明顯下降。
