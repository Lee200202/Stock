## 2. 沒講名字的段落：用昨天收盤價認股（管理者 2026/10/01）

原話：「我說這一支股票只要 1745 突破……昨天收盤收多少？1770……啊現在 1800。」
管理者：去持股追蹤看昨天收盤價，就知道是嘉澤（3533）；對不到就不計入；被提示詞辨識為這一類的要進二次稽核。

流程（`identify_unnamed_stocks`，排在所有主詞與語氣核對之後、寫入之前）：

1. **找段落**（模型，`UNNAMED_SYSTEM`）：只在原文有「收盤＋數字」時才問。模型照抄原句、標出線索種類（昨收、現價、關卡、買進價、漲跌），不准猜公司。程式核對：引用是原文、數字在那一句裡、引用沒有點到今天已收錄的公司、至少有一個明講的昨天收盤價。
2. **對行情**（程式，`market_snapshot`＋`match_unnamed_by_price`）：追蹤中每一檔前一個交易日的實際收盤（日K快取；那一天沒有日K時用即時快取當天的昨收）。昨收一模一樣、而且只有一檔才算認出來；原話另有「現在幾塊」時必須落在那一檔當天高低（各放寬 1.5%）之間。對不到或同價不只一檔 → 不計入。
3. **二次稽核**（模型，`UNNAMED_AUDIT_SYSTEM`）：把候選公司、實際收盤與原話一起送去，問歸給這家公司有沒有矛盾；`accept=true` 才往下。說明逐句核對引用與數字，沒過的句子不用，全沒過就不收。
4. **分類限制**：只會是觀望注意／觀望不碰；持股追蹤裡正持有、而且原話有買進或抱著的說法才列會員持股（續抱）。不會產生買入或賣出，不會替沒持有的股票開回合。同一檔今天已收錄就不重複。
5. 任何一步失敗（配額、時間、模型回應異常）都只是不收錄，判定歷程留「無名段落」一筆，不擋發布。

2026/10/01 實測資料：嘉澤 9/30 收 1770、10/01 高低 1760～1865，是追蹤名單裡唯一昨收 1770 的一檔，也在持有中（8/12 起）。

## 3. 反向檢查：說明裡掛錯的數字

`strip_foreign_price_claims` 多一條：說明裡的數字（價位、關卡、張數；月份與分K參數不算）在原文每一次出現，往前、往後最近的本檔名稱都超過 500 字，而且中間都點名過今天有進表格的別檔 → 整句刪掉。
當天實測：正確的數字離本檔名稱最遠 241 字（聖暉 924），掛錯的最近 762 字（世芯 1745）。同一檔講很久沒再報名字、先講內容後報名字、會員簡訊帶來的價位都不動。
這一步現在在合併補問之前先做一次，短掉的說明才輪得到補問；補問之後照原順序再過一次。

## 4. 下游忙碌不再算失敗

`maybe_refresh_site` 收到「Lock timeout／鎖定逾時／刷新正在更新進度」時：同一步等 20、40、60、60 秒各重試一次（時間預算不夠就不等）；仍然忙碌就回報暫時性，`finish_transcript_refresh` 保存檢查點、工單改「等待續跑」，由既有排程自動接著做。真正的錯誤（例外、回應格式錯）照舊停下來。
