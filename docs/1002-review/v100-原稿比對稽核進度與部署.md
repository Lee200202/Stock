## 為什麼一直卡在潤飾

原稿共有 13,600 字；三個獨立時間標題清掉後為 13,540 字。舊程式以清理後指紋比對試算表仍含標題的原稿，兩者必然不同，因此每次潤飾完成都誤判「原稿已更新」，等待 180 秒後重新做相同工作。這不是 VOD 還沒轉好。

- 完整原稿 SHA256：`824bc5d9b87358c94234dd00a7db4796cc8a056d3c0404ad1073652f6e4aaa33`。
- 清理後 SHA256：`b918ea0b3d9b368773e6adcf6c4852f84559c42662af56c01afd9c5c9a2bf1fc`。

現在讀取時保存完整原稿與影片 ID，寫回前重新核對同一筆。只有真正改稿或改為手動保留才停止舊結果。重新貼相同內容（忽略空白及獨立聽打標題）會保留既有修飾稿；真實內容改變才清掉修飾稿並讀新稿。人工說明保存與手動工單也採完整原稿指紋，避免時間標題再次造成保護失效。

新聽打不再額外寫入 `0:00:00–0:30:00` 標題。已存在的獨立標題在判讀與顯示時清理；不刪除正常句子中的時間或數字。

## 進度與取消

潤飾每三十秒回報實際片段完成數及心跳；總進度仍表示工作步驟，不用假的逐秒百分比。只有一個片段時也回報等待心跳。畫面等待動畫遵守「減少動態效果」偏好。

「取消執行」以今天正在執行的取稿或每日稽核 GitHub run ID 啟用；後端再次核對流程、日期及執行名稱，不把會員簡訊解析或另一張手動工單取消。取消這一輪保留已落地資料，不停用後續排程。真正要停止當日取稿仍用當日暫停功能。
