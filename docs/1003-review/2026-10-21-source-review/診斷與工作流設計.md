## 3. 反省：第一次執行為什麼會有這麼大的幻覺

1. **一次問太多軸**：擷取把公司身分、主體、部位、立場、分類合在一次判讀，而且不知道持股紀錄。「不要賣聯電／鴻海」這種對觀眾的建議被讀成講者持有；明講的「我只有力積電」「開始講我的股票…台積電」反而沒列持股。
2. **聽錯的名字讓範圍切錯**：同一句「台郡跌，富橋跌，台玻跌」在不同輪被切成不同段落，三檔拿到不同的票。
3. **後段修正靠多數票，但「不能用的答案」吃掉票數**：模型其實引了正確的前置結論，卻因引句不在點名那句之後被判成不能用。
4. **說明寫作沿用前文**：模型與補空程序都可能把前一檔或通用句接到本股。

所以要改的是結構（部位交給紀錄、立場交給多票、範圍與並列有明確規則、說明只用本股句），不是為今天的股票加特例。

## 4. 分類界線（本次確認後的定義）

| 判斷 | 歸類 | 不能這樣歸 |
|---|---|---|
| 「我沒有X」＋X的看多理由 | 觀望注意（部位軸改不持有） | 不公開 |
| 「X不要再賣／不要殺低／會漲回來」 | 觀望注意（續抱看多） | 觀望不碰、會員持股（沒有部位依據時） |
| 結論在股名之前並用「這兩支／這些」指向後名 | 結論屬於後面每一檔 | 只算給最後一檔、或判成沒有看法 |
| 同一述語並列多檔（「A跌，B跌，C跌…不要追」） | 整組同一結論（教學例子≈觀望不碰） | 一檔公開、其他不公開 |
| 已出場、今天重申買點 | 觀望注意 | 回顧 |
| 「我現在要等低檔量，沒看到量不會買」 | 觀望不碰（條件未到） | 觀望注意 |
| 往日減碼＋現在剩餘部位 | 會員持股，說明寫成回顧 | 今日賣出、或說明宣告今天減碼 |
| 原稿只剩不能辨認的字（「序」） | 不補列 | 憑紀錄硬配到某檔 |
| 當日會員通知「新進會員於X以下買進」、已有部位 | 當日買入（產品契約），不另開回合 | 由逐字稿「我買在這邊」推成今日成交 |

## 5. 工作流（穩定性設計）

1. **來源閘**：同日多份原稿時比對字數、標點、可辨識股名；採用的那份明顯較差要警示（已上線，唯讀）。
2. **身分**：只用正式名稱、管理者確認的別名與同音規則；新增別名先問管理者。
3. **部位軸**：持有與否以紀錄、會員通知、明講持有為準；擷取的「持股」只當候選，否認部位只改這一軸。
4. **立場軸**：有疑點的送三票問卷；不能用的答案補問到五輪（一天多 0～2 個請求，15RPM／500 日內）；記錄每一份不能用的原因。
5. **群組一致**：並列同述語、前置共同結論在裁決後整組檢查，結論不一致時看合併的票。
6. **說明**：只用本股範圍內的原句；不得自行宣告賣出、減碼、成本；補空句必須點名本股或帶立場。
7. **跨日診斷**：同一檔前後日分類翻轉、紀錄持有卻沒列、名單同句卻分類不同，列入當日稽核待核清單，不自動改正式資料。
8. **當日修正**：模型結果不穩時，不重跑碰運氣；用來源核對計畫（引句逐字、指紋綁定、模型 0、寄送 0）修正當日，規則改進另以重播與保留日驗證。
