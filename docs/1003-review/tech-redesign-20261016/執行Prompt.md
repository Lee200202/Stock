## 3. 閱讀架構：20 個完整短章

以 `chapter-map.json` 為分配起點。章名控制 6–10 個中文字；章內主標可用具體問句。順序如下。

### 01 網站緣起與查詢

- 問題：「一筆操作隔了幾集，還找得到嗎？」
- 主圖：本站每日卡、持股回合、個股時間軸三張真實畫面局部，依重要性一大兩小，不是三張文字框。
- 三個痛點改成圖片卡：找當天看法、追同一檔回合、核對分類依據。
- 卡面每張一個問題、一句回答；來源、範圍與例外直接列於下方。
- 不展示過時累計數字當即時統計；靜態數據標日期，動態資料標讀取狀態。
- 增加「一筆紀錄五站全景」入口：直播／紀錄、原稿／指紋、判讀／核對、寫入、網站／通知五站的圖與一句職責**同時可見**；滑桿僅能作額外播放控制，不能是看見其餘四站的唯一方法。桌面採波形或折線全景，手機直列五卡，不強行橫向滑動。
- 規模統計若保留天數、紀錄數、代號數、即時紀錄數、文章數與人工補登數，做成一張統計圖區，分母與快照日期共用。各數字須來自同一份快照，不把不同日期湊成「今日規模」。

### 02 資料來源與流向

- 主圖：左邊兩條來源、中央處理工作區、右邊網站與通知輸出；資料庫位於中央下方。
- 點任一物件時，只突出它的上游與下游，旁邊顯示用途及證據類型。
- 保留現行資料圖的關聯功能與所有節點資訊，不再重做一份六步流程文字。
- 動畫只沿實際資料連線；資料庫不是所有請求必經的裝飾節點。
- 依現況整理六個**概念分群**：來源、辨識與規則、操作紀錄、行情、衍生結果、網站與寄送。後台工單、系統狀態、使用統計及封存索引另列維護區；概念分群不是新增資料表或宣稱資料庫強制外鍵。
- 將原先藏在文字版的八類關聯直接呈現：影片ID、即時／人工紀錄識別、股票代號、持股回合、每日績效、文章與收件紀錄、原稿指紋與進度、GAS／Actions 分工。各卡含「鍵值→來源→去向」的微縮圖。表數、鍵值字串、保存位置先查原碼，不硬寫 30+ 分頁。
- 已存在的關聯圖繼續負責點選高亮；八卡負責解釋資料語意，兩者不能各再複製一排相同選擇按鈕。

### 03 單日處理時間線

- 主圖：影片與操作紀錄雙泳道時間線，加一個後端工作托盤。
- 沿用現行 9/23 等有來源的案例；真實日期與示意播放時間分開標。
- 播放時輸入卡抵達工作區、完成狀態逐項變化，最後顯示網站可讀與寄送關卡。
- 文章完成、資料寫入與服務接受分別標示；不能把服務接受畫成使用者已讀。

### 04 資料規模與首屏

- 把「天數／原始列／股票數／回傳量」畫成逐層收斂切片，不只是四張數字卡。
- 旁邊放本站首頁局部截圖，指出首屏實際讀什麼、不讀什麼。
- 一張同尺度橫條圖比較有依據的前後時間，列日期、樣本數、測量端點。
- 核心定義直接可讀；完整量測方法、原始樣本與來源放可點圖卡的說明視窗。
- 不把歷史樣本 54 KB、67 天、1,413 列等寫成永遠即時的本站規模；保留它們但標留存日期。
- 「後端有多少列→前端取得多少位元組」是資料範圍與回傳量比較，不能直接算壓縮比。只有同一資料、同一序列化、壓縮前後 bytes 完整可得，才能宣稱壓縮比例。
- 當天提及數→有公開分類的股票數可做流向圖，但買入與持股可能重疊；先定義以唯一代號、資料列或回合計數，不把有重疊集合畫成總和必等於原數的漏斗。

### 05 快取查詢與更新

- 使用本資料夾原型的空間構圖：手機在左，快取在右上，資料來源在右下，路徑有來回方向。
- 唯一一組情境：**有效快取／背景備份／歷史日期／備份過期**。
- 有效快取：手機→快取→手機；試算表變淡但保留，不進入光點路徑。
- 背景備份：前景回覆與背景刷新是不同工作；不可因半小時沒人訪問就宣稱未命中。
- 歷史日期：明確指定「此日期無有效答案」才回源；不是歷史查詢必定慢。
- 備份過期：回源成功則換新；回源失敗則呈現暫無可用資料，不顯示過期即時價。
- 定義、各資料有效期、背景失敗邊界及來源完整保留；以目前 Worker／GAS 程式查證。
- 命中 0.09 秒、未命中 7.19 秒是 2026/10/07 的歷史樣本，不能宣稱所有頁面快 80 倍。
- 圖內可嵌入手機首頁局部、快取答案卡、試算表格線，但數字與資訊要少量且可讀。不得用公開圖解暴露私人通知成交價，也不把示意行情當現價。
- 「不同資料類型的有效期」「前景快取／背景備份」「定時刷新」是三個不同維度。除非程式證明逐層查詢，不能將 1 分鐘／10 分鐘／1 小時畫成同一請求必經的三層同心環；背景每 5 分鐘是排程頻率，不是另一個 TTL。
- 未命中是正常查詢分支，不是紅色失敗；以資料庫查詢圖示＋「回源整理」呈現。回源成功、回源失敗、備份過期另有結果標籤，不一律打勾或一律報錯。

### 06 模型輸入與切詞

- 原句→token→編號→向量，做一張可對照的放大圖，不用四張只有文字的小卡。
- 點一個 token，同一單位在四區同時高亮；旁邊只顯示這個單位的說明。
- 真實 tokenizer 取得的結果才標真實；人為切詞、編號及向量格必須標示「原理示意」。
- 不宣稱中文字、字數或一個股票名稱固定等於幾個 token。

### 07 模型容量與用量

- 以本站實際設定模型與每日記錄呈現，不拿泛用容量假裝實測。
- 分清單次 context 上限、實際輸入 token、輸出上限、每日請求數與計費；不能相加成一種容量。
- 用巢狀比例圖顯示系統規則、本股證據、工具結果與輸出保留空間。
- Gemini 3.5 Flash Lite 的可用名稱、規格與來源由實作者當日查官方文件及現行設定。無法查證就標未取得，不借其他模型數字冒充。
- 不為畫圖重跑每日模型；優先讀既有去識別 usage metadata。若要補實測，使用唯讀 countTokens 並記錄模型及樣本。
- 現有 10/13 留存樣本可作看板內容：`docs/1003-review/2026-10-13-agent-usage.json` 的 19 筆成功文字回應，輸入合計179,291、文字輸出26,113、thinking6,946；**不含聽打與未留存嘗試，不等於全天總量或帳單**。
- 第一筆擷取為輸入27,205／文字輸出4,934；最大輸入32,325那一筆的文字輸出是5,379；最大文字輸出5,861屬另一筆輸入32,162。不能把兩個最大值畫成同一請求。
- 若官方上限仍核實為1,048,576，27,205占2.59%、32,325占3.08%；5,861／65,536約8.94%。低於容量上限**不等於低於失真門檻或答案有保證**。模型上限是官方規格，使用量是留存證據，兩種來源分開。

### 08 代理推論與工具

- 原稿視窗在左、控制程式居中、模型與工具在右上下；用位置表現權責。
- 六種原有案例各自對應：輸入→推論／核對→工具結果→最終處理。
- 以「今天不准殺低」等已有核對案例說明：模型提出事實題回覆，程式檢查否定語氣與證據，並非見到賣字就算賣出。
- 控制程式（harness）負責參數、工具白名單、重試、保存、驗證及停止條件；模型不能直接寫資料。
- 模型交換是介面與能力契約，不宣稱換 URL 就一定等價；保留目前模型／抓取方式的實際依據。
- 保留原有六種問題的索引，但分入第06至08章，不把六份全文硬塞同一舞台；每題的核心結論不需先點才看見。
- 「能解釋底層」改成職責對照：輸入如何組裝、誰執行工具、誰驗權限、誰保存狀態、誰核對結果。右側列僅安裝套件仍需補上的能力；不寫成對求職者、技能包或使用者的貶抑評語，也不把未查證文章當本站能力證據。
- 模型名稱與抓取方式以現行設定為準；不得加入心得列的 Whisper／Cloud Speech-to-Text 或 Gemini 2.5，除非原碼與日誌證明本站確有使用。

### 09 股名辨識與校字

- 左卡顯示原字，中間候選清單，右側正式名稱／待確認結果。
- 支援相鄰句、代號、讀音與價位線索的既有案例；不得編造新確定對應。
- 明確區分「校正閱讀稿」與「分類證據」，不暗中改原始保存稿。
- 無法唯一確認的結果保留限制；用問號及文字，不只靠黃色。
- 心得誤抄的三個案例必須更正：現行 `Tech.html` 的「出金城→勤誠8210」、「加折→嘉澤3533」、「連帽→未確認，保留原字」。不可複製成鉅祥2476、佳世達2352或聯詠3034，也不因此新增正式別名。
- 可以直接展開已核對案例的成對縮圖，按卡放大原句與核對結果；原始寫法、正式名稱、代號與未定標籤要對得上。

### 10 數字單位與歸屬

- 將一段原文放在像文件的主圖內，點數字顯示單位、主體、時間與是否可公開。
- 代號、價格、EPS、百分比、張數、均線週期用有文字的向量標記區別，不能全部當價位遮掉。
- 千分位、每股／每張及跨股主體既有案例全部保留。
- 不把「沒有來源的數字」補成合理數值；不新增私人通知成交價的公開呈現。

### 11 匿名個股與證據

- 用候選漏斗或放射對照圖，不用三張永遠不變的結果卡。
- 唯一符合、兩檔同價、查無符合三選項直接可見，選後候選數與判定一起改變。
- 價位只是條件之一；日期、產業、部位等依目前流程核對，不以猜測硬配一檔。
- 「唯一」必須同時標候選範圍與資料日期；只查240檔追蹤清單就不能聲稱全市場唯一。沒有可靠全市場行情資料時，不能新增此能力的描述。

### 12 操作主體與分類

- 卡面先顯示「誰／哪一天／已發生或建議」三個核對點，再顯示分類。
- 五種主要分類及不公開的現有定義完整保留。
- 特別畫出**部位狀態**與**今日動作／進場立場**兩軸：部分賣出仍可能有剩餘持股，不能強迫整檔只剩賣出。
- 操作通知優先與逐字稿書面說明分工，以現行流程為準。
- 「今天可以買」是否為操作指令，要依來源與實際規則；公開圖解不可把所有建議都畫成已成交。
- 現在無部位但偏多可列觀望注意；描述行情不自動等於偏多。禁止／等待條件的邊界依已核對例子呈現。
- 「散戶／外資在賣」只能排除把它認成會員賣出；它本身**不能證明會員續抱**。仍需持有紀錄或講者／會員持有證據，否則只呈現「不是會員成交證據」。

### 13 分類裁決與證據

- 主圖是證據投票桌：每票有六個事實題摘要與引句驗證狀態，不做沒有根據的投票箱動畫。
- 分開畫「模型回覆一票」與「有效證據一票」；引句不存在或跨股借句就劃除。
- 1／2／3 票規則若仍符合目前程式才呈現；明確規則與操作通知不被投票反轉。
- 票數不足：維持既定可核對結果或單檔未定，依現行程式說明；不能畫成多數決保證正確。
- 同一原稿指紋的裁決快取、人工裁示及條件改變後重新核對各有卡片。

### 14 多來源操作合併

- 左邊操作紀錄、右邊逐字稿，合併至中央「分類」與「說明」兩個獨立槽。
- 明確案例：先收到賣出操作，影片再提持股；全數賣出不能同時續抱，部分出場保留剩餘回合。
- 不同來源的說明以本股證據整理，不把私人價位公開；圖解通知只用明示虛構示例或已公開可用材料。
- 來源晚到、人工修正保護、已寄郵件快照均保留。
- 不畫成永遠無條件的三層權重金字塔。人工修正的保護依原稿指紋、股票、來源、分類及欄位範圍；條件變更要重新核對。操作分類、文字說明、部位與送信狀態是不同欄位，不以一個權重概括。

### 15 公開說明與核對

- 用可放大的文件對照：原句→核對項→書面成稿；不是把原稿貼進三個框。
- 依現有案例顯示保留技術條件、刪重複、跨公司誤接、分類與說明衝突、數字保留、人工修正保護。
- 核心結果直接可見；每個修改標記有理由。
- 文章更新不能畫成已寄郵件被改寫，更不能暗示觸發重寄。

### 16 原稿版本與續跑

- 每份原稿一張指紋卡；片段、稽核、文章、寄送關卡是不同進度，不做一條假的總完成條。
- 同稿再貼、潤飾中更新、取消單工單、503、JSON 無效、證據缺漏、鎖忙碌等既有案例全部保留。
- 舊稿被新稿取代時，以拒寫路徑標記；已完成片段可沿用的條件直接列出。
- 心跳只代表活躍，不代表成功；文章完成不等於績效完成。

### 17 持股回合與績效

- 主圖用真實日期軸與進出場回合，不把所有價位寫成現價。
- 「播放這個回合」進視野循環，點案例或滑桿暫停，再播恢復；剩餘部位與關閉回合有清楚不同形狀。
- 保留頁面目前算式、人工成本覆寫與稽核限制；先核對後端公式，禁止照舊文硬寫。
- 模擬報酬、實際成交通知與行情取價不能混為一談。
- 依目前 `SheetService.gs`：先算 `m=(H+L)/2`（依程式分幣與四捨五入）；有通過取價日K核對且位於當日區間的明講價時，進場 `min(p_in,m)`、出場 `max(p_out,m)`；無有效明講價則皆為 `m`。人工覆寫依現行規則優先。不能混成「缺值取最低／最高／均價都可以」。
- 這種選較低進場、較高出場的估算可能使報酬偏高，未扣費稅滑價；**不可稱為最保守公式**。歷史9/23案例原本使用何種版本要標歷史口徑，不把當時最低價說成現行通用公式。
- 回合關閉還可能受現行轉觀望或逾期規則影響；不要因心得寫「只在明講賣出才結束」就更改演算法。圖解必須區分實際賣出與規則結束的回合。

### 18 故障恢復與限制

- 原 failure 與 limit 合併但內容不刪：主圖是成功路徑旁的失敗分支與檢查點。
- 暫時性錯誤、不可恢復錯誤、鎖忙碌、單檔隔離、資料不足有不同處理卡。
- 一筆錯誤不擋其他有效股票；但不得把不確定分類公開湊數。
- 尚未提供的能力直接列出，不把規格願景畫成已實作功能。

### 19 常見問題與改進

- 原 open 與 faq 的所有問答、改進方向、來源保留。
- 核心答案直接展開；只有補充工程細節可用 dialog。
- 以已完成／進行中／尚未做的帶文字卡區分，狀態有查證日期。
- 沒有連結目標的卡片不能假裝可點；不把所有靜態文字都加動效。

### 20 作者資訊與聲明

- 保留作者署名、聯絡、第三方來源及風險聲明；不擅自改署名。
- 用靜態向量聯絡卡與來源卡；作者區不用自動播放。
- 結尾提供回章節總覽與上一章，不自動跳回第一章。

## 4. 版面數值與響應式規格

## 5. 圖像資產規格：每章不同，不套同一張圖

- 每章至少一個有資訊意義的主視覺；可互動 SVG、本站截圖、標註示意圖均可。
- 至少 8 種構圖：空間網路、雙泳道時間線、資料切片、查詢分支、文件放大、候選漏斗、證據投票桌、回合日期軸。
- 不以更換 icon 的三矩形圖充當 20 張不同主圖。

## 7. 動畫：路徑正確，比「有動」更重要

### 7.1 播放契約

所有教學動畫由**單一控制器**管理：

```text
可播放 = 技術分頁啟用
       且本章啟用
       且圖解進入視野
       且瀏覽器頁籤可見
       且沒有說明視窗遮住
       且使用者未手動暫停
       且不偏好減少動態
```

- 首次進入視野自動循環；播放完不要自行停止。
- 使用者選情境／拖滑桿／點案例後，結果立即切換並暫停該模組；其他章不受影響。
- 「再播圖解」從當前情境起點重播且繼續循環；不能只播一次。
- 另有暫停／繼續控制，避免超過五秒的自動動畫無法停止。
- 依 reduced-motion 直接顯示結果與靜態方向，不隱藏內容、不自動移動。
- 作者、聲明、普通問答不必為了全站有動畫而亂動。
- 不使用進入畫面前 `opacity:0`，JavaScript 壞掉也不能整章空白。
- 原碼確實有 `.story-main.is-stopped * {animation:none!important}`；問題是廣域凍結與控制器衝突，不代表「手動暫停」本身有錯。重建後用明確狀態暫停 marker、光束與卡片，不能照心得刪光停止機制而讓離屏／背景／減少動態仍全天運轉。

### 7.2 路徑動畫程式範例

完整可執行版本見 `prototype.js`。核心應是先定義合法路徑，再讓 marker 沿 path 移動：

```js
const routeByCase = {
  hit: ['request', 'return'],
  backup: ['request', 'return'],
  history: ['request', 'source', 'store', 'return'],
  expired: ['request', 'source', 'store', 'return']
};
function drawTraveller(svg, marker, caseKey, progress) {
  const ids = routeByCase[caseKey];
  const scaled = Math.min(0.999999, Math.max(0, progress)) * ids.length;
  const path = svg.querySelector('#' + ids[Math.floor(scaled)]);
  const point = path.getPointAtLength(path.getTotalLength() * (scaled % 1));
  marker.setAttribute('transform', `translate(${point.x} ${point.y})`);
}
```

- SVG 在初始化建立一次；播放時不重設 innerHTML、不重新產生文字或按鈕。
- 路徑上的資料球、卡片或封包都有對應來源與目的地；命中時不得進試算表。
- 比較條使用 `transform:scaleX()`，不用 width 動畫。
- 切情境只改狀態與標籤；動畫每幀不更新 aria-live，以免螢幕閱讀器不停朗讀。
- 教學速度可壓縮為 5–8 秒一輪，必須標「動畫速度為閱讀示範」，不當 API 秒數。
- 避免多個 IO 與 setInterval 同時操作同一模組；卸載時 cancelAnimationFrame、disconnect。

## 8. 分章導覽、錨點與無 JavaScript

### 8.1 路由要求

- 技術頁外層仍是既有 `?tab=tech`，保留 `technical` 相容別名。
- 每章一個穩定 id；原有 id、`#toc-1` 至 `#toc-18` 及章內錨點有顯式相容表。
- 舊 tech-agent 拆成三章時，原 `#tech-agent` 進模型輸入；原章內子錨點應對到它實際搬入的新章。
- 不能讓舊動態 TOC 再按照新 DOM 順序覆寫舊 `toc-*` 的意思。
- 點章節要同步 active chapter、網址、目錄、頁數與焦點。
- `history.pushState()` 不會觸發 hashchange；必須自行呼叫 render。另支援 popstate 與 hashchange。
- 瀏覽器上一頁／下一頁需恢復正確章節；本章內錨點不能誤跳另一章或回第一章。
- 關閉分頁再從深連結進入也正確；章節切換不重抓每日資料、不呼叫模型。

### 8.2 漸進增強範例

```js
  ['toc-3', 'tech-loading'], ['toc-4', 'tech-agent'],
  ['toc-5', 'tech-day'], ['toc-6', 'tech-names'],
  ['toc-7', 'tech-subject'], ['toc-8', 'tech-number'],
  ['toc-9', 'tech-unnamed'], ['toc-10', 'tech-transcript-progress'],
  ['toc-11', 'tech-source-priority'], ['toc-12', 'tech-public-notes'],
  ['toc-13', 'tech-hold'], ['toc-14', 'tech-failure'],
  ['toc-15', 'tech-failure'], ['toc-16', 'tech-faq'],
  ['toc-17', 'tech-faq'], ['toc-18', 'tech-author'],
  ['tech-limit', 'tech-failure'], ['tech-open', 'tech-faq']
]);
function resolveChapter(hash) {
  const key = decodeURIComponent(hash.replace(/^#/, ''));
  const alias = legacy.get(key);
  const target = document.getElementById(alias || key);
  return target?.closest('[data-chapter]') || chapters[0];
}
function activate(hash, moveFocus) {
  const next = resolveChapter(hash);
  closeChapterDialogs();
  chapters.forEach(ch => { ch.hidden = ch !== next; });
  updateContentsAndPager(next.id);
  updateAnimationEligibility(next.id);
  if (moveFocus) {
    const heading = next.querySelector('h2');
    heading.focus({preventScroll: true});
    // 若 hash 對應本章子錨點，改捲至該子錨點。
    scrollToResolvedAnchor(hash, next);
  }
}
```

上例的輔助函式是介面規格，實作者必須完成，不得貼上空函式。原型有較小型的完整可跑版本，正式版須接既有 docnav。

先驗證目錄、id 唯一性及內容 manifest，成功後才加 `is-enhanced` 並隱藏非作用中章。初始化出錯則清除所有 hidden，讓內容仍可閱讀；不讓錯誤留下半頁空白。

### 8.3 章末導覽

- 普通文件流中的兩個大橢圓連結：上一章／下一章＋各自章名。
- 桌面各半寬，手機一列一顆；高度至少 72px；不得只放箭頭不知道目標。
- 首章、末章提供章節總覽，不自動循環跳章。
- 回頂按鈕維持**底部中央**，不改右下；為頁尾及 pager 保留至少 100px 安全區，避免遮字。
- 右側目錄沿用既有可點手柄，展開後可直接跳章；增加「05 / 20」及章名，不添加一整排四幕按鈕。
- 新增中央進度「第05／20章」可作目錄入口；與右側手柄打開同一個目錄、共用狀態，不建立兩份不同順序的章節清單。
- 若加入左右方向鍵，只在章末導覽內聚焦且無修飾鍵時處理；不可攔截輸入框、滑桿、tabs、選單、dialog或文字選取中的方向鍵。原生連結、Tab及Enter仍是主要操作方式。
- 為列印與跨章全文查詢提供專門路徑：列印時一次輸出所有章節；章節搜尋可使用本機內容索引定位。不要重新加入預設「一鍵全18章長卷模式」造成原本過載；章數以20章manifest為準。

## 10. 測試矩陣與通過標準

### 10.1 版面

在 1916×857 與 1880 寬版，測大字 l／x；在 1440、1280、1024、768、390、360px 測淺深色。必要時縮放 200%。

每個章節都要檢查：

1. 整頁無水平捲軸，無文字被 overflow hidden 截斷。
2. 卡片、視窗、圖與 pager 不重疊；回頂與提問浮層不遮住當前操作。

4. 選項直接可見，不靠左右拖拉才找到第四項。
5. 大字不把字距撐開，不出現句尾一字配一整行大空白。
6. 章內區塊間距符合設定，沒有固定 min-height 造成空洞。
7. 原版面設定依然有效；不以固定 px 字體讓大字模式失效。

1. 20 章下一章完整走一遍，再反向上一章；目錄任意跳章。
