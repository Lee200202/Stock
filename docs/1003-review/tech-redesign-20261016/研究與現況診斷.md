# 技術說明重設計：現況診斷與 Apple 官網研究

日期：2026/10/16。這輪交付設計研究、執行 Prompt 與局部互動原型，未修改正式網站。管理者後續澄清的研究範圍是 **Apple 官網裡至少 20 個連結**，不是 20 家不同公司；以下以 Apple 22 個頁面為主體。

## 一、結論與修改方向

採「分章閱讀的圖像產品介紹」：完整內容分配到 20 章，每次呈現一章；章內先主視覺，再三個必要重點、可點圖片卡與完整規則，最後是橢圓形上一章／下一章。必要資訊直接呈現，圖卡的對話視窗只承載延伸解說，不能把正文再次全藏起來。

保留原品牌、深淺色、橢圓按鈕、字級／寬度設定、相容錨點與資料真實性。重新設計目前「十八張同型長條 SVG＋克隆情境按鈕＋展開全文」這一層，而不是在舊版上繼續疊補丁。

## 二、正式頁實際查驗

網址：<https://lee200202.github.io/Stock/?tab=tech#tech-loading>。本機檢查提交起點 `b91b941`；正式頁顯示更新時間 `2026/10/16 11:01`，此時間是頁面標示，不是本輪量測的 API 時間。

實際 viewport 1916×857，深色、大字 `data-fs="l"`。內容卡寬 1320px，SVG 約 1278×250px，資料載入主卡高約 430px；章節細節 `open=false`，總共 18 個 `.story-section`。這不是管理者寬版 `data-w="w"` 的已完成測試，執行 AI 仍要另測該設定。

| 問題 | 程式及畫面證據 | 本輪判斷 | 重設計要求 |
|---|---|---|---|
| 章節／卡片內距太緊 | `StoryDesign.html` 簡版將 section padding 縮為 14px、main 縮為 10px，手機 main 14px | 多層縮減規則累積，不只是字體問題 | 單章殼、主舞台及補充卡使用獨立間距 token；不繼續全域加 padding |
| 寬螢幕沒有真正使用寬度 | 實際 1916px 時主卡仍 1320px | 舊章節容器與使用者版面設定需一起查 | 新殼尊重寬版 1700／加寬 2000 及可用 viewport，不只放大 SVG |
| 情境呈現重複 | `.story-stamp` 顯示目前選項；`.story-choices` 又克隆原 `[data-load-case]`；原控制仍存在 details | 是兩套控制與重複標題，不應再加第三套 | 每模組只保留一組控制；移除情境 stamp、更多情境及重複原控制 |
| 圓點不像流程動畫 | `setInterval` 每 1600ms 重畫 SVG，`renderPlayhead` 依形狀列表跳點 | 命中情境也能把點放到試算表，與說明矛盾 | 路徑驅動的 request/response 分支，只更新 marker transform，不每輪重建 SVG |
| 圖像只有三條長框 | 手機／快取／試算表用同尺寸橫條，24px icon 距置中文字很遠 | 看不出裝置、暫存、資料表的不同角色 | 裝置線框、快取層、表格格線、資料封包與曲線路徑；桌面非對稱，手機另構圖 |
| 內容完整模式一次過多 | 簡版藏全文，完整模式同時展開 18 章 | 兩個極端都造成閱讀成本 | 20 章路由，單章完整，避免全站一起展開 |
| 真圖被藏住 | `Tech.html` 已有 `.load-charts`、定義與 `.load-evidence`，但被搬進 details；簡版還隱藏 evidence | 不是完全沒有圖，而是入口把有用圖放在次要層 | 必要比較圖與本站截圖直接放正文 |
| 狀態文字不精準 | 可見「命中快取。。」；主圖回覆被通用 headline 拼接覆寫 | 同一結果多處生成，容易重複與失真 | 情境資料一個來源，結論只產生一次 |

原碼重點位置：`StoryDesign.html` 約 11–60（間距／簡版）、176–204（包裝與克隆）、236–245（快取圖）、304–329（結果覆寫／跳點）、339–350（自播與舊播放器）；`Tech.html` 約 150–193（載入完整內容）。行號是本輪起點，交接時以 selector 搜尋為準。

## 三、Apple 22 個內部頁面：逐項借用與轉譯

研究方法：逐頁開啟 Apple 官方連結、讀產品段落／圖像描述及導覽；另在瀏覽器實際查看 iPhone 首頁、iPhone Pro 產品頁，操作「Read more about Design」圖卡的開啟／關閉。不是聲稱以下 22 頁所有動畫、所有彈窗及手機版都已逐一實測。每項「採用」是本專案設計判斷，不是 Apple 對本專案的背書。

## 四、圖片卡與視窗的實際觀察

在 iPhone 頁點「Read more about Design」後出現大型圖文說明容器，包含三張圖片、分段小標與解說，並有具名稱的關閉按鈕。關閉操作後焦點回到原圖卡入口。視窗內容長於 viewport，可以繼續讀，不是把文字硬塞在固定高度的小框。

本站採相同的資訊分工，但用原生 `<dialog>`：主章先交代核心規則與結果，圖片卡點開才看「節點分工、來源截圖局部、技術限制」。每張卡標題就是問題，不能只有無意義加號。視窗右上有 44px 關閉控制、Esc、標題關聯及焦點返回；手機改接近滿版的可捲動 sheet。可拖曳不是閱讀必要條件。

## 五、輔助研究（非 Apple 20 連結的替代）

初始另查看了 Apple 之外 23 個站點的官方頁面與畫面，僅作對照。可用的借用點：

- [Stripe](https://stripe.com/)：主視覺留白與重點對比；不沿用大量漸層裝飾。
- [Linear](https://linear.app/)：暗色介面中的實際工作視窗；第一次截圖尚未載完，後續另讀到工作卡畫面。
- [Vercel](https://vercel.com/)：單一主題舞台；不採過重 3D 場景。
- [Notion](https://www.notion.com/)：短結論＋產品畫面。
- [Figma](https://www.figma.com/)：畫布與任務入口；只觀察當下可讀版面，不宣稱動畫已測。
- [Framer](https://www.framer.com/)：操作介面與主題的連結。
- [Webflow](https://webflow.com/)：本次瀏覽器畫面為空白，僅官方結構可讀，**不當視覺完成樣本**。
- [Pitch](https://pitch.com/)：圖像主導與結果展示。
- [Raycast](https://www.raycast.com/)：深色與聚焦主視覺。
- [Arc](https://arc.net/)：不同內容區的色彩分場；不採新聞式橫幅堆疊。
- [Resend](https://resend.com/)：短標題與技術產品定位。
- [Clerk](https://clerk.com/)：直接展示可理解的介面狀態。
- [Supabase](https://supabase.com/)：資料能力卡與向量圖。
- [PlanetScale](https://planetscale.com/)：系統性邊框與清楚技術內容；不採過小等寬正文。
- [Tailscale](https://tailscale.com/)：連線與角色分工的視覺語言。
- [Cloudflare](https://www.cloudflare.com/)：區域分場與系統概念；不把產品行銷性能當本站數據。
- [Dropbox](https://www.dropbox.com/)：桌面與手機實際畫面一起說明。
- [Slack](https://slack.com/)：使用情境截圖；不採會擋圖的通知浮層。
- [GitHub 公開功能頁](https://github.com/features)：功能圖卡與分區導覽；研究不用登入後 Dashboard。
- [Craft](https://www.craft.do/)：紙張／視窗的具象比喻；文字擷取曾逾時，但瀏覽器有取得首頁。
- [Superhuman](https://superhuman.com/)：應用視窗與任務文字搭配。
- [Intercom](https://www.intercom.com/)：同一個問題在不同介面中的對照。
- [The Pudding](https://pudding.cool/)：視覺文章索引、主題卡；未把首頁查看冒稱所有文章的捲動動畫實測。

## 六、技術與無障礙依據

- [W3C：Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)：長時間自動移動需有可操作的暫停／停止方式。本站要求 44px 播放控制，比最低適用規範另採較大觸控基準。
- [W3C：Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)：拖動功能有非拖動替代；本設計把核心內容直接展開，不以拖拉揭露全文。
- [MDN：Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)：可見範圍驅動播放，並配合章節／分頁狀態。
- [MDN：getPointAtLength](https://developer.mozilla.org/en-US/docs/Web/API/SVGGeometryElement/getPointAtLength)：依實際 SVG 路徑定位資料封包，避免按矩形順序亂跳。
- [MDN：prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)：減少動態時呈現完整靜態分支圖。
- [MDN：hashchange](https://developer.mozilla.org/en-US/docs/Web/API/Window/hashchange_event)：處理書籤與歷史導覽；`pushState` 不會自行觸發 hashchange，程式須主動更新視圖。
- [Lucide](https://lucide.dev/guide/)：可作一致線條向量圖示的參考。若實際引入圖庫須保留授權；本原型用自畫 SVG，不使用 emoji 或外部圖示字型。
