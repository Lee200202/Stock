# v114 後台持股追蹤：持有／已出場切換，已出場回合可修正

日期：2026/10/03。Apps Script build `2026-10-03-admin-exited-v114`。GitHub `ac651eb`。

## 改動

- 後端 `apiAdminHeldList` 另外回傳 `exited`（已出場回合：出場價、報酬、出場日、出場原因）；`apiAdminSetHoldingCost` 接受持有中或已出場的回合，不在持股追蹤裡的回合仍拒絕。成本覆寫原本就以「代號＋回合開始日」套用到每一個回合並重算已實現報酬（`SheetService.gs`），這次只開放入口。
- 後台分頁「現有持股」改名「持股追蹤」，加上與前台同一組的「持有／已出場」橢圓膠囊。已出場用同一張卡與同一個編輯表單，欄名為「進場成本」「出場價／報酬」，卡片多一行出場日與原因。
- 有未儲存的修改時不能切換，並提示先儲存或收起；修改收掉後提示自動消失。手機上「修改」按鈕恢復整列寬。
- 出場價仍由系統依當日行情取得，沒有手動修改欄位。儲存已出場回合的成本，會從該回合開始日重算持股追蹤與歷史績效。

## 驗收

- `tests/test_admin_exited_v114.js`：清單含已出場與既有修正；已出場回合存成本會取代舊列、寫入新列並從回合開始日排重算；未知回合拒絕且不寫入。
- 本機假 API 畫面檢查（1280／390px）：膠囊筆數、已出場卡欄名與出場行、出場行在按鈕上方、按鈕 ≥44px、無橫向溢出、編輯表單、未儲存時切換被擋、收起後提示消失、全程沒有呼叫儲存。
- Python 218、Node 36、LINE 確認卡檢查、原站對齊 30／60 通過。
- 正式後台（真資料）：持有（13）／已出場（22）與前台一致；已出場 22 張卡都有出場日與原因、都有出場價；按「修改」展開表單（進場成本 2590、出場價 3,350），收起後未儲存 0、儲存列隱藏；切回持有為 13 張。沒有儲存任何資料。
