# v145　進出場價改取當日最高與最低的平均

日期：2026/10/08　main：`d7a9e1b`　Apps Script 版本：402（正式部署在 401，需指到 402）

## 規則

| | v68（先前） | v145（現在） |
| --- | --- | --- |
| 進場價 | 進場日最低 | （進場日最高＋最低）÷ 2 |
| 出場價 | 出場日最高 | （出場日最高＋最低）÷ 2 |
| 報酬 | （出場－進場）÷ 進場 | 相同；持有中用最新成交價代入 |

四捨五入到小數兩位（先換成「分」再平均，剛好半分時進位）。
理由：買賣是盤中喊的，實際成交落在當天區間的哪一點無從得知。買最低、賣最高是最有利的成交，報酬高估；反過來又低估；取平均不偏向任何一邊。

不變：哪一天算成交的判定（明講買賣、首次明講持有、轉觀望不碰、逾期未再提及；條件價的觸價日）；口頭價只當附註；管理者修正的成本優先；缺日 K 只往前找。

## 會自動套用到未來資料的原因

取價只在一個地方算——`SheetService.gs` 的持股追蹤重算（`midPrice_`）。每天 14:50 的排程、每日流程寫完資料後的刷新、後台的重算按鈕都走這一支，沒有第二套算法。
歷史每日績效（績效走勢）用回合的進場價加每日收盤計算：規則第一次更換時，重算會留下記號，15:05 的每日績效工作看到就先把歷史整張重算，成功才拿掉記號。

## 自動稽核

1. **每次重算後自我稽核**：每一個有日 K 的進場價、出場價都要等於那一天的高低平均（管理者修正成本的回合不算）。結果寫進執行紀錄，並隨持股追蹤資料一起提供（`priceAudit`：規則、核對數、不符數、重算時間）。
2. **獨立稽核腳本** `scripts/check_tracker_midprice.py`（唯讀、只用公開 API）：不沿用後端的計算，拿每一檔的日 K 最高、最低重算每個回合的進出場價與報酬，逐一比對；有不符時結束代碼 1。`--rule old` 可用舊規則比對，換版前已用它確認腳本本身正確（38 檔、45 個回合、121 個價位與報酬全部符合舊規則）。
3. 回合資料多記一個「出場取價日」（條件價的觸價日或往前取的那一天），稽核時才對得到正確的那一根日 K。
