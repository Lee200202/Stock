## 流程調整

1. 判讀 Prompt 的反問規則改為看語氣與後文。先前把「我也沒有告訴你 X」一律當作「早就說過 X」，可能把真正否認翻成肯定；現在只有後文確認的反問才可如此整理。單獨否定句不能推出當日買入或仍持有。
2. 公開說明補寫也遵守相同界線；資料不足時省略那個主張。它仍須保留本股自己的技術位置、數字和有來源的條件，不能直接貼原句或加套話。
3. `ASSESSMENT_VERSION` 改為 `context-json-v31`。檢查點以影片、日期、原稿指紋及規則版本為鍵；換版讓將來對同稿重判時不誤用 v30 的舊判讀。
4. `scripts/sync_quality.py` 把 Python 提示詞同步到 Apps Script `Adminpipeline.gs`。`Config.gs` 與 `Setup.gs` 對齊 `2026-10-11-evidence-regression-v166r1`。初版的 `checkProjectFiles()` 把「清除同步租約」誤查在 `dayEditSyncTick_`，實際程式位於 `runDayEditSync_`；r1 修正檢查標記，沒有改動同步程式。
5. 本次核對後，現有 Prompt 已明列「X 不敢買，但 A、B 只是被點名」要列 `ignored`，不能借用 X 的獲利或否定原因。流程另有 `drop_borrowed_avoidance`、發布品質關卡及 10/07 `must_not`；因此不再為同一例增加新的提示詞或模型呼叫。離線 `tests/test_borrowed_avoidance_1007.py` 六項與 `scripts/check_regenerate_gate.py` 通過；這不能取代下一次真實模型判讀。
