### 2. 統一橢圓形、寬鬆而清楚的視覺系統

建立可重用的設計 token：頁面背景、表面、分隔、文字、狀態、分類、價位、間距、圓角、陰影、字級與動態。主要按鈕、分頁、搜尋、篩選及狀態標籤採膠囊或橢圓；資訊卡採柔和大圓角（例如 20–28px）；不能為了「圓」犧牲文字空間或把所有資料塞進一顆藥丸。主要觸控目標至少 44–48px 高，操作群之間通常留 8–12px；卡內約 16–24px，章節約 24–40px，依密度調整。中文正文目標 16–18px、行高約 1.6–1.8；次要字不得小到必須放大才能辨認。桌面長文保持可讀欄寬，手機用自然換行和分層資訊，不能整頁橫捲。

所有顏色都有**文字標籤與形狀／圖示**配合，不只靠紅綠辨認。沿用台股語意：買入／上漲用紅系、賣出／下跌用綠系、觀望不碰用琥珀、觀望注意用藍青、持有用靛紫；但「進場價」「目前市價」「出場價」「明講價」「條件價／目標價」「試算報酬」必須另以明確欄名與不同底色／邊框區分，且不得把明講價冒充實際成交或即時報價。深淺主題都量測文字對比；一般文字至少 4.5:1。對交易／通知狀態設成功、處理中、待核對、失敗、休市五種一致語彙。

持股手機卡目前進場價、現價、報酬擠在同一行；改成可一眼掃讀的 2–3 個大欄位或上下層，標示各自日期和來源，確保較長股票名與數字不相撞。後台表單、日曆、訊息紀錄和錯誤回饋也套用相同元件，但需保留足夠資訊供管理者判斷。動態跑馬燈要支援暫停與 `prefers-reduced-motion`。

郵件使用可被 Gmail、Outlook、手機郵件相容的 table 與 inline CSS，另有可讀純文字版。設計上保留膠囊 CTA、清楚小節、長句分段與風險提醒；確認深色模式、圖片被擋、狹窄螢幕、連結點擊區。LINE Flex 必須在手機實機或 LINE 官方預覽核對可用寬度、字數截斷、alt text、按鈕、明講價與現價標籤，長內容使用摘要加原站詳情，不把整篇文章塞進卡片。管理者告警應先呈現「哪一步失敗、影響範圍、下一步、執行紀錄連結」，不要和用戶投資內容混成一封。

### 4. 讓排程與發送有明確狀態、可續跑且不重複

畫出從交易日判斷→YouTube 影片／手動稿→Gemini 聽打→Pipeline 潤飾與個股擷取→證據稽核→試算表提交→站台快取／持股與行情→每日內容快照→Email／LINE 各自寄送帳本的實際流程圖。逐步找出中斷、重複、競爭與假完成：GitHub schedule 延遲或漏跑、兩種取稿同時進來、來源內容覆蓋、模型 429／503、GAS 逾時、302 結果頁失敗、網路超時但 POST 已執行、品質關卡未完成、人工改稿、跨日、寄送途中狀態不明、個別收件者失敗、重跑、取消與恢復。

每一步要有明確狀態與檢查點；使用交易日＋來源指紋＋內容版本，通知用 channel／message type／business date／recipient 的防重鍵及接受帳本。區分「待送、已提交、服務接受、失敗可重試、結果不明需核對」，結果不明時**不得盲目重 POST**。Email 和 LINE 分開計帳與重試，測試通知只發已綁定測試帳號／指定測試信箱，正式訂閱者不因 UI 測試收到重複訊息。盤中通知只向明確同意者發送，休市每日信閘門不影響獨立的會員簡訊流程。已寄快照、人工稿與人工說明保護不可被全站重構覆蓋。

在後台做一張真正有用的操作台：本交易日最後成功階段、每階段耗時、資料日期、原稿與稽核證據、Email／LINE 每類收件數與逐人狀態、剩餘額度、最後錯誤、重試／續跑／取消按鈕的影響範圍。危險操作需顯示會改哪些資料或寄給誰，避免「刷新網站」和「重跑並重寄」語意混淆。休市顯示「按設計略過」，不顯示假失敗。
