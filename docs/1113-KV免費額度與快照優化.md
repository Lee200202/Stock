# KV 免費額度與快照優化（2026/11/13）

管理者選擇 A：保留五分鐘更新，同時減少 KV 與後端呼叫；正常工作量低於 50% 寫入警示門檻。不是關閉 Cloudflare 通知，也沒有升級付費方案。

## 原因與範圍

Cloudflare 免費 KV 每日寫入1,000次、讀取100,000次，按 UTC 00:00（台北08:00）重置。通知沒有指出操作類型；本次登入後台確認 SNAP 最近24小時有514次寫入、253次讀取，列舉與刪除均0。最近24小時不是 UTC 配額日，不能把514直接說成當天用量；但主要壓力明顯在寫入。

舊排程台北06:00–23:59每5分鐘一次，全天216輪。每輪一個心跳、最多六個內容快照，所以即使沒有訪客，寫入範圍也可能從216增加至1,512次。內容hash只能省未變動的值，不能限制全日上界。讀取路徑先讀KV心跳＋內容，再看邊緣快取；首頁已包含持股追蹤，排程仍重複向GAS查一次。

本次只修改Worker、它的設定及相關測試。Apps Script、Python主流程、寄送帳本與通知設定沒有改動。

## 修改後

| 項目 | 原本 | 新流程 |
|---|---|---|
| KV寫入 | 一輪1–7次 | 一輪最多1次，心跳／內容／逐鍵核對時間在同一包原子寫入 |
| 正常每日寫入 | 216–1,512 | 最多216（有錯誤／沒有完成寫入時更少） |
| 重複與手動重試 | 沒有跨執行個體限制 | 唯一SQLite Durable Object協調，每UTC五分鐘時槽最多准入一次 |
| 所有時槽都人工觸發 | 不受同槽總次數限制 | 每UTC日最多288次准入；另有450次預算保護，不能靠重建執行個體重置 |
| 每輪GAS方法查詢 | 通常6 | 通常5；首頁追蹤資料完整時共用，缺少時才回退6 |
| 全日GAS方法查詢 | 通常1,296 | 通常1,080，減216（約16.7%）；不含HTTP轉址／既有回源重試 |
| 前台KV讀取 | 記憶體miss後2次 | 有效邊緣命中0次，冷讀1次整包；同執行個體15秒內跨方法合併讀取 |

協調器是SQLite Durable Object，Free方案支援；使用不同資源的少量持久計數，不再為計數器增加KV寫入。原有ADMIN_AUTH類別、binding、migration與安全設定保留。寫入准入先落盤：如果KV寫入結果不明，保留該時槽已使用的紀錄，不在同槽重寫。沒有新增公開的手動刷新路由。

216／288是對這個Worker寫入路徑的上界，不是整個帳號的總用量保證。其他Worker、直接KV API操作、舊版仍在執行的請求，以及上線當日已消耗的額度，要另算。已寄出或延遲寄達的50%警示不會被新版本撤回。

## 新鮮度與錯誤處理

- 每個資料鍵保留自己的 `validatedAt`。某鍵失敗不會因其他鍵成功或整包心跳更新而續命；超過12分鐘改走既有即時後端路徑。
- 新增的快照邊緣／memo重用最多30秒，且不得越過該鍵12分鐘上限；整包短期記憶體快取15秒也不改核對時間。
- 同內容可保持較舊的內容時間，核對時間另計；不能以內容時間舊就錯判資料已失效。
- KV不可用、預算用完或寫入失敗時，前台仍可查後端；速度可能下降，不用過期內容冒充成功。
- 即時報價既有不重播／不長期快取規則保留。
- 整包超過20MiB就拒絕寫入，保留舊包；避免撞平台25MiB上限。既有後台觀察的全namespace僅約230KB，但仍需持續看大小與讀取延遲。
