# 複核與修改紀錄頁：建置前驗收計畫

1. 資料連接：讀 REVIEW_LOG_ID 指向的獨立紀錄表，逐項核對每日摘要、差異明細、通知內完整日報與提示詞候選；未設定／讀取失敗不能顯示成零錯誤。
2. 選取完整性：日曆單日、日期區間含起訖日、跨月及無資料狀態；分頁必須完整載入，區間變更後不能被舊回應蓋掉；匯出不可少後續頁。
3. 卡片內容：名稱／代號、網站與複核分類、嚴重度、原文依據、判錯原因、修改前後、處理狀態、執行來源均完整；邊界與複核錯也要可看。
4. 管理者修訂：保留來源原紀錄，另存版本與時間；過期指紋拒絕覆蓋，文字以純文字呈現，不能執行HTML／試算表公式。
5. 網站編輯：先讀當前真實列再編輯，名稱代號及分類沿用既有驗證；儲存前核對整列版本，不用舊複核判斷直接覆蓋新資料；缺列時明示不能當既有列修改。
6. 更新進度：網站儲存後接既有郵件內容、追蹤、績效同步，分清儲存完成與衍生更新完成，保留既有寄送旗標，不重寄。
7. MD匯出：包含整個區間的原始與修訂差異、完整日報、提示詞候選及來源；說明哪些是複核判斷、人工修訂及已驗證結果；不夾帶金鑰／收件者名單。
8. 權限：僅管理者API；未登入／錯密鑰不得讀寫，不新增公開資料入口；寫入保留可追溯紀錄。
9. 實際UI：沿用圓角卡片／膠囊／來源卡；桌面與390px手機、深淺色及大字，確認無橫向溢出、長文可讀、表單取消及下載正常。
10. 發布：main、Pages、GAS HEAD／版本／原部署及Worker白名單一致；實際讀取至少兩個日期、匯出檔與來源逐項比對；用管理者驗收註記新增再還原驗證寫入，不為測試改掉真實股票分類。
