# 每日寄信前複核排程說明書（草稿 v0，2026/11/02）

狀態：第一階段規劃，待管理者確認後才建置。本文件不改任何程式、不啟動任何排程。

## 1. 目的

每個交易日在整理信寄出前，由 Claude 獨立讀完當天原稿，自己分類，再和網站／郵件內容比對：

- 確保寄出去的郵件沒有明確錯誤（錯分類、漏收、誤收一般詞、無據說明、私人通知價外洩）。
- 把每次發現的差異記錄下來，累積成可以拿來調整 AI 提示詞與規則的資料。
- 管理者一段時間沒空看時，流程仍能在雲端自己跑、自己留紀錄。

## 2. 已定案的選擇（管理者 2026/11/02）

| 項目 | 決定 |
|---|---|
| 執行平台 | Claude 雲端排程（Claude Code 例行任務），不用開電腦 |
| 修正權限 | 先試行「只記錄」約兩週；管理者確認判斷可靠後，才開放明確錯誤自動修正 |
| 錯誤紀錄 | 雲端硬碟新建一份獨立的 Google 試算表（可匯出 Excel） |
| 寄信時間 | 加「複核中」暫停旗標：複核完成就寄；超過 13:00 仍未完成，照原內容寄出並在日報註明 |

第二優先（需要開電腦的本機排程）只在雲端方案確定做不到時才用。

## 3. 現況與時間軸

- 主流程（GitHub Actions `daily.yml`）11:05 起輪詢影片。最近幾個交易日約 11:20 寫完當天內容，偶爾到 12:10（10/28）。
- 整理信由 Apps Script `dailyPushJob` 寄出：預設最早 12:00，且要文章與品質關卡就緒；同一天只寄第一封。
- 原稿位置：主資料試算表「影片清單」的「原始逐字稿內容」「修飾後逐字稿內容」欄；當日會員通知在「會員簡訊」。

預定時間軸（交易日）：

| 時間 | 動作 |
|---|---|
| 11:40 | 雲端排程啟動。若主流程還沒寫完，每 5 分鐘再看一次，最多等到 12:40 |
| 啟動後立刻 | 設「複核中」旗標，郵件暫緩 |
| 讀完原稿 | 先寫好並凍結獨立判讀，這時還不看網站結果 |
| 凍結後 | 讀網站／郵件內容，逐檔比對 |
| 比對完 | 寫錯誤紀錄與日報；試行期不改內容 |
| 完成 | 解除旗標，郵件照常寄出 |
| 13:00 | 旗標自動失效（安全閥），郵件照原內容寄出 |

週末、休市日、當天沒有影片：不啟動或啟動後立即結束，只寫一列「未執行原因」。

## 4. 每日步驟

### 4.1 取資料（唯讀）

1. 讀「影片清單」當日列：原始逐字稿、修飾後逐字稿、影片 ID。原始逐字稿是唯一判讀依據，修飾稿只輔助辨認同音字。
2. 讀「會員簡訊」當日通知、「操作紀錄」「會員持股」：只用來判斷部位（持有／當日成交）。讀不到就記「不知道」，不等於沒有部位。
3. 這一步不讀網站分類、不讀「分類裁決」快取。

### 4.2 獨立判讀並凍結

逐檔寫出：

- 公司身分。一般詞要排除（如「世界第一名」「國巨大漲」裡的「巨大」）；聽寫別名只用已確認的對照，例如金策＝精測、季家＝技嘉。
- 主體：是本人／會員，還是觀眾、他人。
- 時間：今日成交、既有部位、歷史回顧，還是未來條件。
- 可接受的分類集合，依既有裁示。例如持股與觀望注意都算通過；有當下禁令就算觀望不碰；持有必須有紀錄。
- 必要的技術重點與原文段落編號。

判讀寫成 JSON，記下雜湊後才進入比對，之後不得回頭改判讀。

### 4.3 比對

讀網站 API 與「每日推播內容」，對每一檔核對：

| 差異類型 | 例子 |
|---|---|
| 分類錯誤 | 網站列賣出，原稿只是昨天賣 |
| 漏收 | 原稿明講觀望不碰，網站沒有 |
| 誤收 | 一般詞被當成股票 |
| 說明無據 | 「基本面與技術面同步強勢」原稿沒講 |
| 時態錯誤 | 原稿「會突破」，說明寫「順利突破」 |
| 通知價外洩 | 只在私人通知才有的價格出現在公開說明 |
| 郵件章節 | 盤勢總覽／教學重點空白、重複或無據 |

每一項分成「明確錯誤」或「邊界案例」。邊界案例只記錄，不算錯，例如持股與注意互換、可接受集合內的差異。

### 4.4 處理

- **試行期（只記錄）**：不改網站、不改郵件，只寫紀錄和日報。
- **開放自動修正後**：只修明確錯誤，而且只走現有的寫入路徑。
  - 路徑：分類裁決人工列，或單日重判的套用模式；會先備份、寫完讀回，寄送帳本不動。
  - 修完逐檔讀回網站 API 才算完成。
  - 不操作後台網頁，不輸入管理密鑰。

### 4.5 紀錄與日報

錯誤紀錄試算表（新建）分頁：

**「差異明細」**，每一項差異一列，欄位如下：
- 日期、代號、名稱
- 網站分類、複核分類、可接受集合
- 差異類型、嚴重度（明確錯誤／邊界）
- 原文段落與引句、判斷理由
- 處理（只記錄／已修正／待管理者）
- 修正前內容、修正後內容
- 排程執行編號
- 是否已轉成規則或測試、備註

**「每日摘要」**，每天一列：
- 日期、是否執行、未執行原因
- 主流程完成時間、複核完成時間
- 檔數、明確錯誤數、邊界數、已修正數
- 郵件是否被暫緩、暫緩多久
- 判讀雜湊、執行編號

**「提示詞候選」**：同一類錯誤累積到門檻（例如兩週內 3 次）時，寫一則修改建議，附反例原句、建議的規則或提示詞文字，以及要新增的離線測試。

## 5. 提示詞與規則調整

- 每日排程不直接改正式程式或提示詞。
- 符合門檻時，排程另開一個分支，放上提示詞或規則修改，加上對應的離線測試（`scripts/run_offline_contracts.py` 必須全過），並在「提示詞候選」填連結。
- 由管理者確認後才合併。日後若要放寬成自動合併，另行定案。
- 不加股票名稱特例，不用關鍵字決定方向，不在提示詞放股名或預期答案（沿用既有規則）。

## 6. 權限與安全

| 能做 | 不能做 |
|---|---|
| 讀主資料試算表、網站 API、原稿 | 寄送任何 Email／LINE（郵件仍由原流程寄） |

## 7. 需要新建的東西（第二階段）

1. **「複核中」暫停旗標**（Apps Script）：
   - `dailyPushJob` 寄信前先看旗標；旗標在、而且還沒到 13:00，就延後。
   - 旗標放在試算表的一格，或 Script Properties，由排程設定和解除。
   - 時間觸發器跑的是 HEAD，以 clasp 推上去就生效；需要確認不影響 LINE 每日總覽。
2. **錯誤紀錄試算表**：
   - 管理者在雲端硬碟建立後，共用給服務帳戶（編輯者）。
   - 或由服務帳戶建立後共用給管理者。
3. **雲端環境設定**：
   - Claude 雲端環境要放服務帳戶金鑰、主資料試算表 ID、紀錄試算表 ID（環境變數或秘密）。
   - 網路權限要能連 Google Sheets API 和網站 API。
   - GitHub 權限要能讀 repo、開分支。
4. **複核腳本**：
   - 讀取與寫紀錄用固定的 Python 腳本，凍結判讀、比對、雜湊、讀回都由程式記錄。
   - 判讀和比對由 Claude 依本說明書與分類裁示（`docs/stock-skills`）執行。
5. **試行期檢查表**：前兩週每天的紀錄由管理者抽看，決定是否開放自動修正。

## 8. 失敗處理

| 狀況 | 處理 |
|---|---|
| 12:40 主流程仍未寫完 | 不複核；解除旗標，寫「未執行原因：主流程未完成」 |
| 讀不到試算表或網站 API | 重試 3 次；仍失敗就解除旗標，寫失敗原因 |
| 排程本身沒啟動 | 13:00 安全閥讓郵件照常寄；隔天日報補記「前一天沒有複核紀錄」 |
| 判讀中斷或超時 | 已凍結的部分保留；未完成項目記「未複核」，不算通過 |
| 試行期後修正失敗 | 不重試第二次；記「待管理者」，郵件照原內容寄出 |

## 9. 驗收方式（第二階段）

- 先用已有答案檔的歷史日（10/27～10/29）離線演練：比對與紀錄格式要正確，但這些日子已用於調整，只算回歸。
- 再在交易日以「只記錄」模式實跑，至少 10 個交易日。
- 每天由管理者抽看紀錄，算出複核判讀與管理者判斷的一致率。
- 開放自動修正的條件（建議）：連續 10 個交易日沒有誤報的「明確錯誤」，且漏報的明確錯誤不超過 1 項。

## 10. 待確認的問題

1. 日報要怎麼通知你？
   - 預設：只寫進紀錄試算表。
   - 另可選：每天寄一封只給你的簡短信（需在 Apps Script 加管理者通知）。
   - 或：在 GitHub 開一則日報。
2. 「提示詞候選」的門檻：兩週內同類錯誤 3 次，可以嗎？
3. 複核範圍要不要包含網站上的個股說明全文，還是先只核分類與郵件兩個章節？說明全文會讓每天的判讀時間和用量明顯增加。
4. 試行期多久：預設 10 個交易日；開放自動修正前由你看過紀錄再決定。
5. Claude 雲端排程用的是你的 Claude 方案額度。每天一次完整判讀大約要讀 1～3 萬字原稿，會占用部分額度。是否接受？
6. 錯誤紀錄試算表由你建（再共用給服務帳戶），還是由服務帳戶建好後共用給你？

## 12. 做成技能，減少每次的判讀成本（管理者 2026/11/02 建議）

重複的步驟和固定的位置寫成技能與腳本，讓 AI 只花力氣在判讀上：

- **新技能 `stock-daily-review`**（放在 `docs/stock-skills`，依十技能的建置規則同步）：
  - 時間軸、資料位置（分頁與欄位）、判讀順序。
  - 要先載入的裁示清單、比對的差異類型、紀錄欄位、權限表。
- **固定腳本**（判斷結果與 AI 無關的部分都交給程式）：
  - `fetch_day.py`：取當日原始逐字稿、修飾稿、會員通知原文、今天以前的部位，輸出一份小的輸入包；不輸出今天的流程結果。
  - `freeze_reading.py`：寫入判讀 JSON 並算雜湊。
  - `compare_site.py`：讀網站 API 與郵件內容，依可接受集合自動產出差異表，並檢查通知專屬用語。
  - `write_log.py`：寫進紀錄試算表的三個分頁。
- **不用網頁點選**：
  - 後台和試算表都改走 API 與腳本，不靠截圖和座標點按鈕。截圖最耗額度，版面一改就失效。
  - 真的需要網頁的步驟才在技能裡寫死路徑與按鈕。
- 預估每天只剩「讀原稿判讀」和「看差異表」需要 AI 思考，其餘由腳本完成。
