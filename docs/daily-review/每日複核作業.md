# 每日寄信前複核：雲端排程作業步驟

本檔是雲端排程每天照做的步驟（等同技能）。固定動作交給腳本，AI 只做兩件事：讀原稿判讀、判斷差異。不用截圖或點網頁。

- 試行期：2026/11/03～2026/11/14（10 個交易日）。只記錄、提出修正建議，不改網站。
- 試行期後：明確錯誤自動修正（走第 6 步），改了什麼寫進 12:30 日誌。

## 0. 環境（雲端環境變數，由管理者設定）

| 變數 | 用途 |
|---|---|
| `GOOGLE_SHEETS_SERVICE_ACCOUNT` | 服務帳戶金鑰 JSON（與 GitHub 的同一把） |
| `SPREADSHEET_ID` | 主資料試算表 |
| `REVIEW_LOG_ID` | 複核紀錄試算表 |
| `GEMINI_API_KEY` | 填 `offline` 即可：複核不呼叫 Gemini，只為了讓主流程模組能載入 |

- 網路要允許：`sheets.googleapis.com`、`oauth2.googleapis.com`、`www.googleapis.com`。
- 第一步先安裝套件：`pip install -r requirements.txt`。

## 1. 取輸入包（11:40 起）

```bash
python scripts/daily_review/fetch_day.py --hold
```

- **印出 `NO_TRADING_DAY`**：週末或休市日，直接結束，不寫任何東西。
- **印出 `NOT_READY`**：主流程還沒寫完。每 5 分鐘再跑一次，最多到 12:40。
  - 到了 12:40 仍未完成（包括當天沒有影片）：寫 `judged.json`，`diffs` 留空，`report` 寫「主流程 12:40 仍未完成，今天未複核」，然後跑第 5 步。
- **印出 `READY`**：已把今天設為「複核中」，郵件會等，最晚 13:00。

## 2. 讀裁示，再獨立判讀（這時不看網站）

1. 先讀以下三份，記在判讀檔的 `rulings_read`：
   - `docs/daily-review/裁示紀錄.md`
   - `docs/分類裁決基準.md`
   - `docs/stock-skills/skills/stock-content-audit/references/self-classification.md`
2. 讀 `.daily-review/<日期>/` 裡的檔案：
   - `raw.txt`：判讀唯一依據。
   - `polished.txt`：只用來辨認同音字。
   - `notices.txt`：只用來判斷部位。
   - `positions.json`：今天以前的部位。
3. 整篇讀完再寫 `reading.json`，格式見 `scripts/daily_review/freeze_reading.py`：
   - 每一檔原稿點名的股票都要有一列，附原句和可接受集合 `accept`。
   - 確定不該公開的放在 `must_not_public`。
   - 沒有股名的「這一支」不要猜。
4. 凍結：

```bash
python scripts/daily_review/freeze_reading.py .daily-review/<日期>/reading.json
```

凍結之後不得回頭改判讀。

## 3. 比對（凍結後才讀網站內容）

```bash
python scripts/daily_review/compare_site.py
```

產出 `diffs.json` 與 `diffs.md`，差異類型包括：分類、漏收、複核未涵蓋、應排除卻公開、今日買賣、通知用語外洩、說明重複。

## 4. 判斷每一項差異，寫 judged.json

每一項差異給一個嚴重度：

| 嚴重度 | 什麼時候用 |
|---|---|
| 明確錯誤 | 違反裁示紀錄或分類基準，原句清楚 |
| 待確認 | 可能錯，但裁示沒有直接規定，或原句兩可 |
| 邊界 | 在可接受集合內的差異，或材料極少 |
| 複核錯 | 回頭看，是自己的判讀沒套用裁示；網站是對的 |

`report` 是寄給管理者的完整日報，純文字，依序寫：
1. 一句總結：比對幾檔、各嚴重度幾項。
2. 每一項明確錯誤／待確認：網站寫什麼、原句、依據哪一條裁示、建議怎麼改（分類與說明全文）。
3. 主流程執行狀況：幾點寫完、郵件狀態。
4. 提示詞候選：同一類錯誤反覆出現時，寫要改哪一段規則或提示詞、附反例原句，並說明要加什麼離線測試。
5. 待管理者裁示的問題，例如新的別名、新的邊界寫法。

## 5. 寫紀錄、排通知、解除複核中

```bash
python scripts/daily_review/write_log.py .daily-review/<日期>/judged.json
```

- 試行期 `trial: true`：立刻排一封「複核結果」，另排 12:30「每日複核日誌」。
- 試行期後 `trial: false`：只排 12:30 那封。
- 實際寄信由 Apps Script 每 5 分鐘讀「通知」分頁，用管理者通知寄出。

## 6. 試行期後才做：修正明確錯誤

只修「明確錯誤」，而且只走現有的修正工具，不碰後台網頁、不用管理密碼：

1. 寫計畫檔：
   - 個股分類與說明：`scripts/repairs/<日期>-source-review.json`，格式見 `scripts/apply_source_review.py`；`previous_note_sha256` 由 `site.json` 的說明算 SHA256。
   - 盤勢與教學章節：`scripts/repairs/<日期>-points-review.json`，格式見 `scripts/apply_reviewed_points.py`。
   - 引句要逐字出自 `raw.txt`。
2. 推到分支 `daily-review/apply-<日期YYYYMMDD>`。GitHub 工作流程 `daily-review-apply.yml` 會依序預覽、套用、讀回。
3. 不得修正的項目：
   - 新增或更動今日買賣（成交事實）。
   - 新增聽寫別名。
   - 其他日期的資料。
   - 寄送帳本。
   - 遇到這些情況改列「待管理者」。

## 省用量的規則

- 只讀這裡列出的檔案，不要全庫搜尋，也不要讀 `pipeline/pipeline.py` 全文。
- 原稿只讀一次，判讀一次寫完。
- 不重跑主流程、不呼叫 Gemini、不開瀏覽器。
- 判斷差異時只看 `diffs.md` 與相關原句，不重讀整份原稿。
