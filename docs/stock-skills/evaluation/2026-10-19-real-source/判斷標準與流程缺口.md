# 獨立判斷標準、發布修正與流程缺口

## 一、答案從哪裡來

本輪先完整閱讀保存原稿，依公司、主體、事件日、動作性質、現有部位與目前進場立場分類，再比較工作流。正式網站是發布結果與待修資料的讀回來源，不是分類答案。既有13天答案只提供定義與回歸例，不把那13天股票的標籤、價位或後來的部位套到新日期。

四個額外日期為8/21、9/02、9/22、10/19，共65,498原始字元。凍結表、12次重播、失敗輪次與評分限制見[實測結論](實測結論.md)。來源審核草稿仍接受再次覆核；例如10/19祥碩身分只剩「享受」諧音，本輪已撤回必收要求。

## 二、分類的先後順序

| 問題 | 必須取得的事實 | 不能拿來代替的內容 |
|---|---|---|
| 是哪家公司？ | 明講名稱／代號，或來源內足以核對的身分線索 | 數字剛好像代號、只靠價位猜股名、把族群名當公司 |
| 誰做的？ | 講者本人、會員共同操作、個別觀眾、第三方各自區分 | 觀眾「我有」不等於講者持股；法人買超不等於會員買入 |
| 何時發生？ | 今天、昨天、具體日期、尚未發生分開 | 今天提到過去賣出，不能改成今天賣出 |
| 動作完成了嗎？ | 已買／已賣，或經原文確認的正式當日操作指令 | 可以買、如果賣、不要賣、想買、反彈可賣不是已成交 |
| 目前有部位嗎？ | 當時有效的未出場紀錄或本股明講持有 | 只有歷史買過，或在背景新聞點名，不足以產生今日分析卡 |
| 現在的進場立場？ | 可執行的買點、向前展望，或目前禁止／尚不成熟的限制 | 沒有主動通知不等於禁買；將來看好不解除現在不能買 |
| 這項數字屬於誰？ | 每項成本、EPS、量能、技術位置回到本股段落 | 全文找得到數字、比較句提到股名、裁決三票一致 |

通知優先的是經原文語意核對的操作事實，不是解析器產生的錯誤列。不能因代號是整數就斷言一定是人工輸入；正式修正直接核對來源ID與舊文字SHA。

### 買入與賣出

需要公司、本人／會員操作主體、當日時間及動作已發生／正式指令四項一致。只描述「今天賣會很蠢」「我若賣也賺錢」「昨天先賣再買回」，均不是今日實際成交。條件式指令還要保存觸發條件及部分部位範圍，不能擅自推論全部成交或全數出清。

10/19鴻海260元、世芯4,400元及鈺邦出場均是過去操作；當天結尾維持不亂調節，不能因此新增當日賣出。9/02晶心科的先賣後買回明講在昨天，不能同時記到9/02。

### 會員持股與觀望注意

持股需要部位證據；注意表示目前有偏多或可執行條件，並不建立成本、持有張數或回合。管理者允許這兩類在特定公開分類驗收同組接受，不表示投資組合帳本也能互換。

持有紀錄可以支持現有部位，但只有在原稿有本股當日有效內容時才產生今日分析說明。8/21台積電只在晶片供應背景中被點名，不能拿未賣出紀錄補出一張當日持股分析卡；同理，刪掉10/19毅嘉的大盤錯位說明，不代表應關閉先前真實持有回合。

鴻海10/19給出230餘元拉回區，說未主動叫會員買，是偏好其他標的而未發新指令；不是「不准買」。因此公開分析應為觀望注意。旭隼與神準則在不同段明講自己的股票，不能把旭準與網通聖準合成一檔。

### 觀望不碰與條件式注意

「目前不買，條件還沒形成」「等我判斷後才告知」是現在進場限制，列不碰；「拉回某個已明確給出的區域可觀察」且沒有當下禁買，是條件式注意。不能僅看到「等」「如果」就機械地判為注意。

世芯10/19已有缺口與60分K尚未成熟的具體限制，即使未來願意買回，也不是目前可買。台達電9/22的原文則明確把「過去三個月不買」切換為「近一週轉強、突破季線」，不能沿用過去的否定。

### 回顧、不公開與身分未定

只有過去交易、現在沒有看法時可不公開，但候選與原因留在內部。過去交易後另有現在買點或風險時，必須另判現在立場，不能把整家公司一起丟掉。僅行情描述、公司背景或籌碼數字而沒有有效觀點，不硬湊分類。

身分未定不是確定排除；保留未知原因，不放進強制不應出現名單。矽晶圓不是精元，合晶不是合庫金；但只剩「維星」且無足夠代號線索的候選，不能只因某個名稱存在就當成已辨識成功。

## 三、為何第一輪有明顯幻覺

這裡的幻覺包括跨股搬用真實句子；句子在原稿存在仍可能歸屬錯誤，並不一定是憑空造字。

1. **原文窗口越過轉場。** 亞德客的大戶比重、1200元以下與年線後接世芯買回討論；後段的「3266／未買」被接到亞德客。
2. **比較對象接走整段數字。** 「像嘉澤一樣」只是一個比較，嘉澤不能因此繼承亞德客1200元以下的大戶圖。
3. **聽寫身分與部位紀錄互相加強。** 只要近音字加上歷史持股，就可能把大盤止穩段寫成毅嘉說明；反向只看四位數，也會把價位誤認為公司代號。
4. **日期與現在觀點混在同一欄。** 歷史已賣被用來刪掉現在有效買點；「未通知」被誤讀成禁止，或「可以買」被當成正式買入。
5. **生成與覆核信任相同錯誤材料。** 審閱提示原本將上游evidence稱為已核定，但其實只核實字串存在。模型沿同一窗口覆核，三票也可能一起錯。
6. **改寫失敗卻保留原本錯句。** 原程式限制數字不可改，本來借錯股的數字即使被改寫模型刪掉，也可能因數字變動而不採用；保留舊句不等於保留正確事實。
7. **反覆整天套用重生成。** 每輪分類可能相同，說明卻換一組缺陷；已通過片段沒有依來源與審核版本穩定保存，重跑不會自然收斂。

這些是輸入、證據與狀態設計缺口，不能只靠加大context window、放寬觀望數量或改用更昂貴模型解決。

## 四、已實作的正式修正路徑

`scripts/apply_source_review.py`已加入單日工作流，使用日期修正計畫，與模型重播及答案檔分離。

```text
完整原稿與原始通知
        ↓ 來源SHA／公司／主體／日期／本股歸屬
獨立判定＋書面修正計畫
        ↓ 舊列SHA、來源ID、唯一性、官方代號
唯讀預覽
        ↓ 獨立試算表三表備份、再次核對同期變動
同一Sheets原子批次：修改＋收據＋已審核說明紀錄
        ↓ 逐欄讀回；其他日期與受保護來源不變
只刷新郵件查詢／持股／績效
        ↓ 寄送旗標與帳本不變
日期API＋首頁＋郵件查詢實際驗收
```

不呼叫模型、不寄送，不對未知結果的寫入盲目重試；重跑先驗收據與最終狀態，只接續刷新。修正內容保留Git版本、原稿引句與舊列指紋，已確認的書面說明按既有來源指紋保留機制存入修正紀錄。

這是今日與歷史缺陷的來源審核修正，不是通用模型分類改善證明。GitHub concurrency也不是GAS全域鎖；備份期間資料變動會取消寫入，寫入後另有獨立工作修改則須讀回診斷。

## 五、通用流程下一版要改在哪裡

以下為**設計及驗收規格，尚未全部實作或通過真實模型驗證**。先前實驗PR保留草稿，不能把本節當成已部署功能。

| 階段 | 應有契約 | 本輪發現的缺口 |
|---|---|---|
| 來源凍結 | raw、閱讀稿、影片、通知、截至當日部位各有指紋 | 重播的外部上下文未全凍結；停用裁決快取仍可能沿用舊列與人工說明 |
| 候選盤點 | 名稱／代號／匿名候選有穩定ID及處置帳 | history清空、忽略列及只念代號的公司未必送到下一輪 |
| 批次事實覆核 | 主體、時間、已成交／建議、否定作用對象、部位與現在立場分欄 | 一個條件或動詞直接轉類別，多個後置規則覆蓋已判事實 |
| 本股事實整理 | 數字與技術主張各有原句位置及所屬公司 | 字串存在被當成本股證明；類比與換圖跨股 |
| 分類映射 | 固定優先順序；部位與新進場立場雙軸 | 歷史賣出吃掉現況、未通知等同禁買、觀眾部位等同本人部位 |
| 書面生成與審閱 | 使用核定事實；輸入句及輸出句分別核對 | 原句錯誤與改寫錯誤混為一談；不能修數字時留下原本錯數字 |
| 發布與隔離 | 已證實錯誤、未定、漏收各別記錄；單檔錯誤不擋其他可發布列 | 隔離率可能上升但漏收未被量測，綠燈不足以證明內容正確 |
| 保存與重跑 | 原文段落＋事實＋版本指紋；只重問變動或未定項 | 同稿重寫不穩定；人工修正、模型快取、直接規則結果混用 |

### AI請求如何合併

- 沿用既有擷取、裁決、撰稿及公開審閱入口；同日期候選以穩定case ID合批，不一檔一問。
- 覆核包含未公開與回顧候選，才能檢查漏收；不能只審已收錄清單。
- 裁決問事實及原句歸屬，不請模型只回一個分類標籤。原文與候選引句均是待覆核材料，不宣稱已正確。
- 新增的獨立歸屬覆核以每日期一批為起點；只有缺答、截斷或仍未定的小批再問一次。實際上限依token與模型回覆完整度決定，不把所有日期塞成一包。
- 同模型專案滾動60秒合計15RPM，含重試；不同key與工作不能各自用滿15。分類是否更穩定與呼叫量、速度各自報告，不用省呼叫掩蓋錯誤。
- 高票不是原句支持。三票一致仍可能跨股；來源不足、身份不明及受限條件未解，不為取得一致結果無限重問。

### 發布前的可量測門檻

分開量測當日成交錯列、候選漏收、當下立場錯類、部位錯造、跨股數字、無依據技術主張、隔離後覆蓋率、人工介入與用量。不能用平均總分抵銷虛構交易或跨股資訊。

同一版本至少重複測來源範圍不同的日期，固定部位／名稱／通知與前版內容快照；13天回歸與新增月份分列，最壞輪次也要過硬關卡。模型或Prompt更新後再測；失敗與部分輸出一併保存。只有程式格式、技能安裝或合成測試通過，不能寫成未來不會幻覺。
