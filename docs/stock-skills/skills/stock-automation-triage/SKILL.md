# 自動化診斷與續跑

擔任流程可靠度工程師。先界定台北日期、交易日／停播、目前時窗、來源事件與應完成階段；未到時間、來源還在直播、無片與系統故障分開。任務缺日期時從現行站點、GitHub Actions、GAS 執行紀錄及帳本定位，不先重跑。

管理者指定的取稿截止為台北時間 12:00：成功核對當日影片清單、直播、預告及回放仍無節目，就記當日「今日無直播」，後續當日取稿與無原稿的每日流程直接略過；下一交易日按日期自動恢復。不以停播公告或 AI 回答作必要條件，不因此停掉簡訊、行情與既有寄送續跑。已偵測到直播／預告繼續等回放；API 失敗、權限問題與查詢未完成不能冒充無片。GitHub 排程非準點保證，說明規則截止時間與實際執行時間。

先讀工作區適用規則與當前 `.github/workflows/`、`transcript.py`（確認實際路徑）、`pipeline/pipeline.py`、GAS `Setup.gs`／`Cmoney.gs`／`MailService.gs`／`Line.gs`。建立來源 → 原稿 → 稽核 → 發布 → 通知 → 背景行情／績效的同日事件鏈。詳細定位、錯誤分流與工具入口讀 [診斷及恢復手冊](references/triage.md)。

GitHub 綠燈、心跳、HTTP 200、文章完成、平台接受與收件者已讀是不同證據。恢復只續未完成階段，保留片段、檢查點、租約、原稿指紋及寄送狀態。程式有單檔內容問題時隔離本股；整體原文失效、身份錯誤或寫入不一致則停止相應寫入，不把所有錯誤都降為成功。

認證／參數 400 與暫時性 429／503 分流；永久配置錯誤不輪換所有金鑰空等。把同批校字／疑點裁決合併，保留已完成內容，先量真正耗時再節流。官方寄件身分為 `rainforecast2026@gmail.com`；核對當前設定及有效執行者，不能用協作者誤寄或為驗版重送全體。

已發生過的事故與處理（10/05–10/15）讀第 8 節；沒有 gh CLI 時怎麼讀與觸發 Actions 讀第 9 節。規則判錯要改規則與回測時交給 `stock-rule-tuning`。

一般健康巡檢先唯讀，發現確定故障且在授權範圍才修復並讀回。已寄送不重寄、未知結果不盲重送；一般部署不重裝觸發器。報告本日各階段、根因、修復、呼叫／時間預算、Email 與 LINE 各自帳本、背景進度及未驗證項。

## 盤中連續無成交的異常核對（2026/10/22）

行情排程連續20分鐘且至少三輪沒有本日有效成交時，使用 `MarketSession.gs` 合批讀證交所年度表與最新新聞，再以一批AI核對休市日期、全市場範圍、全日／部分時段及逐字引句。已知國定休市直接略過，不為已知答案呼叫模型。空報價、來源逾時、AI肯定但無官方引句，均不構成休市。

官方確認當日全日休市才暫停行情和盤中通知來源的自動抓取；已保存原文的同步、Email／LINE待送續跑、歷史補抓及人工強制稽核保留。年度表未取得不能冒充已確認休市。當日有有效成交不能再標全日休市。未知每30分鐘最多一批、每日最多三批、每批單次實際模型請求；不可為查假日輪替全部金鑰或形成呼叫迴圈。日期狀態換日自動失效，不刪排程。

`diagnoseMarketSession()` 只讀保存狀態；`previewMarketSessionReview()` 會取官方來源並送一批AI，但不改狀態或排程。替身模型的契約測試與真實模型預覽分開報告，不把模擬20分鐘寫成實際當日停抓已驗。
