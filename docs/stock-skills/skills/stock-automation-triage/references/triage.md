# 日期事件鏈、錯誤分流與低耗時恢復

## 1. 最小診斷表

| 階段 | 查什麼 | 不可混淆 |
|---|---|---|
| 影片來源 | 日期、影片 ID、直播／預告／結束、可轉錄時間 | 11:05 尚在直播不是抓取失敗 |
| 原稿落地 | 原始字數、SHA-256、已完成片段、保存時間 | 有模型回覆不等於已保存整份原稿 |
| 品質／分類 | run、規則版、有效引句、隔離股票、全篇關卡 | job 綠燈不等於每列有證據 |
| 文章發布 | 正確日期、標題、分類與狀態、API 讀回 | 試算表寫好未發布可能仍顯示舊版 |
| Email | 就緒、正式寄件者、收件者快照、accepted／pending／unknown | 已寄信是當時快照，不隨網站修正改寫 |
| LINE | 同意／綁定、模式、relay、queue、期限與帳本 | Email 完成不能代替 LINE 完成 |
| 背景 | 日 K 游標、持股／績效重算與快取 | 文章完成不代表全部背景完成 |

每列保留台灣時間、日期、來源 ID、run／job、心跳、attempt、規則與下一步。不要把前交易日最新成功當今天證據。使用者只要健康檢查就先查這張表，不新增補寄或監控排程。

## 2. 影片與模型錯誤

影片偵測按當前 YouTube 來源狀態處理 live／upcoming／已結束；未結束延後輪詢，結束後再轉錄。當日沒片、未發布、API 故障分開記，輪詢有截止／退避和可續跑狀態，不合成不存在的稿。引用模型名稱、每段長度與平行度要讀當前設定，不將舊日誌永遠寫進指令。

| 錯誤 | 行為 |
|---|---|
| 400 Multiple authentication credentials | 檢查重複 query/header/OAuth、端點及 SDK；此為協議／認證配置問題，換三把鑰或等 180 秒不會修好。若有已驗證替代通道，可同鑰切一次；仍同錯就保存檢查點、明確報錯 |
| 400 格式／不支援參數 | 修請求／schema／端點；不對永久錯誤重試九次 |
| 401／403 | 檢查權限、有效金鑰與專案配置，不無限退避 |
| 429 | 分分鐘／日額度，依 Retry-After／當前限制退避；日額度不靠高速輪鑰掩蓋 |
| 503、5xx、連線逾時 | 有上限的退避與抖動；按已驗證模型／金鑰備援，保留成功片段，記最後恢復或失敗 |
| JSON 無效／截斷 | 保存原回覆與診斷，依現行可恢復解析／分批重試；格式合法後仍查證據，不強造空內容通過 |

不要為「效率」直接換成舊 Prompt 裡的 Gemini 2.0／2.5 名單；先讀實際成功的通道、當前支援規格與配額。分段轉錄可有限併發，但不能多鑰並行造成重試風暴。產物按原稿／片段指紋沿用，避免第二段失敗又重做第一段。

## 3. 稽核與發布不中斷的界線

- 原文明確的事實直接核對；有疑點的成交／語氣／主體併入既有裁決批次，不逐檔多問。校字亦合併一批，逐處採用。
- 單股說明有口語殘句、未證實因果、錯誤公司或無效引句：修／移除該句，仍缺證據則隔離本股並留稽核紀錄，其他合法股票繼續。
- 原稿不在、指紋已換、整體資料格式損壞、批次寫入衝突或寄件身份錯：停止受影響正式寫入／寄送，清楚顯示失敗，不能因要求「不中斷」放行。
- 心跳只表示有活動；狀態要具 stage、完成片段、租約、最後進度與下一棒。空回應發生在已寫入之後，先讀後端步驟狀態，再用同一 idempotency identity 續跑，不重頭生成／寫表／寄送。
- 文章、持股、績效與通知分階段。顯示「全部完成」需各自完成，否則列背景更新中。

## 4. 觸發器與效率

先量耗時來源：每五分鐘工作、簡訊輪詢、重算、補 K、後台反覆儲存。讀當前市場時窗、最後執行和排程頻率，再決定低成本改善。Google 觸發器配額可能是滾動窗口；台北日累計／個人帳號常見參考上限不等於可精確保證剩餘分鐘。舊日 88.7 分鐘是事故例，不是今天的即時數字。

優先：來源／狀態欄／表尾限定讀取，同一表每請求讀一次；長時間軸展開才讀；已有結果不重問模型；背景刷新依序執行以免 GAS 爭用；行情補抓按批次與游標，維持盤中通知優先。不得為節省時間讓現價永久過期，或把文章寫入綁在補完全部歷史 K 之後。

長任務採既有檢查點／續跑；新增觸發器前核對同名是否已存在及租約過期條件，不用重裝全部作通用修復。市場外略過輪詢需有清楚記錄；不要把 skip 轉成偽成功。不同 GitHub workflow 的 concurrency group 可能只留一個 pending，批量排多天前先查是否互相取消。

## 5. Email／LINE 與防重

正式寄送前查有效執行者與設定，正式寄件者 `rainforecast2026@gmail.com`。協作者可存程式不代表可用他的帳號發正式通知；身分不符即停止並回報，不自建代發憑證繞過。

按日期／來源／修訂／收件者／通道讀帳本，已 accepted 不重送；外部服務接受後寫帳本前中斷為 unknown，先核對，不能承諾 exactly-once。只續 pending／可重試者。網站更新不改已寄送旗標；改寫郵件查詢頁不等於改寫收件匣。

全新通知與實質修訂分流，沿用現行去重／修訂雜湊／期限；標點微調不造成通知風暴。若新增 debounce，按實際產品定義與原文修訂時間驗證，不能硬加固定延遲拖慢新通知。LINE 已有推送與綁定，先讀 `Line.gs`、relay 和帳本；不要因舊文件沒寫就再建一套。

只驗版面用離線預覽；真寄測試需已有對應授權、指定信箱／LINE 測試帳號。歷史一次補寄授權不自動擴為所有未來日期。

## 6. 備份及安全恢復

正式修復指定日期，優先用現有備份及修復腳本；獨立私人 Google 試算表存備份，避免主檔堆滿「備份_時間_表名」分頁。搬移先複製資料與格式、驗來源／目的數量和內容、記映射，通過才按授權移除原備份頁；非備份業務頁不可跟著搬。`scripts/backup_archive.py` 與 GAS 備份實作以當前版本確認。

通知排障候選 `diagnoseCmoneyToday`、`diagnoseLineDelivery`，會寫入的 `cmoneyReconcileNow`、各修復腳本先讀副作用及參數。函式不存在不能照歷史文件直接執行。鎖忙碌等自動續跑，不刪原稿或清空租約硬搶。

## 7. 效能與交付

列請求 wall time、後端各段、冷／熱快取、資料日期、同時段工作、失敗數。少量同路徑重測改善前後；單次 0.4 秒不代表全部請求都達標。使用者要 15 秒內完整資訊時定義完成條件（幾檔有效價格、哪些可無成交），保留冷讀超標樣本，別用顯示骨架時間當完整資料時間。

最終列正常／未到時窗／等待續跑／需處理／證據不足，附 run、原因、修復、讀回、Email／LINE 各帳本及背景工作。已啟用自動化不代表下一交易日已完成端到端驗收。
