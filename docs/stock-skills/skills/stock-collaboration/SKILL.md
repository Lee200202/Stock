# 協作與常設註解引導

處理盤勢有據的持續任務、複合要求、途中註解或交接時，先辨識本次交付與既有授權，再選需要的領域技能。窄任務不載入所有技能，不因技能被選用而新增部署、寫入或寄送權。

## 開始時掌握四件事

1. **範圍與順序**：最新要求如何接續尚未完成工作？同時要求今日及歷史內容時，先完成今日有依據的修正與正式讀回，再做其他日期；不因擴大測試拖延已確認的修復。
2. **已完成的證據**：核對 git、執行紀錄及受影響的正式內容；貼上紀錄是線索。保留他人變更，不重做已完成寫入，不取消別人的工作。
3. **本次適用的常設要求**：讀 [反覆註解引導](references/repeated-annotations.md) 的對應主題。單日股票、舊版本與暫時限制不是永久規則。
4. **授權與交付**：沿用範圍內已有授權。來源核對後的歷史更新若已整體授權，不逐日重問。對外寄送、權限變更或範圍外破壞性操作仍須相應授權；當前工具規則優先。限制來自哪層就明說，不把舊失敗升格成新限制。

## 分工

| 工作 | 技能 |
|---|---|
| 原稿、獨立分類、證據與部位 | stock-content-audit |
| 說明、重點、標題與批次語意審閱 | stock-public-writing |
| 分歧成因、Prompt／工作流修正與未見日期回歸 | stock-rule-tuning |
| 版面、卡片、圖解與跨裝置操作 | stock-site-design |
| 報價、載入、持股回合與報酬 | stock-market-data |
| 取稿、排程、續跑、通知與帳本 | stock-automation-triage |
| GitHub、Pages、GAS、Worker 及正式讀回 | stock-release-check |
| 前台 AI 助理能力邊界 | stock-assistant |

分類差異的交付包含「我的判斷與本股證據 → 流程結果 → 最早分歧 → 定義／資訊缺口 → 修正 → 未見案例結果」。來源綁定的正式修復與流程品質證明分開報告；修好網頁不代表模型已穩定。

依需要讀 [協作手冊](references/collaboration.md)：語意、授權、其他工作階段、交接 Prompt 與結案；[反覆註解引導](references/repeated-annotations.md)：內容、流程、版面及驗收的常設要求與反例。

結案提供完成結果、正式證據及未解決事項；本機、模型預覽、正式 API、瀏覽器與寄送分列。技能已安裝不等於每輪必定選用，更不等於分類準確率已提升。
