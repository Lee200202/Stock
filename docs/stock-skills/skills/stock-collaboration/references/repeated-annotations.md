# 反覆註解引導

整理於2026/10/19，來源是本對話中多次插入的註解及後續裁示。依決策主題合併，**不是精確出現次數統計**；短引文作追溯，單日股票僅作例子。最新明確要求優先。開始時選相關主題，遇到差異回查基準，結案列實際證據；不是每次都執行所有測試。

## A. 優先順序與評估

| 編號／反覆要求 | 具體引導 | 驗收與反例 | 負責技能 |
|---|---|---|---|
| A01「首先將今日正確說法推到網站上，再來測試其他天」 | 今日有依據的缺陷先核對、備份、有限修復並正式讀回；再驗歷史 | 不因長時間A/B拖延已確認修復；今天已完成不重做 | collaboration、release-check |
| A02「評斷標準不是網站…根據你自己分類」 | 先讀完整原稿與必要通知，凍結獨立判斷，再看流程／網站；留來源SHA | 網站舊分類、模型多數票、GitHub綠燈都不是標準答案 | content-audit |
| A03「分享你的判斷標準，確認目前工作流依據不足之處，定義問題然後接著修改」 | 每項差異寫證據、原則、最早分歧、資訊／定義缺口、通用修正及回歸 | 區分轉場、主體／日期、否定、錯名、裁決／補漏覆寫、撰稿與呈現；不只加股名特例 | rule-tuning |
| A04「過去沒有答案…仍保有13天…分類依據」 | 舊答案供政策及回歸，另選無答案全文、先凍結參考再跑流程 | 新參考標審核者及未知項，不把代理草稿冒充人類金標，不限13日 | content-audit、rule-tuning |
| A05「實際資料…穩定性」 | 固定來源、模型、Prompt及部位快照；區分調規則／未見／人工輔助，同版重複及失敗均保留 | 引句存在不等於屬於本股；只關裁決快取不代表沒有舊說明影響；一次通過不證明零錯誤 | rule-tuning |

## E. 分類差異的完整交付

1. **獨立結論**：身分、誰的部位、事件日、當日動作、剩餘部位、新進場立場與未知項。
2. **證據**：原稿SHA、引用及轉場，通知／操作紀錄支持何種事實，哪些屬本股。
3. **流程差異**：最早改錯、漏掉或借錯句的階段，後續是否覆寫。
4. **定義與修法**：可適用其他公司的原則，分清AI語意、固定事實核對、投票與呈現。
5. **正式修復**：授權、來源及舊值綁定、備份、範圍、回執與未變帳本。
6. **品質證據**：正例、反例、未見日期、同版重複及失敗；代理／人工修復不計為未輔助模型準確率。
7. **讀回與限制**：API、實際頁面、快照／部署面；未解決的渲染或權限問題不能隱去。

例如「高點賣出後還不能買回」是當下新進場限制，既非今天賣出，也不能因未來看好改為可買；若剩餘部分續抱則另存部位。這是語意原則，不是看到「高點」兩字觸發固定分類。
