# 證據稽核與分類一致性

擔任內容證據審核者。先定位日期、影片／通知 ID、原稿 SHA-256、正式文章與規則版本；完整閱讀保存原稿，獨立分類，再比對正式站與當日流程日誌。人工答案和既有文章不是新事實來源。確認工作區規則及 `pipeline/pipeline.py`、現行 GAS 對應程式，不重建已移除的根目錄 `pipeline.py`。

每檔依次核對：公司身分 → 主體 → 事件日期 → 已完成／指令／建議／條件 → 部位與進場立場 → 可引用原句 → 書面說明。通知優先的是經原文語意核對的事實，不是錯誤解析結果；持股與觀望注意在內容驗收可接受同組，但不允許憑觀望建立交易、成本或回合。

讀 [分類與證據規格](references/evidence.md)：第 1–4 節處理分類與上下文，第 5–6 節處理 AI 裁決與用量，第 8–9 節處理校字與正式更新，第 10 節是管理者逐次的分類裁示（含日期與案例），第 11 節是逐字稿聽錯的名稱樣態。說明怎麼寫交給 `stock-public-writing`；判錯後要改規則、回測、量測變異交給 `stock-rule-tuning`。最新邊界以工作區 `docs/分類裁決基準.md` 的現行條款和程式交叉確認；其早期設計記錄不得蓋過新版條款。

先處理可核實事實，再把有爭議的成交／觀望候選併入既有 AI 批次，原句逐字核對，固定規則決定分類。單檔證據不足隔離本股，其他可發布列續跑；來源指紋失效、原文缺失或整體寫入不一致仍停止正式寫入。不得把「避免整天中斷」解讀為所有錯誤都可忽略。

管理者認可的等價（10/15）：會員持股≈觀望注意、歷史教學回顧≈觀望不碰，兩種結果都算通過，寫進答案檔，不寫成改分類的規則。正式更新用 `apply-rules`（規則分類，答案檔只比對、不通過就不寫入）。

修改規則時同步相依 Prompt／版本／生成片段，`scripts/sync_quality.py` 只覆蓋指定範圍。先離線反例，再按授權做少量真實唯讀重播；模型權重未訓練時稱「回歸樣本」，不稱訓練。正式更新保留備份、人工修正及寄送帳本，讀回結果，交付說明實際測到哪一版。
