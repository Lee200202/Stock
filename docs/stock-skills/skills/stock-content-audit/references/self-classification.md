# 自行分類與沒有答案日期的驗收

適用：管理者要求先讀原稿自行分類、建立較早日期的新答案，或確認未來新稿仍採既有標準。這是 `stock-content-audit` 的工作模式；不另建分類技能，也不授權寫入正式站。與 `evidence.md` 共用六類定義，以下將它落成可填選項與交付格式。

## 1. 舊答案提供標準，不提供新日期的事實

既有 13 天答案是已核對的回歸種子集；它們確認過的主體、日期、否定、部位與證據規則適用沒有答案的新日期，不能因沒有答案就改用較寬或較嚴的門檻。答案日數增加後重新盤點，不把 13 寫成永久上限。

| 可沿用 | 必須為目標日期重新確認 | 不可沿用 |
|---|---|---|
| 六類定義、適用的管理者裁示、已核對反例及當前分類政策 | 本股原句、通知版本、主體、交易日、未全出部位、今日進場立場 | 舊日期某股的分類、價位、持股名單、說明、模型票或核對說明 |
| 「可以買不是已完成買入」「不要殺低不是賣出」等語意原則 | 話是誰說、在說哪一檔、是否換話題、動作是否當天已發生 | 只因股票相同／題材相同就搬舊判定；因新稿少收而湊到舊日檔數 |

查「當時持有」只能用截至目標時點的可靠紀錄。後來的買進／出場不可倒填成目標日事實；目標日文章或錯列衍生的持股回合不能反過來證明該錯列正確。資料缺失記 `unknown`，不冒認已持有或已清倉。

當前管理者定義與已確認的新裁示優先；13 天的早期答案若與新版政策不同，保留原標註版本，重新複核後另記新版結果，不能為了全過靜默改答案。早期持股／注意同組的 accepted 驗收政策按原版本保留；2026/10/21 起已核對未全出部位、當天另有本股分析的注意列，發布應列會員持股。部位未知或未持有仍列注意；不能為新版全過而靜默改舊答案。

## 2. 自行分類的兩個工作選項

| 工作選項 | 何時用 | 必交付 | 能聲稱的結果 |
|---|---|---|---|
| `independent_review` 自行分類 | 任何日期，尤其尚無答案 | 完整候選表、各軸事實、主分類、來源與疑點；凍結後再比流程 | 逐檔來源審核／獨立比對，尚非黃金答案準確率 |
| `golden_draft` 建立候選答案 | 自行分類後要擴充評估集 | 上述資料＋期望集合、排除名單、衝突、審核狀態與政策版本 | AI 初標／待複核答案；有審核憑證後才成核定答案 |

「自己分類」指先根據完整來源作出可核對的判定，不代表改成另一個 AI 重問一次就獲得人工真值。模型初標和同模型自評不能互相證明；爭議案例交獨立覆核或人審。未核定資料不計入已核定準確率。

**網站不是評斷標準。** 正確順序是完整原稿與當時通知／部位 → 獨立判定表與原句 → 凍結版本 → 對照當前工作流／Prompt輸出。網站、郵件及追蹤只查發布結果有沒有一致落地；不得拿它們的現有分類替流程打分，也不因兩者相同就算正確。自行判定表若有身份未定或定義不清，標 unresolved，不強迫納入必收分母；後續修訂另存版本及理由，原版不刪，不按模型結果反向改答案。

若先前已看過目標日分類或管理者給的結果，記 `target_result_exposure=seen`；仍可做來源重核，但不可稱盲分。沒有紀錄則填 `unknown`，不能預設未看過。`independent_review` 是先以來源作判定的工作模式名稱，不自動證明實驗完全無暴露。

執行順序：

1. **載入共用標準**：讀六類定義、已確認裁示及一般化反例；記 `policy_version`。可用 13 天作基準回歸，不能把其中每檔答案貼給新日期當提示答案。
2. **凍結目標來源**：日期、影片 ID、原稿指紋、通知 ID／修訂、部位快照截至時間及完整性。來源缺失或互相矛盾先留疑點，不產生肯定交易。
3. **整篇閱讀及候選盤點**：列出所有明確提及、疑似股名、並列名單、匿名持股及術語撞名；每個候選最後都要有處置，避免只查流程已收的股票而漏掉整檔。
4. **先填事實，後選分類**：按第 3–4 節分開交易、部位、進場立場；每個肯定欄位附來源位置，矛盾語意保留完整前後文。
5. **保存獨立初判**：包含不公開與未定候選，記版本／時間；此時不讀目標日期的既有文章、流程結果或答案標籤來湊一致。
6. **逐檔對照流程**：取候選聯集，列漏收、誤收、標籤差異、部位事實差異與說明支持度；差異回原文解決，不以舊站或模型多數票當真值。
7. **產生候選答案**：有充分證據的列入候選 `must`，有充分證據應排除的列入候選 `must_not`；未定留 `unresolved`，不能當應排除。必要並存標籤與禁止今日交易分別註明。核定後才按當前 loader 格式建立／更新答案檔。

## 3. 每檔必填的事實選項

| 欄位 | 可選值 | 必須核對 |
|---|---|---|
| 公司身分 | `confirmed`／`ambiguous`／`not_a_stock` | 名稱與代號是否同公司；匿名標的有沒有可靠對應，不能只靠價格猜 |
| 主體 | `speaker`／`member_instruction`／`viewer`／`hypothetical`／`unknown` | 觀眾問「我有」不能變成講者持股；會員指令要核對完整原文 |
| 事件時間 | `target_day`／`past`／`future`／`unspecified` | 「今天賣很蠢」的今天不等於宣告賣出；預告與已執行分清 |
| 動作性質 | `completed`／`verified_instruction`／`advice`／`conditional`／`recap`／`none`／`unknown` | 是否已發生，或只是可以買、計畫、提問、假設 |
| 當日事件 | `buy`／`sell_partial`／`sell_full`／`sell_scope_unknown`／`none`／`unknown` | 未知賣出範圍不可當全出；有買又賣可用多個已核對事件項目 |
| 當時部位 | `holding`／`partial_remaining`／`not_holding`／`unknown` | 原句及截至該日紀錄；未有成交紀錄不自動等於沒有持有 |
| 新進場立場 | `positive`／`avoid_now`／`no_current_view`／`unknown` | 肯定／否定針對買還是賣、現在還是未來、本股還是鄰股 |
| 處置狀態 | `decided`／`needs_review`／`excluded` | 不足證據和確定不應公開分開，保留排除／未定原因 |

一檔多段或多筆操作可分成多個 evidence／event 項目，不強迫用單一枚舉抹掉買入後部分賣出等真實情況。每個欄位只有支持到的程度才填，不能因想選某分類倒填事實。

## 4. 主分類選項與不能跨越的界線

| 選項（現行欄位名） | 選擇條件 | 必須擋下的混淆 |
|---|---|---|
| 買入 `buy` | 目標日講者已買，或核實且依產品契約入帳的會員買進執行指令 | 可以買、買點到了、觀眾買過、明天預計買，不宣稱本人今日已成交 |
| 賣出 `sell` | 目標日已賣或經核實的當日賣出執行指令，範圍另記 | 高點賣出者、昨天賣、不該殺低、若跌破再賣都不是今日已賣 |
| 會員持股 `holdings` | 截至當時可靠紀錄未全出，或本股明講仍持有且無後續否定 | 觀眾部位、假設持有、已全出後只回顧，不憑看多建立部位 |
| 觀望注意 `watch_watch` | 有本股現在向前正面看法、可辨認買點或等待條件，且未明講目前不能買 | 純漲跌、點名、通用教學、只說沒有持有、別股的買點不足以收錄 |
| 觀望不碰 `watch_avoid` | 本股現在禁買、不參與、尚未符合條件或不急買回，或原文明確現在風險 | 不准賣不是不准買；既往虧損不是當下禁令；只因曾賣出不能自動列不碰 |
| 不公開（內部處置，非公開第六區） | 僅歷史／行情／名單、非股票、不能確認身分，或無可用現況資訊 | 已出場但另有今日買點仍要評估現況；未定必須另記不能悄悄消失 |

最容易混淆的分界：

- **等待買點 vs 尚不能買**：只給可執行買點或正面等待條件可列注意；同段明講「目前還不行、條件未到、不急買回」則目前是不碰。未來可能變好不覆蓋目前禁令。
- **歷史交易 vs 現況**：先剝離過去的買賣事件，再判斷是否另有本股今日觀點；歷史不固定偏多或偏空，也不新增今天的交易。
- **持有 vs 注意**：按最新發布政策，有截至當時的可靠未全出部位且今天有本股分析，列會員持股；沒有可靠部位只按正面看法列注意。早期同組 accepted 分數需標舊政策，不得混成新版已精確歸類。選持股不代表今天買入。
- **部分出場 vs 全數出場**：同日可有賣出事件與剩餘持股；餘部續抱和已賣部位暫不買回分軸寫，不構成互相矛盾。張數未知就保留未知。
- **來源優先 vs 錯誤解析**：經核對的當日操作來源優先，AI 解析標籤不具有覆蓋原句的權力。買／賣候選附完整原文合批覆核，不逐檔加呼叫；模型票不能代替證據。
- **文體 vs 分類**：錯字或口語交既有 AI 批次審閱；不能用文體字串命中搬動分類。原句、主體、日期、數字、部位及通道核對仍保留。

## 5. 固定交付表與答案格式

先交獨立表，再交比對表；沒有舊答案仍照填，不能把「無答案可比」寫成「品質通過」。

| 日期／代號 | 主體／時間／動作 | 當日事件 | 當時部位 | 進場立場 | 初判分類 | 本股來源位置 | 未定／排除理由 | 比對後差異 |
|---|---|---|---|---|---|---|---|---|
| 目標日／候選代號 | 各軸分開填 | 不預設成交 | 不預設持有 | 不由部位代填 | 可多類並存但需理由 | source ID＋段落／句號 | 沒有也明填無 | 凍結初判後才填 |

機器格式範本（待填，不是任何一天的答案；不得直接導入正式資料）：

```json
{
  "mode": "independent_review",
  "policy_version": null,
  "target_date": null,
  "raw_sha256": null,
  "position_as_of": null,
  "target_result_exposure": "unknown",
  "label_origin": "agent_draft",
  "review_status": "unreviewed",
  "candidates": [
    {
      "candidate_id": null,
      "code": null,
      "identity": "ambiguous",
      "actor": "unknown",
      "event_time": "unspecified",
      "action_type": "unknown",
      "events": [],
      "position": "unknown",
      "entry_stance": "unknown",
      "selected_categories": [],
      "evidence_refs": [],
      "decision_status": "needs_review",
      "unresolved_reason": null,
      "accepted_policy_id": null,
      "allowed_labels_for_scoring": []
    }
  ]
}
```

`selected_categories` 僅用現行 `buy/sell/holdings/watch_watch/watch_avoid`；不公開用狀態與理由表達，不新增公開分類代碼。`allowed_labels_for_scoring` 依管理者既有政策與證據設定，不直接照 AI 初判生成；需要同時存在的類別與可擇一接受的類別分開記，映射現行答案檔的 `required_categories` 與 `must` 時不能混淆。模板只是工作交付格式，未改現行 pipeline 的讀取契約。

每份報告列出候選總數、已決定、確定排除、未定、漏收／誤收／部位事實差異、說明有依據與否。沒有核定標籤時，報來源審核結果與覆蓋率，不捏造準確率。新增答案需記來源指紋、政策、標註者類型、複核憑證與未定名單；未定不得悄悄放進 `must_not`。

## 6. 可直接交給執行 AI 的批次指令

### 管理者指定「先更新今天，再測其他天」時

先做來源審核與正式內容恢復，接著才做跨日評估；不要為等通用模型偶然全過而反覆重寫今天。正式修正的答案來自完整原稿、當日通知與當時部位，不以網站作真值。網站只能提供待改列的身分與舊文字指紋。

可用 `scripts/apply_source_review.py` 的日期計畫，先 `source-review-preview`，核對後才 `source-review-apply`。計畫保存在 `scripts/repairs/日期-source-review.json`，含授權、影片ID、raw SHA、逐筆分類理由、真實引句、舊說明SHA與書面內容。這是具來源的資料修正，不是往分類程式注入答案，也不代表模型已學會。修改已套用的計畫須保留Git版本與前次收據，按新舊資料重新綁定指紋；不把前次預覽當本次正式成功。

該工具保留其他日期與不同來源列，禁止建立新成交；若要移除或更正誤記在當天的歷史交易，另附已核對的主體及實際較早事件日，且原日須已有對應交易。舊投稿列的來源若是本日`MANUAL-日期`而非後來保存的影片ID，先讀回原列，再以逐筆`previous_source_id`、`reviewed_manual_source`及覆核原因指定，不讓分類器取得概括覆寫人工資料的權限。通知列不走此例外。通知優先的是通知原文支持的事實，不能僅看股票代號為數字或字串就推定來源。移除當日錯位分析列不代表應關閉該檔歷史部位。

交付需分列「正式內容已修正」「通用Prompt／規則實驗是否改善」。同稿重播仍有不同錯誤時，不用更多apply換取碰巧成功；保留失敗並回查候選、原文範圍、主體、事件日、比較對象及後置覆蓋。

> 使用 stock-content-audit 的 independent_review 模式。先讀共用六類定義、管理者驗收政策及既有已核對的正反例，再完整閱讀本批目標日期原稿、核實操作原文與截至各目標日的部位紀錄。歷史 13 天答案用於定義與回歸，不把舊股票標籤、價位或後來的部位套給新日期。先不看目標日流程分類，盤點所有候選並逐檔選填公司身分、主體、事件時間、動作性質、當日事件、當時部位、現在進場立場、分類及原句位置；資料不足填 unknown／needs_review，不猜、不湊檔數。保存初判後，再與流程候選聯集逐檔比較，回來源解釋每個差異。買入／賣出候選與有疑點者併同既有批次覆核，格式通過不等於證據通過。文體交 AI 合批整理，數字、單位、方向及本股範圍不得改掉。沒有既有答案仍交完整獨立表、候選答案與未定清單；AI 初標只作候選，核對後才建立評分答案。最後列實際讀了哪些日期、來源、政策版本、已核定／未核定數與模型用量；不寫正式資料或寄送，除非另有適用授權。
