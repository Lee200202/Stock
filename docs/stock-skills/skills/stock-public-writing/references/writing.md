# 書面規格、通道可見性與禁用清單

整理自 2026/09–10/15 的管理者指示與實際出錯紀錄。股票名稱、日期與句子都是當時的案例，用來說明句型；規則以通用句型判斷，不以股名硬編。

## 1. 通道與可見性

| 通道 | 可以出現 | 不可以出現 |
|---|---|---|
| 公開前台（每日總覽、個股、持股追蹤、技術頁、郵件查詢頁） | 分類、書面說明、行情、已核對的技術條件價（「900 以下」）、示意數字（標示示意） | 會員通知的存在與用詞（簡訊、盤中通知、會員通知、即時通知）、通知的成交價、電話、Email、訂閱者 |
| 每日總覽信、每日 LINE | 同公開前台；每檔獨立卡片、分類與說明 | 同上；不寫「依通知」「已通知會員」 |
| 盤中通知（已同意者的 Email／LINE） | 通知原文、完整價位與條件 | 改寫成摘要後冒充原文；切半句 |
| 後台 | 原文全文、解析、寫入的操作、判定歷程、錯誤與待複核 | 用摘要取代原文；為了好看刪掉錯誤狀態 |

- 公開文字只呈現「分類」這個結果，不說明它從哪個私人管道得來。技術頁與版本紀錄講來源時，用「操作紀錄」這類一般說法，保留歷史版本原意（管理者 2026/10/06 選擇「技術說明淡化來源，保留版本歷史」）。
- 移除通知價位後，句子仍要通順可讀。不可留下「在以下買進」「先前已左右相對高點」這種殘字（2026/10/15 嘉澤：「1,980～2,000元左右」的價位拿掉後留下「左右」）。
- 不把所有數字都當私人價位：EPS、均線週期、張數、百分比、漲跌金額、技術關卡價是可以公開的資訊。
- 前台不能讓人訂閱盤中即時通知；可訂閱的只有每日總覽（2026/10/12）。助手回答同樣適用，見 `stock-assistant`。

## 2. 個股說明的結構與長度

順序：**本股結論 → 依據 → 條件或風險**。

- 依據優先序：技術位置（季線、年線、缺口、W 底、突破與回測、MACD／KD 翻紅）、量能（爆量、量縮、最大量 K 棒）、籌碼（外資、投信、大戶持股人數、三大法人）、基本面（EPS、營收年增、獲利預估）、題材（產業、新品、匯率受惠）。
- 條件寫成可核對的條件：「回測季線後再上去」「靠近年線才有較有利的低檔條件」「60 分 K MACD 收斂轉紅且出量才考慮買回」。
- 長度目標：材料足夠時 2–4 句、約 70–160 字。**材料只有一句時可以短**（2026/10/09 力積電：管理者同意材料有限時簡短呈現），不湊字。
- 材料不足時可併入「所屬產業」段落：產業由模型從固定的產業清單裡選（約 60 類，結果存「個股產業」表，可人工指定），不從逐字稿猜；併入時只寫產業層次的看法（「所屬的記憶體族群後續將有一波行情，已持有者不用緊張」），不把別檔的價位、均線或成本寫進本股。
- 會員持股要寫實際持有與已核對的位置；觀望注意／觀望不碰不得寫「續抱」「仍持有」這類當前部位（同時是持股與觀望時兩張卡各寫各的）。
- 歷史回顧類（先前已賣出、現在下跌、拿來當操作教學）可寫「先前已在高檔出場，股價由 1,000 多元回落至 800 多元」，不寫「作為教學回顧」這種說明本身的話。

## 3. 禁用寫法（出現就改寫或拿掉那個子句）

| 類型 | 錯誤樣態 | 改法 |
|---|---|---|
| 口語、語助詞、問句 | 「啊」「對不對？」「你有沒有看到」「崩得亂七八糟」 | 書面語：「隨後大幅下跌」 |
| 人當主詞 | 「張震表示」「老師強調」「分析師點名」「講者認為」「被點名」 | 省略主詞，直接寫事實與條件 |
| 轉述動詞開頭 | 「明確表示現在還不能買」「明言目前叫大家先不要動」「指出追價者…」「宣告從此不再碰」（2026/10/16，講者主詞拿掉後只剩動詞） | 直接寫內容；`_REPORTING_LEAD` 在句首與逗號後拿掉，句中「表示支撐有效」不動 |
| 寫作過程 | 「原稿說」「逐字稿補充的重點是」「依通知」 | 刪掉，直接寫內容 |
| 自稱分類 | 「故列觀望不碰」「作為觀望不碰的標的」「X 列觀望注意。」「作為……的教學回顧」 | 刪掉該子句；整句只剩分類就整句刪 |
| 評語式收尾 | 「展現強勁多頭動能」「值得持續關注」「整體操作邏輯穩健」「具備明確的向上潛力」 | 換成具體位置或條件，沒有就不寫 |
| 未經原文的因果 | 「ETF 買進導致跌停」（原文只是先後發生） | 只有原文講了「因為／所以」才寫因果 |
| 傳聞化 | 「有傳聞指出昨天有人提及台達電要賣了」 | 轉述自己先前的話：「先前已表示……」 |
| 大盤層級子句 | 匯率、電子成交比重、清洗浮額、外資總賣超「1,653 億」、崩盤、中小型股相對強 | 個股說明不寫；大盤條件連同結果一起拿掉（「只要台幣貶值，收進來的東西價值就會越高」整句刪，不留半句） |
| 換句話重講 | 「今天股價上漲。今日股價如預期上漲。」「尚未碰到季線……尚未碰到季線，因此還不能買」 | 後面的子句已被前文涵蓋就刪 |
| 名稱連寫或殘字 | 「貿聯-KYKY」「毅嘉的毅嘉」「今天鴻會上漲」（少一字） | 收成一個正式名稱；補回完整名稱 |
| 代稱開頭 | 「該標的因漲多存在回檔風險」「由於其近期走勢……」 | 改成本股名稱 |
| 借鄰股或錯主詞 | 別檔的成本、MACD、EPS 寫進本股；沒報名字的「這一支」整段寫給前一檔 | 只用本股被點名段落裡的事實；價位要落在本股股價 0.4–2.2 倍內 |
| 半句 | 「該股從1,一路下跌」（千分位被切斷） | 數字整組保留或整組拿掉 |

## 4. 數字、單位與時間

- 千分位與範圍整組處理：「1,615 元」「1,980～2,000 元」「74 到 76 塊」不可切成「1,」「615 元」。
- 單位寫清楚：元、張、%、EPS（元）、億元。「每張至少賺 600 元」照原話保留單位（管理者 2026/10/08 確認）。
- 價位條件寫成「900 以下」「站上 1545」；條件價可以公開，通知成交價不公開。
- 時間一律台灣時間，格式 `2026-10-12 11:09:21`；不出現 `2026-10-12T03:09:21Z`。ISO Z 要加八小時，已是台灣時間的字串不要再加。收盤後的價格標「收盤」。
- 統計括號不要塞在正文：「平均與正報酬比例以回合計：共 30 個已結束的回合」後面不再列「（世芯-KY +8.36%；力積電 +20.47%…）」（2026/10/07，違反不必要資訊）。

## 5. 盤勢①與教學③重點

- 每章約 2–3 點（管理者 2026/10/07：只列一點偏少；看過逐字稿有內容就補上）。實際下限與上限以現行 `canonical_article` 與文章核對程式為準，不恢復舊版 6–10 點。
- 每點要有原文支持；同章與跨章去重：意思相近（只換開頭、沒有新數字或新條件）只留一點，換另一個有內容的重點（2026/10/07 ①有兩點語意相近）。
- 寫成書面重點，不貼長段原話；教學重點要寫出操作邏輯（例如「突破季線後回測季線再上去才是買點」），不是只寫「講解了季線」。

## 6. 每集標題

- 標題 = **本集設定的主題 + 結論**，具體自然，從開場與總結的話找證據。例：「外資創下史上第三大賣超大跌千點，歷史經驗顯示從來不是崩盤！」
- **沒有字數上限**（管理者 2026/10/12）；保留程式的下限與子句數限制（約 15 字以上、最多兩個子句），以現行 `compose_episode_title` 與 GAS `articleTitle_` 為準。
- 不抄提示詞示例、不用招生收尾當主題；用 `titles` 唯讀模式試問已上線日期，逐日重新套用前要確認那幾天沒有其他工作階段在手動整理。

## 7. 介面與技術頁文案

- 精簡：拿掉重複的分類總數、正常狀態下每筆的行情時間、冗長操作提示與實作細節。例：後台「只計 GAS 處理；不含網路、排隊及手機繪圖，紀錄保留 15 分鐘。」「僅後台顯示；列出會員簡訊已寫入之買賣與持股明細，不把待解析原文當成交。」都屬於要刪的說明。
- **精簡不是省略內容**：要呈現的資料必須完整呈現；只刪說明性的贅字（2026/10/06：「精簡格式務必是現有資訊要呈現的所有內容，而非省略東西」）。錯誤、待更新、條件與限制要留著。
- 標籤用最短可懂的字：「目前持有」→「持有」。
- 技術頁：主標可以是問句，子目錄約 6–10 字的具體名詞短語；每章先圖解、文字只補規則與例外；真實數字標來源日期、樣本與單位，示意要標示示意。
- 按鈕文字要對應真的會變化的內容；點了畫面不變的按鈕不放（2026/10/14，見 `stock-site-design`）。

## 8. 程式裡的撰稿與清理順序

依現行 `pipeline/pipeline.py`（函式名稱每次以 `rg -n "def 名稱"` 確認）：

1. 補充說明：`enrich_stock_context`（提示詞 `STOCK_CONTEXT_SYSTEM`，一次合併多檔，逐句以 `source_ids` 對回原句）。
2. 書面化：`polish_public_texts`（提示詞 `PUBLIC_EDIT_SYSTEM`；數字、技術名詞、股名、買賣方向不變才採用）。
3. 清理：`strip_foreign_price_claims`、`strip_implausible_price_claims`（行情帶 0.4–2.2 倍；日 K 快取沒有的股票用上市櫃最近行情）、`strip_guessed_names_and_causes`、`strip_distant_company_names`、`strip_unsupported_time_clauses`、`drop_speaker_sentences`、`strip_macro_clauses`（`strip_macro_text`）、`drop_repeated_clauses`、`strip_leading_conjunctions`、`fill_empty_notes`。
4. 公開呈現：`public_narrative`（`strip_editorial_wrappers`、`_public_subject_fixes`、正式名稱與別名、連寫收斂）、通知列 `public_sms_note`。
5. 會員通知優先的撰稿紀錄：`sms_first_article_records`；通知列說明在寫入階段由 `enrich_sms_notes_from_signals` 用同日原文補寫，同樣經過大盤子句清理。
6. 已核對且原稿指紋、股票、來源、分類都相同的書面說明（答案檔 `reviewed_notes` 綁 `reviewed_notes_sha256`）沿用，避免同一份原稿每次套用都重寫。

## 9. 改寫規則時的驗收

- 先寫最小反例單元測試（`tests/test_regression_MMDD.py`；`tests/` 在 .gitignore，不進版控）。
- **對全部已發布說明回測**：從公開 API 讀 9/29 起每天的說明，套新規則，列出每一則被改動的前後文字；只能動到目標樣態。曾發生的回歸：自稱分類規則把「譜瑞-KY列觀望注意。」改成「譜瑞-KY。」——要整句刪而不是留下股名。
- 套用後逐則讀 `print_public_texts` 的輸出（日誌「觀望注意　X（N 字）：…」行）與正式站讀回，查口語、殘句、借股、重講與大盤子句。
- 答案檔可用 `note_must_not` 列某檔不得出現的說法；寫入後再讀回通知列說明（通知列說明在寫入階段才改寫，寫入前的比對看不到）。
- 模型每次改寫的文字不同：同一天反覆套用只會換一組問題。說明已核對就綁定沿用，局部有錯就局部修，不整天重跑。
