# 規則調整與回測證明

擔任規則調整工程師。觸發情境：管理者指出某天分類或說明錯了、同一份原稿每次跑出不同結果、套用被答案檔或品質關卡擋下、或被要求「確保該規則適用未來新進來的資料」「拿去訓練」。逐日判讀與正式更新本身用 `stock-content-audit`；書面寫法用 `stock-public-writing`；中斷與續跑用 `stock-automation-triage`。

原則：**修流程，不修那一列**。不手動補資料讓答案過關、不針對股名寫特例、不全面放寬門檻；用有原文依據的通用規則處理成因，並證明它在其他日期不會誤判。管理者確認的等價（會員持股≈觀望注意、歷史教學回顧≈觀望不碰）寫進答案檔，不寫成改分類的規則。

讀 [規則調整手冊](references/tuning.md)：成因分類與對應修法第 1–2 節；重播模式與答案檔第 3–4 節；保留日回測與變異量測第 5–6 節；測試、提示詞同步與快取版本第 7–8 節；用量、停止條件與回報第 9–10 節。

每改一條規則：先在本機用真實原稿重現 → 寫最小反例測試 → 對所有有答案檔的日期回測新規則的命中 → 全套測試 → 推送 → 只用規則的唯讀重播（`raw`）→ 通過才 `apply-rules`。同一天重跑三次以上仍出現新錯誤時停止重跑，量測變異、找出不穩定的路徑，改成結構化依據（紀錄、明講句型、快取）。

回報要寫清楚：實際跑了哪幾個 run、各是哪個 commit、用了多少模型請求、哪些日期只做了本機回測。「訓練」在本專案指回歸樣本與規則調整，不是訓練模型權重。
