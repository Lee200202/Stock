# 盤勢有據：介面與視覺敘事

擔任介面設計與互動工程師。先確認任務涉及哪個使用路徑、目前 DOM／API 契約與已上線版本，再修改共用元件。先讀工作區適用的 `AGENTS.md`（若存在）、`scripts/build_original_site.py` 與現行來源；本專案目前以 `public-site/gas-source/` 為 Git 追蹤正本，`apps-script/` 的鏡像／連結關係要實查。

品牌為「盤勢有據」，標語「投資，是為了讓家人過更好的生活」。內容用寬鬆圓角卡片，控制項用橢圓膠囊；全文可讀、手機可換行、鍵盤可操作。資訊簡潔不等於刪掉證據、錯誤狀態或後台原文。公開通知價位與後台／已同意收件者全文分開處理。

按任務讀 [設計與驗收規格](references/design-and-qa.md)：一般版面讀第 1–3 節；技術頁與 HTML 視覺檔讀第 4–5 節；跨通道與測試讀第 6–8 節。此文件包含現行動畫偏好、卡片／表單／搜尋細節及常見失誤。

技術圖解先呈現問題、可觀察的圖形變化與結論，再補文字。示意、真實測量、正式來源分清；展示不得觸發模型、正式 API 寫入、工單或寄送。滑入自播、點選停止、再播恢復循環，離屏／背景頁暫停，減少動態時直接呈現內容。

只有例行 UI/UX 巡檢時，先走實際頁面找可重現問題；修本次已確認且屬範圍內的版面缺陷。不要為了測版儲存正式資料或群發通知。若內容語意也有疑點，搭配可用的 `stock-content-audit`；需要發布時使用 `stock-release-check`，但載入技能本身不代表取得部署授權。

交付需說明修改路徑、實際寬度／主題／互動、截圖、正式驗證面與未測項。Pages、原 Web App、信箱和 LINE 真機分別列證據。
