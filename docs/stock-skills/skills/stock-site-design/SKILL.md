# 盤勢有據：介面與視覺敘事

擔任介面設計與互動工程師。先確認任務涉及哪個使用路徑、目前 DOM／API 契約與已上線版本，再修改共用元件。先讀工作區適用的 `AGENTS.md`（若存在）、`scripts/build_original_site.py` 與現行來源；本專案目前以 `public-site/gas-source/` 為 Git 追蹤正本，`apps-script/` 的鏡像／連結關係要實查。

品牌為「盤勢有據」，標語「投資，是為了讓家人過更好的生活」。內容用寬鬆圓角卡片，控制項用橢圓膠囊；全文可讀、手機可換行、鍵盤可操作。資訊簡潔不等於刪掉證據、錯誤狀態或後台原文。公開通知價位與後台／已同意收件者全文分開處理。

按任務讀 [設計與驗收規格](references/design-and-qa.md)：一般版面讀第 1–3 節；技術頁與 HTML 視覺檔讀第 4–5 節；跨通道與測試讀第 6–8 節；管理者逐次確認的版面裁示（含日期）讀第 9 節；「只改被要求的部分」與管理者實際設定的驗收寬度讀第 10 節；按鈕互動、群組自播與 GAS 巢狀 include 陷阱讀第 11 節；定義、篩選、判定、狀態類內容要畫成哪種圖讀第 12 節；元件一致性（來源卡、選項膠囊）與 `auto-fit 1fr` 把卡片拉大的陷阱讀第 13 節；「全站逐一章節驗收」的程序讀第 14 節。介面文案的用字交給 `stock-public-writing`，網站助理對話框的後端交給 `stock-assistant`。

依已授權範圍修改；管理者已要求全站改善或全版重設時，直接處理可重現問題，不重問同一授權。窄任務不要順手改不相關尺寸與配色。自製按鈕、切換與選單保留原生語意、鍵盤、焦點及狀態；寬版沿用各分頁共用容器與設定，不讓使用分析另起超寬欄。具體做法及量測讀 [寬版、控制項與資訊層次](references/design-and-qa.md)。驗收包含管理者設定（1916×857、`data-w="w"`、`data-fs="l"`／`"x"`）、1440、390；受影響手機最窄設定亦檢查。

技術圖解先呈現問題、可觀察的圖形變化與結論，再補文字。定義、篩選、判定與狀態轉移一律先畫圖並加動畫，卡片只用在清單類內容；同一種用途只用一種元件：來源連結一律用來源卡、不放底線文字連結，情境切換沿用相鄰章節的選項膠囊，不另起縮小變體。示意、真實測量、正式來源分清；展示不得觸發模型、正式 API 寫入、工單或寄送。滑入自播、點選停止、再播恢復循環，離屏／背景頁暫停，減少動態時直接呈現內容。

上述循環是技術說明圖解的偏好，統計圖依資料及互動需求設計，不強制循環閃動。使用分析先顯示數字、同期趨勢與分群，定義按需查看；必要分母、時間範圍、缺值與過期狀態仍可辨識。改版效果的 A/B 方法見 `stock-rule-tuning` 的 `references/evaluation.md`：截圖漂亮、停留變長或多點一次，不等於可用性或內容品質提升。

只有例行 UI/UX 巡檢時，先走實際頁面找可重現問題；修本次已確認且屬範圍內的版面缺陷。不要為了測版儲存正式資料或群發通知。若內容語意也有疑點，搭配可用的 `stock-content-audit`；需要發布時使用 `stock-release-check`，但載入技能本身不代表取得部署授權。

交付需說明修改路徑、實際寬度／主題／互動、截圖、正式驗證面與未測項。Pages、原 Web App、信箱和 LINE 真機分別列證據。
