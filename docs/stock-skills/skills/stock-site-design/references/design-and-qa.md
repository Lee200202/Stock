# 設計、圖解與跨通道驗收

## 1. 視覺語言與內容密度

- 先使用現行主題、字級、間距與圓角變數，再調整個別元件。卡片大圓角、表單／按鈕膠囊，不把所有主容器硬改成 999px。歷史 `--wrapmax:1320px` 等值是查證起點，不是永遠固定值。
- 內容預設一張一列、占滿內容欄；多欄須有比較價值，手機回到單欄。不得留下無用途的置中窄欄、巨大留白，或把表單擠在卡片左半。
- 正文以約 16–17px 為起點，次要文字通常至少 13–14px；依現行字體設定縮放，不用固定小字抵消使用者選擇。行高依密度約 1.7–1.95，避免全站一律拉到 2 倍反而過長。內距、卡距優先沿用變數，必要時以約 20–28px／16–24px 起調。
- 繁中不以 `text-align:justify`、過大 `word-spacing` 或強制斷行填滿整列；測最後一行只有一兩字、標點孤行與長股名。短標籤可不拆字，長段落必須正常換行。
- 主按鈕約 48–52px，其他可操作區至少 44×44px；圖示按鈕有名稱、焦點及可用的點擊範圍。不要把靜態標籤也強制放大成主按鈕。
- 買入／上漲紅、賣出／下跌綠、持股紫、注意藍系、不碰琥珀；依現行主題調色且搭配文字／圖示，不用顏色單獨決定意義。
- 資訊簡潔：保留「結論、必要條件、例外、可執行動作」，拿掉重複分類總數、正常狀態的行情時間、冗長操作提示和實作細節。過期／失敗提示與來源時間仍保存在資料、必要提示或詳細資訊，不可連檢查邏輯一起刪掉。
- 不用省略號、固定高度裁切或不可展開的摘要取代完整說明。技術細節可展開，必要結論須直接看見。

## 3. 價位與完整內容

公開會員通知依現行產品遮蔽私人通知價位；後台原文與已同意接收盤中通知者的 Email／LINE 保留完整原文。不可拿操作摘要代替原文，或因全句含價位就刪成空白。核對千分位、範圍、條件方向；EPS、均線週期、張數、百分比不是一律遮蔽的成交價。

不要擅自新增「付費解鎖」徽章、目標價推薦或股價高低階級。有意義的技術條件數字可保留；持股績效計價另依行情技能核對。禁止僅靠正規表達式把每個數字都變彩色價位標籤。

## 4. 技術說明的故事與圖像

沿用現行章節 ID、目錄、四幕／閱讀模式；改章節順序時同步預告、進度、前後章與相容錨點。子目錄用約 6–10 字具體名詞短語，主標可用問句。直接跳章也應理解問題與結論。

每章以「讀者問題 → 操作選擇 → 依據圖像 → 結果」建立一條故事。可用：

| 想說明 | 優先圖像 | 必須看見的變化 |
|---|---|---|
| 多來源優先順序 | 來源卡＋合流箭頭＋獨立部位／立場結果 | 先通知後影片、部分賣出、可買建議得到不同結果 |
| 分類定義 | 誰／何日／動作／結果四格，配正反例 | 提問不當持有、不要殺低不當賣出 |
| 裁決 | 票卡、有效證據勾叉、1／2／3 票路徑 | 無效票不算；單檔隔離；三輪不是三位獨立專家 |
| 讀稿與工具 | 輸入片段、工具回應、核對與狀態流 | 模型不能憑文字宣稱工具成功；工具結果需讀回 |
| 速度改善 | 同尺度秒數橫條、快取命中／未命中路徑 | 實測慢條晚到，能再播；不是只輪流亮字卡 |
| 原稿與續跑 | 指紋、完成片段、檢查點時間線 | 換稿使哪些結果失效、哪段可沿用 |
| 回合與價格 | 日期滑桿、開／平倉標記、兩端價位 | 部分賣出不關整檔，回顧不產生當日成交 |

文字只補規則、例外與資料限制，不再用四張長文字卡冒充圖解。需要數字時列來源日期、樣本數、單位、量測起終點；示意明示虛構。Tokenizer 編號／切詞未實測就標示意；模型容量、實際 token 用量、每日請求數及價格分開計算，不能拿中文字數直接當 token。模型名稱與官方規格須按目前程式、run 及官方文件重新核對。

## 5. 動畫與獨立 HTML 檔

- 本次累積偏好為「進入可視範圍自動播放，持續循環；使用者點選該模組後停止；再播恢復循環」。只暫停該模組，不改其他模組。離屏、分頁隱藏暫停；回來時尊重手動停止狀態。
- 減少動態模式不自播，圖形及規則仍完整可讀；沒有 JavaScript 時關鍵內容仍存在。不要把內容預設透明等捲動才顯示。
- 優先 transform／opacity，避免 width／left 連續重排；不做干擾閱讀的視差或無意義彈跳。流程動畫要與目前選項、數字、文字結果一致。
- 純情境選擇用原生 button；若真的採 tabs 才實作相應焦點與鍵盤模式。範圍滑桿、展開細節、播放皆需鍵盤操作。
- 展示全部本機執行；測切換／循環時網路請求不得增加，不能啟動取稿、模型或發信。
- 使用者要求可分享 HTML 視覺規格時，建立可單獨開啟、樣式與腳本自足、無私人資料／金鑰的檔案；圖表以 HTML／SVG／CSS 為主，含導覽、重點與詳細規格、深淺色、手機版。若是測量圖，提供可追溯原始樣本，不編造提升比例。

### 解釋 AI 底層時的內容邊界

使用「一句輸入經 tokenizer 變 token ID／向量與位置資訊 → 模型逐步產生 token 或工具請求 → harness 執行工具 → 工具結果加入下一次模型輸入 → 程式核對及寫入」圖像。模型本身不直接接觸檔案／試算表，不把安裝 skills 當作全部原理。

context window 是單次請求可容納內容的容量限制；tokenization 的 token 不等於一個中文字。輸入、輸出、系統規則、工具結果及保留給推理／輸出的預算按模型實際 API 定義核對；不能用當日所有請求總 token 除 context capacity 稱「已占容量」。實際容量及定價只引用當前官方規格。

用專案實際流程說明 harness：讀來源、建立候選、呼叫模型、驗 JSON 及原句、保存檢查點、使用工具讀回。分清「本程式實作了什麼」和「通用概念示意」；不要宣稱本站從零訓練模型、自己重做 Claude Code 或只靠更便宜模型就能無條件替換。替換模型須測 structured output、工具介面、上下文、證據品質與成本，而非改一個名稱就保證相同。

## 6. 郵件與 LINE

Email 用相容的 presentation tables 和 inline style；每檔獨立圓角卡、實體間隔、名稱／立場與正文分層。通知完成、訂閱更新、管理連結也對齊圓角與觸控區；深色查詢頁另用主題覆寫。不要宣稱所有 Outlook 版本百分之百支援圓角。

LINE 已有整合，先讀目前 `Line.gs`、relay 和佇列，不新增第二套寄送。卡片分段依官方現行大小上限核對；超量明示並連到有權查看的完整頁，不切半句。改格式保留綁定、同意與帳本。

## 7. 驗收矩陣

實際檢查 1440／1280／768／390／360px、深淺色、字級放大、長股名／長文、載入／空白／錯誤、鍵盤、減少動態。量 `innerWidth` 與頁面寬度，不能只信工具要求的 viewport。驗證無整頁橫捲、浮層不擋關鍵內容、按鈕至少 44px。

本專案候選腳本：`check_tech_story.py`、`check_class_definitions.py`、`check_tech_autoplay.py`、`check_centered_top.py`、`check_admin_layout.py`、`check_stock_search.py`；先查腳本是否存在、CLI 參數和現行 DOM，按改動選測。舊 `preview_v101*` 不一定仍是有效關卡。真實瀏覽器要操作同一流程；離線通過不代表正式站、Gmail 或 LINE 真機已驗。

## 8. 常見誤修與完成定義

避免：只改本機鏡像；移除資料鉤子；用全域 CSS 放大導致卡片爆版；把內文均線數字當私人價位；移除正常行情時間時也刪新鮮度判斷；影片／圖解在切換後仍顯示上一選項；再播只播一輪；測試主題鍵用錯而兩次其實都淺色。

完成需有受影響畫面的實際操作與截圖、寬度／主題／狀態、測試及發布面證據。若原 `/exec` 在瀏覽器只見 Google 錯誤，獨立列出；Pages 視覺通過加上來源一致，不等於原 Web App 已成功渲染。

## 10. 只改被要求的部分（10/14 教訓）

- 驗收要在管理者自己的設定下截圖：1916×857、`html[data-w="w"]`（寬版 1700px；`x` 為 2000px、`m` 1400px、`n` 1100px）、`html[data-fs="l"|"x"]`（字級 1.25／1.5 倍；`s` .92、`m` 1），加上 1440 與 390。浮動元件（右側目錄）的位置要由實際內容邊界計算，不能假設內容寬 1320px（v181r2 的目錄在寬版大字時蓋住正文）。
- 不要順手改卡片樣式、字級、配色；沒有被要求的視覺改動要先提案。

## 11. 互動與自播的實作細節

- 每個圖解按鈕都要讓使用者眼前的圖解本身有可見變化（換圖、換路徑、換結果卡），不能只改收合的「展開這一章」細節裡的文字。新增按鈕時在 `audit_story_choices.py` 能測出變化；全站按鈕用 `audit_site_buttons.py`（假 API，會略過已選中與需要後端的按鈕）。
- 自播以「群組」為單位：使用者點了某一組，只停那一組（`StoryDesign.html` 的 `userTook`），其他組繼續；舊播放器（`legacyPlayers`）是否被使用者停住由 `legacyHeld` 判斷，不能因一處停止讓整頁都停。
- 「播放一次」類按鈕：進入畫面自動執行，執行完循環；使用者按了就停在使用者的選擇。
- GAS 的 `include()` 是 `createHtmlOutputFromFile(...).getContent()`，**不會執行巢狀的 `<?!= include() ?>`**：被 include 的檔案裡再 include 另一個檔案，在 Pages 版正常、在 `/exec` 版會原樣輸出模板標籤或缺內容。共用片段（如 `StoryDesign`）要直接從 `Index.html` include；`scripts/check_original_parity.py` 有這個檢查。
- Pages 版由 `scripts/build_original_site.py` 從同一份 GAS 正本產生；兩邊顯示不一致時先查 include 與建置腳本，再查 `/exec` 版本。
