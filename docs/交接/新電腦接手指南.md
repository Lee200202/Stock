## 二、安裝（Windows PowerShell，依序）

1. 工具：

```powershell
winget install --id Git.Git -e
winget install --id Python.Python.3.11 -e
winget install --id OpenJS.NodeJS.LTS -e
```

   - Python 用 3.11，和 GitHub Actions 相同。裝完重開 PowerShell。
   - Claude 桌面版從 claude.ai 下載，用管理者指定的訂閱帳號登入。用 Codex 的話照 Codex 官方說明安裝。

2. 取 repo 與套件：

```powershell
git clone https://github.com/Lee200202/Stock.git "$HOME\Stock"
cd "$HOME\Stock"
python -m pip install -r requirements.txt
cmd /c mklink /J apps-script public-site\gas-source
```

   - 最後一行建 `apps-script` 連結，`scripts/sync_quality.py` 需要它。

3. 技能：

```powershell
python scripts\build_stock_skill_handbook.py --install
git checkout -- docs/stock-skills/index.html
New-Item -ItemType Directory -Force "$HOME\.claude\skills" | Out-Null
Copy-Item docs\stock-skills\skills\* "$HOME\.claude\skills\" -Recurse -Force
```

   - 第一行把 10 個技能裝到 Codex（`~/.codex/skills`）。它會順便重建 `index.html`，只差換行，所以第二行還原。
   - 後兩行給 Claude Code 用（`~/.claude/skills`）。
   - 技能正本永遠是 `docs/stock-skills/skills/`。改技能先改正本，再重跑這一步。

4. 私人同步庫（記憶與本機技能）：

```powershell
git clone https://github.com/Lee200202/stock-private-sync.git "$HOME\stock-private-sync"
powershell -ExecutionPolicy Bypass -File "$HOME\stock-private-sync\link-memory.ps1" -StockPath "$HOME\Stock"
Copy-Item "$HOME\stock-private-sync\codex-skills\*" "$HOME\.claude\skills\" -Recurse -Force
```

   - `link-memory.ps1` 把 `~/.claude/projects/<專案資料夾名>/memory` 連到該 repo 的 `claude-memory/`。原本的記憶資料夾會先改名備份。
   - 資料夾名由 Stock 的完整路徑換算，把 `:`、`\` 換成 `-`，例如 `C:\Users\amy\Stock` → `C--Users-amy-Stock`。

5. 部署工具（要碰 Apps Script 時才需要）：

```powershell
npm i -g @google/clasp
clasp login
```

   - 用有權限的 Google 帳號登入。協作帳號可推 HEAD、建版本，只有擁有者能切換正式 `/exec`。

6. 驗收：

```powershell
python scripts\build_stock_skill_handbook.py --check-installed
python scripts\run_offline_contracts.py
git log -1 --oneline
```

   - 第一行要印 `Installed skill files match`；第二行離線契約全過。

## 三、接手的 AI 照這個順序讀

1. `AGENTS.md`（Claude Code 與 Codex 都會自動載入）。
2. `docs/雲端排程/雲端排程總覽.md` 第九節的交付清單，從第 2 項讀下去。
3. 記憶索引 `MEMORY.md`（連好私人同步庫後由 Claude Code 自動載入）。

## 四、兩台電腦一起工作的規則

- **GitHub 是唯一交換點**：開工前 `git pull`；完成一段就推分支。兩台不要同時改同一個檔。
- **記憶靠私人同步庫**：開工前、收工後各跑一次 `powershell -ExecutionPolicy Bypass -File "$HOME\stock-private-sync\sync.ps1"`。它會拉下另一台的修改，再推上這台的修改；不跑就不會同步。
- 新的裁示仍要寫進公開 repo（`docs/daily-review/裁示紀錄.md`、`docs/分類裁決基準.md` 或負責的技能）。雲端排程只讀得到公開 repo，記憶只是輔助。
- **雲端排程只有一份**，在目前的訂閱帳號上。不要在另一個帳號再建一份，否則會重複暫停寄信、重複推分支。
- 正式資料寫入、部署、寄信的授權規則和舊電腦相同（交接規範第六、八節）。
