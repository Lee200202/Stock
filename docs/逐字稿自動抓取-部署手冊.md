## 零、逐字稿怎麼來的

| | |
| --- | --- |
| 這個頻道的影片有沒有字幕 | **沒有**，連 YouTube 自動產生的都沒有 |
| 所以 | 任何靠抓字幕的工具都取不到逐字稿 |
| 做法 | Gemini API 直接讀公開的 YouTube 網址，模型自己「聽」聲音聽打 |

不需要字幕、不需要下載影片、不需要瀏覽器。

## 一、整體架構

```
YouTube 直播 ──► transcript.py ──► 試算表「影片清單」──► pipeline.py ──► Apps Script ──► 網站／郵件
  11:01~11:19    Gemini 聽打        原始逐字稿內容欄      潤飾、擷取       渲染、寄信
   回放+3~5分    （這份手冊）       （唯一交換介面）
```

`transcript.py` 只負責把「日期 + 逐字稿」放進試算表就結束。
後面每一步維持原樣，由 `daily.yml` 的 `pipeline.py` 與下游 Apps Script 接手
——它們本來就會去讀「原始逐字稿內容」欄，**`pipeline.py` 一行都不用改**。

## 二、兩套機制與「手動優先」

「影片清單」有一欄 **`逐字稿來源`**：

| 值 | 誰寫的 | 自動抓取的行為 |
| --- | --- | --- |
| `手動` | 人貼的 | **完全停手**，不覆蓋、不重抓 |
| `手動保留` | 人宣告「今天我自己貼」，還沒貼 | **完全停手**，等人 |
| `自動` | `transcript.py` 抓的 | 已有稿就不重抓 |
| （空白）且已有原文 | 舊資料 | **視同手動**，停手 |

最後一列是刻意的。這一欄是後來才加的，在它之前試算表裡所有原文都是人貼的；
把「沒標來源」當成自動，就等於允許機器覆蓋人工成果——那是這支程式唯一
真正不可逆的傷害。

這一欄**不必手動新增**，程式與 Apps Script 的 `ensureHeaders_` 都會自動補在最後面。

**手動輸入三條路，都會讓自動化停手：**

1. 直接在試算表「影片清單」把逐字稿貼進「原始逐字稿內容」欄（最快）
2. 網站後台「投稿逐字稿」（已改成同時標記 `手動`）
3. `python transcript.py manual --file 稿.txt`

判斷順序上，手動優先排在**最前面**——在查 YouTube、呼叫 Gemini 之前就先擋掉，
所以已經貼好稿的日子一毛額度都不會花。

## 三、要準備的四把鑰匙

| 名稱 | 去哪拿 | 會過期嗎 | 必要 |
| --- | --- | --- | --- |
| `GEMINI_API_KEY` | **AI Studio**（不是 Cloud Console） | 不會 | ✅ |
| `YOUTUBE_API_KEY` | Cloud Console | 不會 | ✅ |
| `GOOGLE_SHEETS_SERVICE_ACCOUNT` | Cloud Console | 不會 | ✅ |
| `SPREADSHEET_ID` | 試算表網址 | — | ✅ |

> 全部都不會過期。這一版沒有任何需要定期維護的憑證。

### 3-1　Gemini 金鑰（AI Studio）

1. 用**個人 Gmail** 登入 <https://aistudio.google.com/apikey>
   （學校／公司的 Google Workspace 帳號常被管理員禁用 AI Studio）
2. 按「建立 API 金鑰」。第一次會自動幫你建一個專案
3. 複製那串，就是 `GEMINI_API_KEY`

**建議多拿幾把。** 免費額度是「每把金鑰 × 每個模型」分開算的，
一集 57～70 分鐘會切成 2～3 段送出，多備幾把就不會卡在額度上。
用不同 Google 帳號各建一把，填法：

```
GEMINI_API_KEY=第一把,第二把,第三把
```

或另外設 `GEMINI_API_KEY_2`、`GEMINI_API_KEY_3`。兩種可以混用，程式會自動去重。

### 3-2　YouTube 金鑰（Cloud Console）

<https://console.cloud.google.com/> → 「API 和服務」→「程式庫」，啟用：

- **YouTube Data API v3**
- **Google Sheets API**
- **Google Drive API**

然後「憑證」→「建立憑證」→「**API 金鑰**」，建好後按「編輯」限制它：

- 應用程式限制：`無`（GitHub 的 IP 每次不同，設 IP 限制會擋到自己）
- API 限制：只勾 **YouTube Data API v3**

> **這把不能省。** 判斷「直播結束了沒、回放處理好了沒」要靠 `videos` 端點的
> `liveStreamingDetails` 與片長。RSS 拿不到這些，所以沒有金鑰時程式會
> **明確拒絕硬猜**，而不是送一份可能只有半截的東西給 Gemini。

配額：一天 10,000 units，本流程一輪約 3 units，用不到零頭。

### 3-3　服務帳號（Cloud Console）

1. 「憑證」→「建立憑證」→「**服務帳戶**」，名稱隨意，角色不用給
2. 點進去 →「金鑰」→「新增金鑰」→「建立新的金鑰」→ **JSON**
3. **這份檔案沒有第二次下載機會**
4. 記下信箱，長得像 `xxx@專案名.iam.gserviceaccount.com`

### 3-4　把試算表分享給服務帳號

試算表 →「共用」→ 貼上那個 `...iam.gserviceaccount.com` → 權限選「**編輯者**」。

漏了這步會停在 `開不了試算表（HTTP 403）`，錯誤訊息會把該分享的信箱印出來。

### 3-5　試算表 ID

```
https://docs.google.com/spreadsheets/d/【這一段就是 SPREADSHEET_ID】/edit
```

## 五之三、休市日怎麼維護

清單來自證交所「有價證券集中交易市場開（休）市日期」，目前收錄 **2026 年 24 天**。

**每年年底證交所公布次年行事曆之後**，跑一次：

```bash
python scripts/update_holidays.py
```

它會同時覆寫 `market_holidays.py` 與 `apps-script/Holidays.gs`，然後把
Python 推上 GitHub、`Holidays.gs` 重新貼進 Apps Script。次年還沒公布時它會
自己略過，不會寫壞既有資料。

> **沒收錄的年份一律當成交易日**，並在日誌印一行提醒。
> 反過來做（當成休市）會讓整年排程安靜停擺，而且沒有任何錯誤訊息；
> 多跑一天的代價只是一次空跑，兩者不對等。

最近會用到的：**2026/09/25（中秋）與 2026/09/28（教師節）都休市**，
這兩天排程會直接返回，不會空跑也不會寄假的「今日無影片」。

## 六、排程

| 觸發點（台灣） | UTC cron |
| --- | --- |
| 11:05、11:30、11:55 | `5,30,55 3 * * 1-5` |
| 12:20、12:45 | `20,45 4 * * 1-5` |
| 13:10、13:35 | `10,35 5 * * 1-5` |

間隔固定 25 分鐘，剛好接上內部輪詢的時間預算，一棒接一棒不留空隙。

**起點為什麼是 11:05。** 實測最近五集「進入頻道清單」的時間是
11:15、11:07、11:04、11:24、11:18——影片在直播**結束時**才進清單，不是開播時。
早收的日子 11:07 就抓得到，用 11:20 起跑會白等十幾分鐘。
提早的代價幾乎是零：影片還沒出現時只用 YouTube API 問一句（約 2 units），
不呼叫 Gemini；撞到直播中也只會回報「直播中」然後等下一輪。

> **改 cron 時 `POLL_START` 要一起改。** 只改 cron 的話，提早觸發的那一輪
> 會停在「現在 11:05，還沒到 11:20，不執行」而空轉——看起來有跑，其實什麼都沒做。
> 有測試在驗這兩者一致。

cron 只負責把程式叫起來，進去之後自己每 3 分鐘敲一次，約 25 分鐘收工交給下一次接力。
GitHub 的 cron 是 best effort，尖峰會漏跑或延遲十幾分鐘，所以輪詢要自己做。

**多數日子在 11:05～11:30 那兩三輪就抓到了。**
前面幾輪回報「直播中」或「回放處理中」是正常的。

可用環境變數覆寫：

| 變數 | 預設 | 意思 |
| --- | --- | --- |
| `POLL_START` / `POLL_UNTIL` | `11:05` / `14:00` | 探詢時段 |
| `POLL_INTERVAL_SEC` | `180` | 每幾秒敲一次 |
| `TIME_BUDGET_SEC` | `1500` | 單次 job 最多跑幾秒 |
| `READY_DELAY_MINUTES` | `5` | 直播結束後等幾分鐘才送出 |
| `SEGMENT_MINUTES` | `30` | 每段幾分鐘。一集切 2～3 段 |
| `VIDEO_FPS` | `0` | 0＝不指定。實測指定 fps 有些片段會一直回 400 |

## 九、出問題時

| 日誌訊息 | 意思與處置 |
| --- | --- |
| `開不了試算表（HTTP 403）` | 試算表沒分享給服務帳號。信箱在錯誤訊息裡 |
| `只能用 RSS，查不到片長與直播結束時間` | 缺 `YOUTUBE_API_KEY`。程式拒絕硬猜，補上金鑰即可 |
| `還沒好：直播中` | 正常，還沒播完 |
| `還沒好：直播已結束，YouTube 回放處理中` | 正常，等下一輪（通常 3～5 分鐘） |
| `還沒好：回放剛好，等滿 5 分鐘緩衝` | 正常，太早送過去會拿到半截 |
| `負載過高（...high demand...），改用 <備援模型>` | 正常的自動處理，不必管 |
| `所有模型目前都負載過高` | 正常，等下一輪。已完成的片段會保留，下一輪只補沒做完的 |
| `::error::Gemini 額度用完` | 退出碼 2。等重置（太平洋時間午夜，約台灣下午 3～4 點）、補金鑰，或加一個 `GEMINI_FALLBACK_MODEL` |
| `金鑰無效或沒有權限（HTTP 401/403）` | 金鑰打錯，或那個帳號不能用 AI Studio（學校帳號常見） |
| `輸出被截斷，切成兩段重做` | 正常的自動處理，不必管 |
| `API 不接受 fps=...，之後所有片段改用預設取樣` | 正常的自動降級 |
| `注意：只有 N 字，對一小時的直播而言偏短` | 收下了，但請抽查是不是完整的一份 |
| `第 3 欄是「X」，與預期的「標題」不同` | 試算表表頭被改過，程式拒絕自動補欄，請人工核對 |

**退出碼**：`0` 有進展或沒事做（含「回放還沒好」）、`1` 真的失敗、`2` Gemini 額度用完。
只有 1 和 2 會亮紅燈——「還沒好」是常態，不該每天發假告警。

### 模型負載過高（2026/09/17 的教訓）

那次的日誌是這樣的：

```
Gemini 轉錄 0:00:00–0:30:00（第 1 次，金鑰 #1）
  失敗：'gemini-3.5-flash-lite is currently experiencing high demand...'
金鑰 #1 失敗，馬上改用金鑰 #2 重送
  失敗：同一個錯誤
所有金鑰這一輪都失敗，30 秒後重新送出
  ...重試 4 次仍失敗，耗時 11 分鐘，整集放棄
```

問題在於 **`high demand` 是模型層級的壅塞，不是金鑰層級的**。
所有金鑰共用同一份模型容量，換金鑰不可能有用，只是把時間燒掉。

現在的處理：

| 失敗類型 | 反應 |
| --- | --- |
| **負載過高**（high demand / 503 / overloaded） | **立刻換模型**，不換金鑰 |
| 額度用完（429 / 每日額度） | 換金鑰；全用完就換模型（額度每個模型分開算） |
| 其他可重試（400 / 逾時 / 連線） | 換金鑰重送 |
| 401 / 404 / 非額度的 403 | 直接失敗，重試沒有用 |

另外三個配套：

1. **所有模型都在忙 → 判成「還沒好」，不是失敗。** 交給輪詢迴圈三分鐘後重試，
   工作也不會亮紅燈。這是 Google 端的暫時壅塞，等一下往往就好了。
2. **已完成的片段會留著。** 一集切 2～3 段，第 1 段成功、第 2 段撞上壅塞時，
   下一輪只補沒做完的那幾段，不會整集重做。
3. **快速檢查逾時也算壅塞。** 連 16 個 token 都回不了代表整個服務在塞，
   那要換模型，而不是判定「這把金鑰不行」然後繼續在同一個塞住的模型上輪金鑰。
   逾時門檻也從 20 秒放寬到 30 秒（`KEY_PROBE_TIMEOUT_SECONDS` 可調）。

> 順帶一提：快速檢查**通過不代表大請求會成功**。小文字請求幾乎不佔容量，
> 模型忙不過來時它照樣 0.7 秒回 OK，接著同一把金鑰送 30 分鐘影片就失敗。
> 那次日誌裡「金鑰 #1 快速檢查通過（0.7 秒）」後面緊接著 high demand，就是這個原因。

## 十、跟 daily.yml 的關係

兩個工作流程互不干擾，concurrency 群組不同。

- `transcript-gemini`（這一份）：把逐字稿放進試算表
- `daily-transcript-pipeline`（既有）：讀試算表的逐字稿，做後面全部的事

`pipeline.py` 的 `stage_transcript()` 目前行為是「沒有原文就回報等待中，綠燈結束」。
所以逐字稿一寫進去，`daily.yml` 下一個觸發點就會自動接著跑完潤飾、擷取、
寫網站、寄信——**`pipeline.py` 一行都不用改**。
