# 初步部署包：2026-09-10-evidence-v2

這是可部署的初步修正版。已通過 Python 載入／編譯、37 項離線回歸測試，以及 18 組 Apps Script／前端程式語法檢查。
尚未使用正式 Gemini 金鑰執行完整逐字稿判讀，也尚未部署到您的 Google Apps Script／GitHub，不能把離線測試視為線上分類品質保證。

## 一、先更新 Apps Script

1. 先備份目前 Google 試算表與 Apps Script 版本，保留可回復的資料。
2. 解壓縮本部署包。開啟目前網站對應的 Apps Script 專案。
3. 將 apps-script 資料夾內的每個 .gs、.html 檔案，依相同名稱完整覆蓋專案內的同名檔案。不要只貼新的 prompt。
4. 如果沒有 Articlequality.gs 或 Evidencequality.gs，請新增這兩個「指令碼」檔案，再貼入對應內容。Articlequality.gs 是這次新增、不能漏掉的檔案。
5. 保留原專案的指令碼屬性、試算表 ID、部署權限與既有金鑰，不必重建試算表或重新執行初始化。
6. 儲存後，選擇右上角「部署」→「管理部署作業」→ 選目前 /exec 網址對應的部署 → 鉛筆編輯 → 版本選「新版本」→「部署」。使用原部署即可保留原網址；只按儲存不會更新已發布網站。
7. 新版 Code.gs 的 GAS_BUILD 必須是 2026-09-10-evidence-v2。GitHub 下游版本檢查也應出現此版本。

## 二、再更新 GitHub

1. 把本包的 pipeline.py、pipeline/pipeline.py、requirements.txt、pipeline/requirements.txt（若包內有）、.github/workflows/daily.yml 放到儲存庫相同位置。
2. 兩份 pipeline.py 必須一起更新。工作流優先使用根目錄 pipeline.py；只更新 pipeline/pipeline.py 會繼續執行舊碼。新版工作流也會阻擋兩份不一致的情況。
3. 提交到 Actions 實際執行的分支。確認最新一次執行使用新提交。
4. 保留既有 Repository Secrets：GOOGLE_SHEETS_SERVICE_ACCOUNT、SPREADSHEET_ID、APPS_SCRIPT_URL、ADMIN_KEY、GEMINI_API_KEY 與已設定的備用金鑰。
5. APPS_SCRIPT_URL 應是上一步更新後同一個 /exec 網址。新 Python 會要求下游支援 evidence-v2；因此必須先更新 Apps Script，再執行 GitHub。
6. 不必新增 Gemini 金鑰才能使用這次修改；但至少一把金鑰必須有可用生成額度。

## 三、第一次驗收只處理 2026/09/10

1. 先核對試算表「影片清單」原始逐字稿內容。您提供的 GitHub 日誌是 23,493 字，但本機「新增 文字文件.txt」讀到 13,608 字，「新增 文字文件 (5).txt」讀到 14,007 字；目前並非可以直接視為相同版本的三份內容。
2. 特別核對「我還有紅準」及末段候選名單。本機第一份檔案實際含宏捷科、信紘科、家登，與您已確認的正確說法有衝突。不要未核對就把這份內容當作絕對正確來源重新投稿。
3. 在後台選擇該日期，提交已核對的完整原文。若要替換有錯的既有潤飾稿，先使用後台既有重跑方式清除／更新該稿；新版判讀即使沿用顯示稿，也只使用原始稿取證。
4. 確認 Actions 日誌印出「判讀來源：原始逐字稿」、字數與 SHA256。保留它作為此次來源識別。
5. 流程會做擷取、完整原文覆核、證據定位；有定位問題會自動修復一次。名稱使用官方清單及該筆上下文確認。
6. 完成判讀後，自動寫入紀錄、更新相關日期郵件內容、重算持股追蹤、重算歷史績效、記錄目前績效。只有相依步驟完成後才標記工單完成。
7. 若刷新階段中斷，按同一張工單「續跑」。新版會用原文 SHA256 與規則版本核對「逐字稿刷新檢查點」，略過已完成的刷新步驟，避免整份重新潤飾、擷取。
8. 如果仍有未解的證據或名稱問題，候選會保存在「逐字稿判讀稽核」。此版不會用只剩 4 筆的部分結果清掉整天舊資料，也不會假報全部成功。這是初步版仍可能需要人工處理的情況。

## 四、逐日手動編輯後

1. 先完成同一天所有需要的修改。
2. 按「重寫郵件並刷新網站」。
3. 後台會依序執行「同步郵件內容 → 重算持股追蹤 → 重算歷史績效 → 記錄目前績效」。可查看進度，背景工作不依賴頁面一直開著。
4. 刷新郵件時會由最終試算表資料重建固定六章格式，不再額外呼叫 Gemini。這直接處理原本「文章章節不完整，未覆蓋郵件內容」的中斷問題。
5. 更新的是網站上的郵件查詢與待寄內容。已寄出的電子郵件不能修改；本次更新不會自動重寄。

## 五、應檢查的結果

- 華城先前賣出的回顧，不應出現在 09/10 當日賣出；未明確交代日期時不得猜成昨天，也不得拿來建立虛構績效事件。
- 力積電若該份已核對原文明講「昨天叫人家賣」，應歸 09/09。世芯若明講昨天買，也應歸 09/09，另依原文明講的現有部位列今日持股。
- 國巨、萬海與各候選公司的分類，應能在稽核中找到原文段落與上下文，不能只靠情緒字或價位推測。
- 原文正確的世芯、譜瑞、矽晶圓等字詞不能被潤飾改成其他名稱；不合格潤飾自動回退原文分段。
- ③ 盤勢總覽保留已驗證的大盤數字及時間條件，採完整條列控制篇幅；④ 表格仍由結構化紀錄生成。
- 「影片今日明講的持股」與「歷史累積追蹤中的持股」是不同統計，不能要求兩者檔數完全相同。

## 六、測試與回復

本包 tests 提供離線測試。在有相依套件的環境執行：

    python -m unittest discover -s tests -p "test_*.py"
    node tests/test_gas.js

若需回復，將 Apps Script 原部署切回先前版本，GitHub 回復到對應提交。程式回復不會自動還原已修改試算表，資料請使用部署前備份。
本包未包含任何金鑰、登入狀態或試算表資料。
