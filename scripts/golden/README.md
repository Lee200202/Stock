# 重播測試的答案

2026/10/27後正常更新只把本目錄當推論後的參考；不是每份檔案都屬人類核定金標，須看檔內來源／曝光狀態。禁止將 must／must_not、reviewed_notes 或 note_must_not 灌入裁決、刪句或覆蓋模型輸出。成功模型預覽保存artifact，正式套用同一份，不重新生成。詞表的方向與漏收盤點只供人工核查，不能決定語氣／分類。

`scripts/replay_extract.py --golden` 用的檔案。每個檔是一天，由人逐字核對過逐字稿之後寫下：

- `must`：這一檔一定要收，值是可以接受的分類（`buy`、`sell`、`holdings`、`watch_watch`、`watch_avoid`）。講法介於兩類之間的才列兩個。
- `must_not`：不應該出現的代號（認錯公司、把別天的買賣當成今天）。
- `note_must_not`：逐字核對後已知不屬於該股的字句。以代號為鍵、禁用片語為陣列；只檢查該股最後公開說明，避免同份原稿有這個數字就誤放行。這是當日人工答案，不取代通用的價位比例與時間詞稽核。
- `names`：代號對應的名稱，只給報告用。
- `why`：每一檔的依據原句，給之後回頭查的人看。

答案只收「逐字稿裡講得出依據」的。聽打把股名寫壞、連人都要靠當天簡訊才認得出來的，不放進 `must`。

## 重播另外會做的兩件事（不需要這裡的答案）

- **通用檢查**：每一天都該成立的事——原文明講今天賣出的那一檔要在賣出、說明不帶內部字樣或通知管道的字眼、同一句不講兩遍、說明不是空的、列觀望不碰的說明不能只有偏多內容、原文講得很直白的台股不能沒有下落。有錯時結束代碼是 3。
- **網站比對**：和試算表裡這一天目前的資料逐檔對照，只列差異；「・」是只在盤中來源出現的列，影片重播本來就不會有。僅供對照，不影響結束代碼。

答案不符的結束代碼是 2。2 和 3 都是檢查結果，不是程式壞掉。

## 怎麼用才算驗證過

模型對同一份逐字稿每一輪的判讀不一樣，所以：

1. 規則只寫句型，不寫股名；單元測試用不屬於任何一天的股名與說法，並附不該觸發的反例。
2. 改完重播「拿來調規則的日子」和「沒拿來調的日子」。只有前者通過不算數。
3. 看每一檔的分類與說明，不只看結束代碼；同一天多跑幾次。


## 可選類別與分狀態書面說明（2026/10/16）

- `forbidden_stock_categories`禁止特定代號列入某類，不強迫它公開；用於「明講沒有持有，是否另有觀望資訊再判」的案例。
- `reviewed_note_variants`是額外已核對說明陣列，每項有`code/category/text/quotes`。同代號可有不同類別文字，例如剩餘持股與暫不買回；不得共用同一段說明。與`reviewed_notes`共用`reviewed_notes_sha256`原稿指紋，來源、分類或文字變更不再沿用。
- 分類別說明由`apply_reviewed_notes.py`更新；不執行新分類、不產生買賣、不寄送。一般單日流程仍按來源與現行裁決判定，已核對說明的保存紀錄只在指紋及分類一致時沿用。
